# 抽卡畫面共同設計 ─ 給 GPT-6 Astra 的第一輪簡報（設計，不改檔）

你和 Claude 一起接續設計 ClawdPet（Tauri 2 桌面寵物）裡的「抽卡」功能。這是功能試作：使用者之後要做其他遊戲，把這裡當作抽卡體驗的實驗場，所以設計要**可拆、可重用、可切換**，不是只把現在這一套做漂亮。

## 先看這些（全部在 repo 內）
- `GACHA-PROMPT.md`：使用者最初的需求原文（爐石開卡包的節奏、四階稀有度色、卡池、音效要合成）。
- `src/gacha.html` / `src/gacha.css` / `src/gacha.js` / `src/gacha-fx.js` / `src/gacha-audio.js`：現行實作。狀態機在 gacha.js 開頭註解；角色立繪是把 `src/index.html` 的 `<template>` SVG 拼回去、rig 資料從 `src/pet.js` 的 `CHAR_CFG` 讀。
- `docs/gacha/current-flipped.png`、`docs/gacha/current-legendary.png`：現況截圖。
- `docs/gacha/cardface-variants.png`：六款卡面比較圖。**使用者選了 A（現行版）和 F（霓虹玻璃）**，要把兩者融合成定案卡面。
- `src/_cardlab.html`：六款卡面的 CSS 覆寫（A 是 gacha.css 的原樣，F 在 `.vF` 區塊）。

## 硬限制
- 畫布固定 960×640 CSS px（螢幕塞不下由後端算 zoom 等比縮），純前端、無框架、classic script。
- 素材只有：角色拆件 PNG（透過 template 拼回）、`toy-*.png`、emoji、`gacha-cardback.jpg`、`gacha-pack.png`。**不能要求新畫圖**；需要的圖形用 CSS / SVG / canvas 畫。
- 音效一律 WebAudio 合成（`gacha-audio.js` 的積木：tone / noiseHit / bell / verb）。
- 角色畫風是厚黑描邊、平塗、貼紙感的可愛小動物；卡背卡包已經對齊這個畫風。
- 效能：閒置時不能有常駐 rAF／無限 CSS 動畫（透明視窗會逼 GPU 全速合成，這是這個專案的既有教訓）。特效只在動作發生時跑。
- 設計原則（使用者原話）：「每個回饋都有重量，不是特效堆疊」「不要有 AI 味」。

## 請產出一份設計文件（Markdown，寫到 stdout / -o 檔）

### 第一部分：定案卡面 = A + F 融合
給出一份可以直接照抄進 CSS 的規格：
- 版面尺寸沿用 150×210、`.face-art / .face-plate / .face-gem / .face-frame` 這些既有節點（可增節點，但說明用途）。
- 四個稀有度各自的差異（不只換色：普通要「安靜」，傳說要「不用翻就知道它貴」）。
- 翻開後 hover 的動態卡面（現有 `.live`：3D 傾斜、鍍膜、視差、rig 閒置動作、餘燼）在新卡面上要怎麼改配色與強度。
- 圖鑑縮圖（scale .64）與未擁有黑影的處理。
- 說明為什麼這樣融合，以及哪些 F 的元素故意不要。

### 第二部分：三到四種「抽卡演出模式」
參考日系手遊的抽卡介面與方式（例如：原神祈願的流星與顏色預告、FGO 召喚陣與卡牌色階、賽馬娘／蔚藍檔案的角色登場、明日方舟的干員探照燈、公主連結的水晶、碧藍航線的建造…等你熟悉的），為**這個專案的素材與限制**重新設計，不是複製。每種模式要寫到「能直接動手做」的程度：
1. 一句話的概念與它借用的日系手遊語彙。
2. 完整分鏡時間軸（毫秒級）：從按下抽到全部揭曉，每一拍的畫面、鏡頭、音效、玩家可以做的操作（點擊跳過？逐張點？長按？）。
3. **稀有度預告（telegraphing）**：玩家在揭曉前如何從顏色／速度／音高得到暗示；傳說的「來了」怎麼做；如何避免每次都一樣（隨機化哪裡、不能隨機化哪裡）。
4. 十連／單抽的差異（現在是一包五張，可提議改成 10 連或保留 5）。
5. 需要新增的視覺元件清單，每一項標明用 CSS / SVG / canvas 哪個做、大概多少行。
6. 需要新增的合成音效清單，用現有積木描述（頻率、包絡、噪音濾波）。
7. 與現有狀態機的接點：哪些狀態共用（deal / fanned / collecting 可否沿用）、哪些要新增。

### 第三部分：模式切換架構
提議一個最小的「演出模式」抽象（例如 `window.GachaModes = { hearthstone, wish, summon, ... }`，每個模式實作 `open(handEntries) → Promise<void>` 之類），讓現有爐石模式成為第一個實作、新模式能各自獨立檔案、頂列可切換、之後搬到別的遊戲時只帶模式檔就好。說明資料流（rollPack → 模式 → 收下）與共用的東西（卡面元件、稀有度色、音效積木、粒子層）。

### 第四部分：優先順序
如果只能先做一種模式，做哪一種、為什麼；估算每種模式的工時。

寫作要求：繁體中文、具體到數值、不要泛泛而談；不同意現有設計的地方直接說。
