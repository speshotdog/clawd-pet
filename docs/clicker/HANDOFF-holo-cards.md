## 三、卡面：已定案的規格

### 三種卡型（資料驅動 `art.kind`）

| 卡型 | 條件 | 做法 |
|---|---|---|
| `depth` 滿版景深卡 | 主體與背景拆得開 | subject／background 兩層沿 Z 推開做視差 |
| `flat` 平面滿版卡 | 有背景但拆不出前後關係 | 整張平鋪、**不做圖內視差**；景深只發生在卡片本身傾斜，箔面反光光暈吃在卡面 |
| `framed` 去背卡框卡 | 單一角色去背 PNG | **維持舊版樣式不更新**（使用者定案，當成與精裝版的識別） |

### Z 順序（由後到前）

`圖繪背景` → `文字框` → `拆出來的角色` → `名字文字`

- 角色**會蓋過文字框的上緣**，這個「被蓋住」就是要的前後關係，不要修掉。
- **名字永遠最上層**，連角色都不能蓋住它。
- `flat` 卡沒有 subject 層，只有三層。

### 其他定案

- **字體**：`Noto Sans TC`（子集化內嵌 data URL，SIL OFL）。
  傳說／神話用**浮雕燙金**；`common`／`rare`／`epic` **維持乾淨白色粗體，不要任何字效**。
  被否決的方向：系統字、Noto 宋、遊戲金屬、像素疊描、斜體分層。
- **寶石**：照抄 `src/gacha-card.css` `.face-gem` 原版形狀，只做微調
  （配色、邊光、極輕微角度反光）。**不要立體、不要改形狀**。位置在**文字框左側**。
- **名字與稀有度置中**：基準是**卡片本身**，不是扣掉寶石之後的剩餘空間。
- **史詩要明確的紫**，跟神話拉開；**傳說與神話的框要奢華**（雙層框、角落裝飾）。
- **珍珍JPG 的透明格子是美術梗**，不是破圖，保留。

### 已否決的路線（不要再走）

- **合成滿版背景**（角色 ＋ `clicker-scene<N>` 場景層）——使用者說「都不好看」。
  `compose_legacy.py` 與 `layer-*` 檔留著當紀錄，展示頁不展示。
- **硬拆滅世珍獸**——城市與角色同色調拆不開，強拆會破壞原本的構圖。改走 `flat`。
- **不透明銘牌橫幅蓋在圖上**——第七輪拆掉了；第八輪回來的是「有前後關係的文字框」，不是黑條。

## 五、踩過的坑（會再踩到的）

1. **搜原始碼不等於驗畫面。** 展示頁一度把中文卡名存成 `String.fromCodePoint(0x…)`，
   所以 grep「火箭狗」查不到，我回報「已改名」是假通過——畫面上還是舊名。
   **驗名字一律讀實際渲染出來的文字。**
2. **卡名不要從檔名推。** 曾經把 `foxfriend` 寫成「狐狸朋友」，
   實際遊戲裡叫「摯友之狐」。正名一律查 `src/gacha-pool.js`。
   （已修正四個：摯友之狐／咩噗噗噗／黃色蠑螈／羊咩噗）
3. **GrabCut 拆出來的邊會有色溢與暈邊。** 修法是輪廓內收 2px ＋ 窄環形 NS inpaint ＋ 0.8px 羽化。
   但更根本的解法是**別拆**（見 `flat` 卡型）。
4. **`file://` 不能用 `fetch`／XHR／ES module import**，CSS mask 也吃 CORS，
   所以 mask 與字體都得內嵌成 data URL。
5. **分享單檔要壓縮**：原始 PNG 合計 28 MB，base64 後 38 MB，塞不進網頁。
   背景轉 WebP／JPEG、主體用 WebP with alpha，壓到 3 MB 左右。
6. **授權**：`pokemon-cards-css` 是 **GPL-3.0**，只能學原理不能抄程式與貼圖；
   `holo-card-studio` 是 MIT 但明文排除生成的圖片；
   Galaxy Holo／Vecteezy **授權未確認，不採用**。
   本專案的箔紋、粒紋、框 mask 全部程式生成（固定 seed `20260908`）。

### 舊卡不升級

**遊戲裡現有的卡面不動**；精裝版是「同一張卡的另一個版本」，不是把舊卡換掉。

### 精裝版只有一種版型

以天外膠膠那張為標準版型，**每一張都必須有**：階級寶石 ＋ 文字框 ＋ 名字 ＋ 稀有度。
**不接受沒有文字框的卡面。**

- 有前後關係的圖 → 比照宇宙冒險羊做 `depth`。
- **沒有背景的卡也是同一個版型**，人物置中（`kind-framed` 的 `.art-media` 改成 grid 置中，
  圖最大 78% 寬 / 70% 高）。
- **字級不再吃 `vw`**：ResizeObserver 把名字算成卡片寬度的固定比例
  （基準 24px / 290px 卡寬＝8.28%，稀有度 9px / 290px），所以同一張卡在場景區、
  卡池區、稀有度區都是同一個比例。宇宙冒險羊之前是 28.7px、天外膠膠是 24px，
  就是 vw 規則造成的不一致。

## 六之五、卡片製作工法（**凍結，禁止隨意更動**）

使用者 2026-09-09 定案：以下數字與結構固定，不要再「順手調整」。
要改必須是使用者明講，改完要跑 `check_demo_round8.py` 與 `check_demo_round9.py`。

### 幾何（佔卡片比例，基準是場景卡）

| 元素 | 值 |
|---|---|
| 圖窗 `.art-media` | `inset: 1.7% 2.4% 3.3%`（滿版，延伸到文字框後面） |
| 文字框 `.face-plate` | `left/right 4.4%`、`bottom 3.4%`、`height 16.2%` |
| 文字層 `.face-text` | 同上位置，名字放這裡，**不要塞進 `.face-plate`** |
| 寶石 `.face-gem` | 文字框左側，`left: calc(5% + var(--gem-fs)*.62)`、`bottom: calc(12% - var(--gem-fs)/2)` |
| framed 人物 | 在「卡頂到文字框上緣」之間置中，最大 100%×100% 圖窗 |

**文字框不是黑條**（第三節「已否決的路線」就有這條，2026-09-09 又犯一次）：
`flat`／`bleed` 的圖是一路鋪到卡底的滿版畫，文字框必須讓下層的畫透出來——
背板用由下往上收的半透明 scrim
（`linear-gradient(to top,#070b12d9,#080d16a6 52%,#0a101c40)`），
保留上緣稀有度色細線、圓角與外框線，**不可以換成不透明色塊**。

### 字級與寶石大小：綁卡片寬度，不吃 vw

`ResizeObserver` 換算，基準是 290px 卡寬：

- 名字 `--name-fs` = 卡寬 × **24/290**，超出文字框安全寬度就每次縮 7%，最多縮到 55%
- 稀有度 `--rarity-fs` = 卡寬 × **13.5/290**（2026-09-09 使用者要求 ×1.5）
- 寶石 `--gem-fs` = 卡寬 × **22/290**
- 安全寬度＝「到文字框內緣」與「到寶石右緣」取小值再乘二；量文字要用 `Range`，
  量 `.face-name` 的 rect 等於量文字框，會一路縮到下限

### Z（配合六之四）

| 層 | translateZ |
|---|---|
| 背景 `.face-depth-bg` | `--zb` 2px |
| 圖層 `.face-art`（framed／flat） | **6px**（低於 2px 會被背景蓋掉，高於 8px 會蓋掉卡框） |
| 卡框 `.face-frame` | `--zf` 8px |
| 文字框 `.face-plate` | `--zp + 1px` |
| 文字層 `.face-text` | `--zp + 28px` |
| 寶石 `.face-gem` | `--zp + 30px` |

`z-index`：背景 10、圖層 30、文字框 20、文字 200、寶石 210。
**上下界都要看**：壓太低被背景蓋、推太高被透視放大浮出卡外。

### 卡型（資料驅動，來源 `_art/holo-test/pool_data.py`）

`scene → depth`／CATALOG 的 `bleed → flat`／其餘 `framed`。
`flat` 不掛 `subject-mask`、圖層不推 Z。

### 字效

`common`/`rare`/`epic` 乾淨白字；`legendary` 實心亮金 `#fff45c` ＋自體光暈；
`mythic` conic 彩虹跟著 `--phase`，黑邊用 `drop-shadow`。

  這是使用者 2026-09-09 指定的行為，見 `paintFoil()`。

## 六之四、硬規則：Z 只能小幅推（踩過三次）

卡面是 `preserve-3d` ＋ `perspective`。**`z-index` 不決定前後，`translateZ` 才決定**——
但推得越高，那一層被透視放大越多，推到 70～106px 就會整塊撐出卡緣、浮在卡片外面。

已經因為這件事重做三次：

| 輪次 | 推高的是什麼 | 症狀 |
|---|---|---|
| 十二 | 文字框推到 70px（為了蓋住人物） | 文字框比卡片還寬，量到 left 1.6%（CSS 寫的是 4.4%） |
| 十九 | 寶石推到 106px（為了蓋過文字背板） | 寶石浮在卡外 |
| 二十 | 圖層在 `--za` 36px、卡框只有 8px | 滿版卡整個沒有框 |

**規則**：卡面所有層的 `translateZ` 一律 ≤ 約 42px（`--zp + 30`）。
要讓 A 蓋過 B，正解是**把 B 降下來**，不是把 A 推上去。
`flat` 的圖層 Z 直接給 0（它本來就不做圖內視差）。

`check_demo_round9.py` 已經釘死這條：`.face-plate`／`.face-text`／`.face-gem`／
`.face-name`／`.face-rarity` 的矩形不准超出卡片矩形 1.5px 以上。
（`.face-frame` 在 `--zf` 8px、設計上就貼著卡緣，不在檢查範圍。）
