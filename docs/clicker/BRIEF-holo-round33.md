## A. 衝擊波環必須蓋過**所有**卡片，而且要更粗

**症狀**：十連時，正在揭曉那張卡的向外擴圓環，**被旁邊的卡蓋住**——環走到鄰卡上就被切掉。單抽看不出來，因為旁邊沒有卡。

**這是上一輪 B 題的驗收漏洞**：`check_gacha_layers_round31.py --b` 只在**單張卡**的情境量環的直徑與線寬，沒有量「環經過鄰卡時還在不在」。修完要把這個情境補進斷言（見驗收 3）。

**現況分層**（`ceremony.css`）：

```
.slot                     z-index:2      （.selected 7、.is-revealing 10、.mobile-current 6）
.reveal-anchor            z-index:1      （在 slot 內，CSS 的 .rarity-fx 環掛在這）
.ceremony-canvas          z-index:1      （round31 為了修射線蓋卡，把 upper 從 4 降到 1）
.ceremony-canvas.under    z-index:1
```

**先量再改，不要照我的猜測動手。** 我的假設是：使用者看到的「外擴圓環」有**兩個來源**，round31 只修對了一個——

- CSS 的 `.rarity-fx`（`fx-substrate-wave` / `fx-spectrum-wave` / `fx-counter-wave` / `mythic-ripple`）掛在 slot 內的 anchor，跟著 slot 的 `z-index:10` 走，**應該**已經蓋過鄰卡（2）。
- `ceremony-fx.js` `strengthen()` 裡畫在 canvas 的 `ring(...)`——round31 為了修 A 題把 upper canvas 降到 `z-index:1`，**它現在在所有 slot（2）之下**，所以會被每一張卡蓋住。

先寫最小重現（十連 fixture、中間那張是 legendary／mythic），**逐幀量像素證明是哪一個來源被蓋住、被誰蓋住**，再動手。

**使用者對分層的補充裁決（原話）**：

> 背光層 射線 只不能蓋到當前演出的那張卡
> 但因為當下他是主角 所以不應該被其他卡壓下去

**這是對 round31 A 契約的放寬與修正，照這個做**：

- 射線／底光**只需要**不蓋到「當前正在演出的那張卡」。它們**可以**、而且**應該**通過並蓋在其他卡之上——現在射線被鄰卡切斷（見使用者截圖：左邊那張史詩卡把金色射線整片擋掉）就是錯的。
- 正在演出的那張卡是主角，**必須壓在所有其他卡之上**，不得被鄰卡蓋到任何一角。

**要求**：

1. **分成四層，由下而上，語意要分乾淨**（不要再用「一張 canvas 全包」的做法，round31 就是因為這樣一修就顧此失彼）：

   | 層 | 內容 | 規則 |
   |---|---|---|
   | 1（最下） | **其他卡**（非演出中的 slot） | 會被射線蓋到，這是對的 |
   | 2 | **背光層**：射線 `rays()`、底光、`flash()` | **只有「演出中那張卡的卡面 rect」不得被覆蓋**；蓋過其他卡是預期行為 |
   | 3 | **演出中的那張卡** | 壓在 1 與 2 之上，不得被任何其他卡或背光遮到 |
   | 4（最上） | **衝擊波層**：向外擴的環（canvas 的 `ring()` 與 CSS 的 `.rarity-fx` 環） | **必須壓過畫面上每一張卡**，含鄰卡、含 `.selected`／`.mobile-current`／`.is-revealing` 的任何組合 |

2. 實作路線你選（要能證明沒有副作用）：新增第三張 canvas（例如 `.ceremony-canvas.over`）承擔衝擊波、背光 canvas 提到「其他卡之上、演出卡之下」、演出中的 slot 拉到背光之上。**卡面 rect 排除只保留給「演出中那張卡」**，round31 那套「排除所有卡面」的邏輯要收窄，不是整組刪掉。
3. **環要更粗**：現行實測外徑 474px（legendary）／516px（mythic）、線寬 12px。**線寬加到 24–28px**（約 2 倍），外徑維持不變（外徑是既有節奏，改了會跟卡片間距打架）。粗了之後亮度要跟著收——**不准變成一圈不透明白棒把卡面蓋死**（LESSONS 第六節第 1 條第 3 點：不透明背板是已否決路線）。環壓在卡上時，卡面的名字與稀有度銘牌必須仍然讀得出來。
4. **不得把 round31 A 題整個丟掉**：射線／底光／flash 仍然一次都不能蓋到**演出中那張卡**的卡面。放寬的只有「其他卡」那部分，這條要在報告寫清楚是使用者裁決。
5. 所有層的 `translateZ` 絕對值上界仍是 **≤ 42px**。

## B. 傳說／神話蓄力時，整片卡背要一起發光

**症狀**：現在蓄力段只有**卡片邊框**在發光（`.charge-glow` 是卡片後方的 radial gradient，從卡的四周漏出來），卡背本身還是暗的，「比較沒感覺」。

**要求**：

1. 蓄力段期間，**`.veilback`（卡背）整片**要跟著發光——不是只有邊緣漏光，是整面卡背在發亮。做法建議（自己選，能證明效果的那條）：
   - 在 `.veilback` 上疊一層同尺寸、同圓角的發光層，用 `mix-blend-mode: screen` 或 `plus-lighter` 上稀有度色，透明度隨蓄力進度漸強；
   - 搭配 `filter: brightness()` / `saturate()` 讓卡背印刷本身變亮（**不要用 `filter: blur()` 讓卡背糊掉**，卡背花紋要看得見）；
   - 外圈的 `box-shadow` 光暈保留當作外溢，但不再是唯一的光源。
2. **強度**：蓄力結束時，卡背區域的平均亮度相對蓄力開始要提升到 **legendary ≥ +45%、mythic ≥ +60%**（灰階平均，量卡背矩形內部而不是外圈）。這是量測目標，不是叫你把它調到全白——**卡背的圖案在最亮時仍必須辨認得出來**（卡背矩形內的亮度標準差不得低於蓄力開始時的 40%，避免整片糊成一塊）。
3. **顏色**：legendary 暖金、mythic 彩虹／冷白，沿用既有的 `--charge-color` 體系。
4. **不預告契約不變**：common／rare／epic 在 `face-visible` 前仍必須逐像素零差，發光只能出現在 legendary／mythic。
5. 收束那一拍（legendary 最後 120ms／mythic 160ms）卡背的光要跟著急收，再翻牌。
6. 跳過語意不變：`skipAll()`／Esc 之後 180ms 內卡背不得殘留任何發光層。

## C. 背景線條要動起來（循環動畫）

**症狀**：上一輪的召喚陣是靜態的，只有 28 秒的整體呼吸。使用者要的是**線條本身在動、而且是無縫循環**。

**要求**：

1. 召喚陣的各個元素要有**各自的循環動畫**，彼此週期不同才不會看起來像整張圖在轉：
   - 同心環：不同速度、不同方向的**緩慢自轉**（外圈慢、內圈快，或相反）；
   - 點列／虛線環：**沿著環周長流動**（用 `stroke-dasharray` + `stroke-dashoffset` 動畫，一個週期剛好走完一個 dash 長度才會無縫）；
   - 破環的兩段弧：**來回擺動**或反向自轉；
   - 菱形刻度：沿環移動或逐一明滅（相位錯開）；
   - 中心四芒星：**呼吸式的明滅與微幅縮放**；
   - 垂直光軸：**由上往下（或由下往上）流動的光點**；
   - 地平面同心橢圓：**由內向外持續擴散**（一圈淡出時外面補一圈進來，才會是無限的）。
2. **必須無縫循環**：每條動畫的起訖狀態要完全相同（`animation-iteration-count: infinite` 且首尾幀一致）。驗收會截頭尾兩幀比對。
3. **不能搶戲**：整體亮度與對比維持在「卡片是主角」的水準；卡片出現時（`.focus-held`）背景動畫照舊降階／暫停。
4. **技術限制（沿用 round31）**：
   - **不得新增常駐 `requestAnimationFrame`**。用 CSS animation（含 SVG 屬性動畫可以用 CSS 驅動）。
   - `.background-paused` 與 `prefers-reduced-motion` 的停動畫行為保留。
   - 不引第三方素材／字型／npm／three.js。
5. **關於 remotion**：使用者說「真的做不出來可以用 remotion 做」。**先用 CSS 做**——上面每一項都是 CSS 做得到的。**只有在你能具體說明哪一項 CSS 做不到、並寫進報告之後**，才可以提 remotion 方案；而且要先講清楚代價（會變成外掛影片素材、體積、與「不引第三方素材」的衝突），**由使用者裁決，不要自己決定改走影片**。

## F. 卡背要滿版

**症狀**：卡背看起來「沒有滿版」——印刷的奶油色外框沒有走到卡片邊緣，外面留了一圈死掉的深藍底，配上暗色舞台就變成一圈黑邊。

**現況**：素材 `_art/holo-test/cardback/deluxe-back.webp` 是 500×700（5:7），我量過**它自己就帶著約 5% 的深藍留白**（`#27325 0` 一路到圖的邊緣，奶油色外框從約 5% 才開始）。CSS 是 `.veilback{background:#26324f url(...) center/cover no-repeat;border-radius:12px}`，`cover` 已經填滿，所以**不是 CSS 沒鋪滿，是素材本身留了邊**。

**要求**：

1. 把那圈死留白處理掉，讓奶油色外框幾乎貼到卡片邊緣（留 1–2% 當出血即可），視覺上跟卡面（`.hcard`）的滿版程度一致。
2. **不准重畫**：只能裁切／縮放既有素材（照 `角色製作工法.md` 的原則：成品不能脫離原圖樣貌）。**裁切後必須維持 5:7**，並確認四角圓角處沒有把外框切斷。
3. 有兩條路，選你能證明沒有副作用的：重新裁一份 `deluxe-back.webp`（連帶 `deluxe-back.png`），或在 CSS 用 `background-size` 放大並 `center` 對齊。**若走 CSS 放大，要證明放大後外框線寬與卡面外框線寬不打架。**
4. 卡背有 `backface-visibility:hidden` 且在 `rotateY(180deg)` 的翻牌鏈上，**不能用 CSS mask**（LESSONS 第四節：Chromium 會讓整個 pseudo-element 消失）。
5. 改完 B 題的卡背發光要重驗——發光層的尺寸與圓角要跟著新的滿版邊界走。

## G. 按下抽卡要有「卡包 → 抽卡畫面」的過場

**症狀**：現在按下抽卡是 `setScreen('ceremony')` 直接切換，按鈕淡出 240ms 就進拆封，**沒有過場**，太生硬。

**使用者已經指定演法（原話）**：

> 點連抽之後 選項按鍵會消失 畫面往卡包稍微放大至中
> 點擊之後 有特效 然後炸出卡片

**所以這是四拍，而且中間多了一個「等玩家再點一下」的互動節點**：

| 拍 | 內容 | 長度 |
|---|---|---|
| 1 | 按下抽卡 → 三顆按鈕（含試抽券計數）**消失** | 180–240ms |
| 2 | 鏡頭**往卡包稍微推近並置中**（卡包放大、背景召喚陣同時後退／收束、入口文案退場） | 320–420ms |
| 3 | **停在這裡等玩家點擊**（無限等待）。要有明確的可點提示（例如卡包輕微呼吸＋一行「點擊開封」），滑鼠游標在卡包上要是 pointer | 等玩家 |
| 4 | 玩家點擊 → **開封特效**（撕封／爆光／震動）→ **炸出卡片**，接既有 `prelude()` 的 deal | 依既有節奏 |

**要求**：

1. 第 3 拍是**新的等待狀態**，`pull()` 從「一路跑到底」變成「中途停下來等輸入」。狀態機要乾淨：這段期間 `busy` 的語意、`generation` 的取消、重複點擊的防抖都要處理好，**不能因為玩家連點兩下就開兩次封或炸出兩組卡**。
2. **跳過語意**：第 3 拍等待時，「跳過演出」按鈕要能用（直接跳到結果）；Esc 同樣有效。點卡包 = 開封，點空白處 = 沿用既有「點空白跳過」還是「也算開封」，**你決定一種並在報告寫明理由**，但兩者不能同時成立造成誤觸。

## I. 抽卡畫面留白：卡不要滿版

**現況數字**（`ceremony-layout.js`，1440×900）：

```
n===1  cw = 420 * min(width/1440, height/900)          → 420px
n<=5   cw = min((width-80)/5.55, (height-200)/1.7)     → 245px，一排五張橫向總跨距 1361px，左右各只剩 40px
n>5    cw = min((width-80)/5.55, (height-200)/3.15)    → 222px，兩排
```

**要求**（1440×900 為基準，其他尺寸等比）：

| 情境 | 卡寬 | 留白 |
|---|---|---|
| 單抽 | 360–390px | 上下左右都要有明顯留白 |
| 五連 | 200–215px | 左右各 ≥ 140px |
| 十連 | 190–205px | 左右各 ≥ 140px、上下各 ≥ 70px |

2. 卡片間距要跟著調整，**任兩張 rect 交集仍必須為 0**，而且卡片之間看得出間隙（不是靠得剛好不重疊）。
