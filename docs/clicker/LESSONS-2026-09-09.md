# 2026-09-09 踩坑與製作經驗（精裝卡面 ／ 抽卡）

## 第三十一輪追加：已實測的演出層陷阱

- `upper` canvas 的 z-index=4 在 `.slot` 移除 `is-revealing` 後會蓋過 z-index=2 的卡；只降 upper 至 1 的對照就能消除當時的卡內像素差。不要把原因誤寫成 rays 跑錯 canvas。卡片翻到側面時，矩形裡也包含透明空隙；嚴格「整個 rect 無 canvas」要額外排除該矩形，不能只看卡正面。
- 外環推至 Z=42 仍會與正在旋轉的 `.reveal-flip` 相交，產生直切缺口。外層 slot 改成 flat、環在獨立平面，內部 shell/card-lift 繼續 preserve-3d，才能同時保留卡面深度與連續圓環。本輪環沒有 perspective 祖先，故補償倍率實測是 1，不能套猜測公式。
- 隱藏父元素做像素對照時，`visibility:hidden` 會被子卡 inline `visibility:visible` 蓋掉。量環的完整直徑應對 `.reveal-shell` 使用 `display:none`，才真的移除卡遮擋；外層尺寸由 slot 保持。
- WAAPI 虛擬時鐘不等於 CSS hover transition 的時鐘。拖曳回正驗收改用原生時間，實際等 400ms，再做相同 hover／selected 狀態的逐像素比較。蓝色選取測試沿用白色 `foxfriend`，不能把紫色卡圖誤認為選取。另須移除繼承的 card-lift transition，避免與 rAF 阻尼回正疊成兩段滯後。
- 暫停的 CSS animation 仍會覆蓋普通宣告的 opacity。`.focus-held` 若必須降亮度，不能只設定 opacity 並 pause；本輪停止該背景動畫，再讓降亮度規則生效。
- 共用樣式的通用 class 也會撞名：lower canvas 的 `.under` 繼承了 demo 的 `margin-top:22px`。以 viewport 座標建立 canvas clip 時必須換算 canvas 自己的實際 rect；否則側面卡的頂緣仍會漏光。本輪保留原有光場位置，使用局部座標換算，沒有偷偷移動既有亮度基準。
- `await animation.finished` 以 render frame 結束，180ms 的動畫可能晚一幀才解除 ownership。需要 180ms 清空的 skip 契約，用既有可取消 timer 等 180ms，再取消 fade、完成卡片；音效也要在開啟狀態下驗資源清理。

完整量測與退出碼見 `REPORT-holo-round31.md`，不是以上文字取代驗收。

## 一、最貴的一條：`preserve-3d` 裡 `translateZ` 決定前後，不是 `z-index`

卡面是 `transform-style: preserve-3d` ＋ `perspective`。同一個 3D 容器裡：

- **誰在前面由 `translateZ` 決定**，`z-index` 只在同一個 Z 平面上有意義
- **推得越高，被透視放大越多**

今天為此重做 **四次**：

| # | 我做了什麼 | 症狀 |
|---|---|---|
| 1 | 文字框推到 `translateZ(70px)` 想蓋住人物 | 文字框比卡片還寬，CSS 寫 4.4% 量出來 1.6% |
| 2 | 寶石推到 `106px` 想蓋過文字背板 | 寶石浮在卡片外面 |
| 3 | 圖層停在 `--za`(36px)、卡框只有 `--zf`(8px) | 滿版卡整個沒有框 |
| 4 | 為了修 3 把圖層壓成 `translateZ(0)` ＋ `z-index:1` | 角色圖被背景層（10 / 2px）整個蓋掉 |

**規則**：

- 所有層 `translateZ` ≤ 約 42px
- 要讓 A 蓋過 B，**把 B 降下來**，不要把 A 推上去
- **上下界都要看**：壓太低被背景蓋、推太高浮出卡外
- 現行分層（凍結）：背景 2px → 圖層 6px → 卡框 8px → 文字框 13px → 文字 40px → 寶石 42px

`check_demo_round9.py` 已經把「文字框／文字／寶石／名字／稀有度不准超出卡片 1.5px」釘成斷言。

## 三、量測的三個陷阱（今天各中一次）

1. **量文字寬度不能量塊元素的 rect。** `.face-name` 是塊元素，它的 rect 等於文字框的寬，
   拿它判斷「有沒有超出」永遠成立，縮字會一路縮到下限（我把字縮到 7.9px）。
   要用 `Range.selectNodeContents(el).getBoundingClientRect().width`。
2. **量佈局寬度不能用 `getBoundingClientRect()`。** 卡片有 hover scale 與 Z 投影，
   102px 的卡會量成 115px，字級就算成 9.54px 而不是 8.44px。
   要用 `clientWidth` 或 `ResizeObserver` 的 `contentRect`。
3. **驗收腳本自己也會量錯。** 我寫的「名字有沒有溢出」報 10/10 全溢出，實際上一張都沒有——
   因為它犯了第 1 點。**寫完檢查腳本要先確認它在已知正確的情況下是綠的。**
4. **互動類驗收要驗像素，不能只驗 CSS 變數。** 這次拖曳變數全對、畫面全藍：瀏覽器選中了圖片。
   拖曳放開、游標移開後截卡片，驗藍色像素比 ≤0.01 與 selection rangeCount 為 0，並在 dev／搬走的 standalone 都跑。

## 四、CSS 的兩個坑

1. **變數一定要給 fallback。** 把 `--pal-*` 的背景 CSS 從一支腳本搬到共用區之後，
   `demo.html` 不設那些變數，整個卡片背景 computed 變成 `none`——而且 round8／9 不檢查
   背景，所以測試還是綠的。`var(--pal-base,#141b2e)` 這樣寫。
2. **同選擇器的兩條規則會各蓋一半。** 傳說卡左上角那條黃色橫塊：
   舊規則是「頂端中央的皇冠」`width:36px;height:12px;background:var(--accent-card)`，
   新規則的缺口邊框只蓋掉 `inset`／`border`／`clip-path`，**寬高與底色沒被蓋到**，
   於是變成貼在左上角 4px 的 36×12 金色方塊。
   → 覆寫舊規則時，要把它設過的所有屬性都收乾淨，不要只覆寫你在意的那幾個。

另外 **`.card-back` 裡不能用 CSS mask**：它是 `rotateY(180deg)` ＋ `backface-visibility:hidden`，
Chromium 對它的 `::after` 上 mask 會讓整個 pseudo-element 消失（三種寫法都實測過）。

## 五、建置腳本：字面字串改寫很脆

`build_round5_standalone.py`／`build_deluxe_b_standalone.py` 都靠「在產物裡找一段程式碼字串
再替換」來做單檔版。今天有三次它靜默失效：

- 改了 `makeCard` 的那一行 → 替換沒命中 → 單檔版還是相對路徑，複製出去整份圖破掉
- 資源正則只吃 `png|jpg` → 卡背是 `webp`，漏掉 → 單檔版破圖
- 先建 asset 表再做字面替換 → 表的 key 也被替換成 data URI → 查表失效

**做法**：把要被替換的地方收斂成**一個函式**（現在是 `path()` / `resolve()`），
單檔版只換那一個函式的實作。另外**每次都要把單檔版複製到別的資料夾再開**才算驗過。

## 七、卡面設計上學到的

- **場景卡（宇宙冒險羊那四張）是標準**，其他卡對齊它的比例，不是反過來。
  差別不在背景，在幾何：圖窗 inset、文字框位置、人物置中範圍。
- **滿版不等於沒有框。** 圖鋪滿的是「圖窗」，不是整張卡。
- **滿版卡的文字框要讓下層的畫透出來**，用由下往上收的半透明 scrim，而且**只能有一層**
  （`.face-plate` 與 `.face-text` 都畫底就會疊成黑棒）。
- **人物置中的基準是「卡頂到文字框上緣」**，不是整張卡。
- **字級與寶石大小綁卡片寬度**（290px 基準），不要吃 `vw`；小卡上不要設固定 px 下限，
  否則 102px 的卡會出現稀有度比卡名還大。長名縮字時稀有度要跟著同比例縮。

## 第三十二輪追加：原圖與驗收條件的衝突

- 檔名是新卡身份的規格，簡報的內容描述不能代替開圖：本次 `珍珍` 實際是褐底貼紙拼盤，`真菌玥` 才是暗色森林角色；另有數張描述也不符。不要因此替換或改寫檔名。
- 寬幅拼盤／角色不能同時做到「純裁成 5:7」與「不切掉任何主體」。本輪保留完整圖的透明留邊稿，明記未經批准的 crop-only 例外，checker 仍報失敗；不能把補透明邊宣稱為純裁切。
- `min(R,G,B)>165` 會把咩噗熊原畫的粉紅色裸露下緣也算成白邊：最終 549 個亮邊像素中 544 個是粉紅色，548 個位於底部 20px。這是量測條件與原畫的衝突，不能為了 1% 數字繼續侵蝕角色，也不能暗改門檻。
- 洪水填充保留的封閉近白像素，後續 defringe 也要保護。本次小丑玥的一個凹角像素在初版被逐圈剝到；加入原圖封閉白元件保護後，11 張的封閉白像素移除數都為 0。
- 最大連通元件會刪掉真正的分離装飾：生日圖三個彩色裝飾被此規則移除，必須在前後圖與報告說清楚，不能稱成「原圖完全沒少東西」。
- 用真實抽卡入口的 fixture 也必須遵守 1／5／10 張控制：63 張拆十張一批，尾批 3 張會找到不存在的按鈕，造成 phase 等待 timeout。補到合法五張並維持身份覆蓋，不改 production ceremony。
- 新卡只進 Deluxe，舊 demo 的 65 個歷史樣本仍維持。擴池回歸中既有卡繼續三頁比對，新卡比較 gallery／gacha；測試需明記 legacy demo 不適用，不能把它假裝成第三份已支援的新卡頁。

## 第三十三輪追加：分層、輸入與量測

- 跨卡特效要按來源與抵達時間分開量。CSS 環與 canvas 環的擴散速度不同；選在尚未抵達鄰卡的時間取樣，不能證明它被遮住。固定中間卡 fixture，先算環與鄰卡相交，再做各來源的開關像素對照。
- 把環搬到舞台 portal 後，定位仍需追蹤演出卡；診斷時隱藏 shell 會使 rect 寬度變成 0。不得用這個無效 rect 把 portal 重設到原點。背光排除區的分數像素邊緣要保守向外取整，否則嚴格 RGB 零差會漏一圈。
- 環加粗後，CSS 與 canvas 的亮度會相加。不能只量外徑與線寬；也要量小卡卡名／稀有度文字對比，並分開控制衝擊波的透明度與背光峰值。
- 文字對比也必須量已翻開的鄰卡，不能只量主角。補上鄰卡後，1024px 神話 +450ms 抓到 59.8%；固定種子 0 重現，關掉 canvas 環仍是 59.9%，CSS 環减半則回到 73.7%。據此將 CSS 環亮度收至 40%，再量原本的線寬、直徑及峰值，不能以一次隨機取樣通過就當成穩定。
- 卡背原稿四邊留白不對稱。中心裁切不必然使四邊合格；先量各邊，維持 5:7 後調整裁切位置，再重驗蓄力亮度與圖案標準差。
- 有負 delay 的循環动画，時間 0 的起始填充狀態可能不是穩態循環。首尾驗收應取同一動畫進入循環後相距一個完整週期的兩幀，保留逐像素比較。
- Hover 必須在非中性位置驗。卡片中心的光位本來就等於中性值，`hover()` 預設置中不能用來斷言「一定變色」。另外，回正 rAF 的確可能覆寫新的滑鼠光位；pointerenter／pointermove 都要停止該 writer，從當下角度接手。不要因另一個假設而放寬 complete 契約。
- 虛擬時鐘同步 CSS animation 後，截圖仍需明確提交樣式。一次並行全測在 rare 的 200ms 出現卡包區差異；十二組重現 probe 的時間、矩陣與像素均一致，未能確證瞬態成因。加入讀取 transform 與短暫呈現等待，並斷言虛擬時間未前進；不可改取樣時刻或刪掉逐像素斷言。
- 並行驗收不可在啟動時讀退出碼總表、結束時覆寫舊快照。每次用唯一時間戳 log 與獨立 exit sidecar，最後合併；失敗碼要保留，後來通過不能覆蓋歷史。
- 先算幾何條件是否相容：1024px 放五張 190px 加四個 8px 間隙已用 982px，兩側不可能再各留約 99.6px。保留衝突與失敗，不能偷偷降低門檻或宣稱使用者批准。
