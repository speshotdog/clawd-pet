## 一、最貴的一條：`preserve-3d` 裡 `translateZ` 決定前後，不是 `z-index`

卡面是 `transform-style: preserve-3d` ＋ `perspective`。同一個 3D 容器裡：

- **誰在前面由 `translateZ` 決定**，`z-index` 只在同一個 Z 平面上有意義
- **推得越高，被透視放大越多**

今天為此重做 **四次**：

| # | 我做了什麼 | 症狀 |
|---|---|---|
| 1 | 文字框推到 `translateZ(70px)` 想蓋住人物 | 文字框比卡片還寬，CSS 寫 4.4% 量出來 1.6% |
| 2 | 寶石推到 `106px` 想蓋過文字背板 | 寶石浮在卡片外面 |
| 3 | 圖層停在 `--za`(36px)、卡框只有 `--zf`(8px) | 滿版卡整個沒有框 |
| 4 | 為了修 3 把圖層壓成 `translateZ(0)` ＋ `z-index:1` | 角色圖被背景層（10 / 2px）整個蓋掉 |

**規則**：

- 所有層 `translateZ` ≤ 約 42px
- 要讓 A 蓋過 B，**把 B 降下來**，不要把 A 推上去
- **上下界都要看**：壓太低被背景蓋、推太高浮出卡外
- 現行分層（凍結）：背景 2px → 圖層 6px → 卡框 8px → 文字框 13px → 文字 40px → 寶石 42px

`check_demo_round9.py` 已經把「文字框／文字／寶石／名字／稀有度不准超出卡片 1.5px」釘成斷言。

## 三、量測的三個陷阱（今天各中一次）

1. **量文字寬度不能量塊元素的 rect。** `.face-name` 是塊元素，它的 rect 等於文字框的寬，
   拿它判斷「有沒有超出」永遠成立，縮字會一路縮到下限（我把字縮到 7.9px）。
   要用 `Range.selectNodeContents(el).getBoundingClientRect().width`。
2. **量佈局寬度不能用 `getBoundingClientRect()`。** 卡片有 hover scale 與 Z 投影，
   102px 的卡會量成 115px，字級就算成 9.54px 而不是 8.44px。
   要用 `clientWidth` 或 `ResizeObserver` 的 `contentRect`。
3. **驗收腳本自己也會量錯。** 我寫的「名字有沒有溢出」報 10/10 全溢出，實際上一張都沒有——
   因為它犯了第 1 點。**寫完檢查腳本要先確認它在已知正確的情況下是綠的。**

## 四、CSS 的兩個坑

1. **變數一定要給 fallback。** 把 `--pal-*` 的背景 CSS 從一支腳本搬到共用區之後，
   `demo.html` 不設那些變數，整個卡片背景 computed 變成 `none`——而且 round8／9 不檢查
   背景，所以測試還是綠的。`var(--pal-base,#141b2e)` 這樣寫。
2. **同選擇器的兩條規則會各蓋一半。** 傳說卡左上角那條黃色橫塊：
   舊規則是「頂端中央的皇冠」`width:36px;height:12px;background:var(--accent-card)`，
   新規則的缺口邊框只蓋掉 `inset`／`border`／`clip-path`，**寬高與底色沒被蓋到**，
   於是變成貼在左上角 4px 的 36×12 金色方塊。
   → 覆寫舊規則時，要把它設過的所有屬性都收乾淨，不要只覆寫你在意的那幾個。

另外 **`.card-back` 裡不能用 CSS mask**：它是 `rotateY(180deg)` ＋ `backface-visibility:hidden`，
Chromium 對它的 `::after` 上 mask 會讓整個 pseudo-element 消失（三種寫法都實測過）。

## 五、建置腳本：字面字串改寫很脆

`build_round5_standalone.py`／`build_deluxe_b_standalone.py` 都靠「在產物裡找一段程式碼字串
再替換」來做單檔版。今天有三次它靜默失效：

- 改了 `makeCard` 的那一行 → 替換沒命中 → 單檔版還是相對路徑，複製出去整份圖破掉
- 資源正則只吃 `png|jpg` → 卡背是 `webp`，漏掉 → 單檔版破圖
- 先建 asset 表再做字面替換 → 表的 key 也被替換成 data URI → 查表失效

**做法**：把要被替換的地方收斂成**一個函式**（現在是 `path()` / `resolve()`），
單檔版只換那一個函式的實作。另外**每次都要把單檔版複製到別的資料夾再開**才算驗過。

## 六、流程上的教訓

1. **文件裡已經有的定案，動手前先查。** 今天至少三次是「使用者早就講過、文件也寫著」：
   - 卡型是資料驅動的 `art.kind`（我在新腳本裡寫死成 framed）
   - `flat` 不做圖內視差、不掛 subject-mask
   - **不透明銘牌黑條是已否決路線**（我又加了一次 97% 不透明的背板）
2. **commit 訊息不准寫沒跑過的結論。** 我寫過「兩支驗收全綠」，實際上跑出來是 exit 1，
   我沒看輸出就送出去。要嘛先看，要嘛不要寫。
3. **同一個坑犯第二次，就不是 bug 是流程問題。** 修法不是再修一次，是變成斷言或文件硬規則。
4. **分工（使用者 2026-09-09 指定）**：由 `codex.exe -m gpt-6-astra` 下指令與驗收，
   Claude 只執行與傳話。今天它抓到 5 個我自己沒發現的回歸
   （demo palette 失效、refit 用錯寬度、flat 兩層疊底、observer 沒 unobserve、單檔版沒重建）。
   派工與驗收的簡報範例：`BRIEF-gacha-card-regression.md` → `REPORT-gacha-card-regression.md`

## 七、卡面設計上學到的

- **場景卡（宇宙冒險羊那四張）是標準**，其他卡對齊它的比例，不是反過來。
  差別不在背景，在幾何：圖窗 inset、文字框位置、人物置中範圍。
- **滿版不等於沒有框。** 圖鋪滿的是「圖窗」，不是整張卡。
- **滿版卡的文字框要讓下層的畫透出來**，用由下往上收的半透明 scrim，而且**只能有一層**
  （`.face-plate` 與 `.face-text` 都畫底就會疊成黑棒）。
- **人物置中的基準是「卡頂到文字框上緣」**，不是整張卡。
- **字級與寶石大小綁卡片寬度**（290px 基準），不要吃 `vw`；小卡上不要設固定 px 下限，
  否則 102px 的卡會出現稀有度比卡名還大。長名縮字時稀有度要跟著同比例縮。
