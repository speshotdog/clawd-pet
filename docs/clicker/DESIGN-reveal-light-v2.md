## 2. 舊版的光，實際由什麼組成

### 2.1 主幹：不是只有 particles，也不是只有 conic

| 層次 | 實際實作與位置 | 對觀感的作用（設計判讀） |
|---|---|---|
| 卡背內透光 | `src/gacha-card.css:310–329`：`.skin-af .back-leak` 以兩個 radial gradient、內陰影與中央白核，hover／charging 才亮；普通只留灰邊 | 光先在卡裡出現，讓未翻的卡有「裝著東西」的感覺 |
| 卡外光暈／蓄力 | `gacha-card.css:332–337`：傳說雙層陰影 34/96px，hard 增至 50/140px；呼吸從 1.6s 加快到 .35s。`33–40` 加震動，`44` 壓暗其他卡 | 用亮度、範圍、頻率一起爬升，與翻面後的釋放形成反差 |
| 卡後射線 | `src/gacha-fx.js:217–278` `rays()`：`under:true`、加色混合、260px 徑向底光；14 與 11 道寬窄不同射線，逆向不同速旋轉，長度預設 900；有淡入、自動停留上限與淡出 | 卡本身遮住光源中心，角色可讀；雙組轉速避免像一個硬轉盤，長射線讓小卡有大尺度存在感 |
| 翻面爆發 | `gacha-fx.js:166–213` 公開 `reveal()`：普通 8 顆灰塵；精良一環＋26 星；史詩雙環＋48 旋散紫光＋14 上飄星；傳說一環＋40 外緣火星＋20 餘燼＋8 星芒 | 各階不只換顏色。傳說粒子先在卡外緣出生，中央留給立繪；.55s 衝擊與最長 3s 餘燼分開消退 |
| 正面材質回應 | 基底 `.face-holo` 在 `gacha-card.css:125–159` 有稀有度鍍膜；實際 `skin-af` 覆寫在 `263–267`，變成畫窗內跟 `--mx/--my` 走的斜帶與 glare | 這是手上卡的反光，不是桌面的爆炸；移動游標仍能接續觀看 |
| 揭曉一次性反光／回彈 | `gacha-card.css:185–193,269–279`：`reveal-pop` 帶卡面抬起；AF sheen 550ms 一次，AF 餘燼是 live-enter 900ms 一次 | 翻面結果本身有反應，避免所有動作都在卡的周圍 |
| 神話專屬 | `gacha-card.css:374–405`：`--spin` 6s conic 框／寶石／卡背，雙色外暈；正面 holo .35、color-dodge，mask 排除畫窗。`gacha-fx.js:168` 加 scope 彩粒與 rainbowRing，rays 的 mythic 分支用七色 | 有持續可辨認的彩虹身份，加上更長的揭曉節奏；不是每階都套神話轉盤 |

必須注意三個容易讀錯的地方：

1. `src/gacha.html:14` 的宿主帶 `skin-af`，不能把 CSS 前半段比較濃的 `.r-legendary .face-holo` 當成 AF 最終效果。`src/gacha-card.js:94` 把一般卡 holo 放在 art 內，神話放到整個 face；神話另以排除式 mask 避開畫窗。
2. `GachaFx.reveal()` 與 `GachaFx.createScope().reveal()` 是兩套。後者在 `gacha-fx.js:330–355` 只有 0/8/12/20/32 顆短命粒子，傳說／神話加六條短線；**不能拿它代表共用翻卡的完整爆光**。runtime 在 `gacha-mode-runtime.js:110` 呼叫的是公開版，`ctx.fx` 才是 scope。
3. 公開版 mythic 呼叫 scope 後沒有 return，仍往下跑傳說段落；實際是彩色 scope＋彩環＋傳說段的組合。`rays()` 雖收 `color`，非 mythic 漸層實際寫死橙金，不能只傳 palette 就宣稱已支援卡色。這些是舊實作細節，不在本輪修正。

### 2.2 舊版時間軸：聲音落在「看見結果」那拍

`src/gacha-mode-runtime.js:78–143` 共用 R：傳說／神話先壓暗、起 rays、`sound.charge(1.05)`，560ms 後 hard，再等 520ms，共 **1080ms 蓄力**。神話額外 120ms 白閃（207–209）。接著翻面 580ms；翻面開始後傳說 270ms、其他 290ms 才 `notify`、`sound.reveal`、公開版 `GachaFx.reveal`。之後普通等 300ms、傳說 900ms、神話 1180ms，最後退暗、收 rays。

也就是：**卡背／卡後預熱 → 轉過側面時聲畫爆發 → 正面停留 → 餘光退場**。`rays` 的 hold 從建立時起算，且自己會開始 .8s 淡出，不能把 runtime 最後的 `stop(1.4)` 當成保證完整持續的 1.4s 尾光。

音效由 `GachaAudio` 的 scope 經 runtime 編排，五種模式還各自用 `tone/noiseHit` 補紙張、衝擊、上升音。新提案沿用 WebAudio 合成，不引錄音。

### 2.3 五種模式各自提供什麼

| 既有模式 | 已讀的實際路徑 | 與「抽到的光芒」的關係 |
|---|---|---|
| 拆包桌面 | `gacha-mode-hearthstone.js:17–36`：430ms 撕開、白閃、packBurst、震動，140ms 後發牌，再 interact | 開包爆光是整包事件；後續單卡才走共用 R。不能把兩次高潮混為一個粒子函式 |
| 撕包 | `gacha-mode-rip.js:129–171`：煙／鋁箔粒子，卡疊起，逐張 `ctx.cards.reveal`，onFlip 同步 580ms 滑出 | 手勢、滑出方向與單卡翻面相連，射線仍來自 R |
| 流星投遞 | `gacha-mode-wish.js:6,45–54,100–149,182–209`：暖白彗尾、白核、撞擊雙環、70 火星、坑口 2200ms 餘光，再浮卡／interact | 大範圍光有移動光源與落點。`WISH_TELEGRAPH=false`，除神話例外，不應描述成一般傳說必有金色流星／懸停 |
| 腳印召喚陣 | `gacha-mode-summon.js:14–18,55–87`：透視陣、地面光、環上亮片、五根相隔 90ms 的 1.4s 光柱，再發牌／interact | 卡是從光柱裡出現，有明確空間關係；註解稱暖白不預告，但 `35–40` 實際腳印已依結果上色，不以註解覆蓋程式事實 |
| 拉幕登場 | `gacha-mode-stage.js:106–133,160–190,193–229`：燈閃蓄力 1080ms，剪影變亮、揭曉音、rays、星芒和彩帶雨，再把角色收成卡 | 主要是獨立 `revealFx()`，**一般登場不重播 R**；只有 veil 分支再呼叫 `ctx.cards.reveal`。光照到角色的因果關係最直接 |

所以使用者稱讚的可能是射線、透光、材質的組合，無法從一句話斷定只愛哪一層。最值得先復現的共同特徵，是「焦點卡有自己的光源與完整起落」；不是把所有舊模式特效一起搬進新模式。

## 3. 現在這版為什麼可能比較差

### 3.1 星軌試抽的確定差異

以下來源皆為 `_art/holo-test/build_deluxe_b.py`。

| 可核對的事實 | 對觀感的具體推論 |
|---|---|
| `255–272` 的 shock／burst 都 append 到 `#orbit`，粒子出生在 orbit 中央；`377–380` 放大的卡只移到原槽位的 .3/.35 倍，未必居中 | 非中央槽尤其十連，獎品與爆光中心分離，像背景在播放慶祝特效，卡只是被放大 |
| `98–100,273–277` 定義 conic rays 與 `rayBurst()`，但揭曉沒有呼叫它 | 目前有光圈和粒子，卻沒有舊版卡後寬窄射線與底光的支撐；不能說「現在射線太少」，實際是這條路未啟動 |
| `362–391` 大卡只 300ms rattle，接 190ms 等待就露正面；舊版先蓄 1080ms。`395–413` 在露面後用 soft-light 閃、shock、burst | 預期建立较短，釋放與卡後亮度的連續性較弱。加長不是必然更好，需檢驗等待是否有有效變化 |
| `370` 建立器先畫中立材質；`425–430` 只在後段 reset／pointermove／leave 呼叫 paintFoil | 揭曉沒有人移游標時，`--phase/--fx/--gx` 不會沿時間走。新材質可動，但高潮仍主要是外圍光圈 |
| `393–413` 色彩取固定稀有度常數，未用單卡 `pal` | 同階卡出場的光都一樣，漂亮的新角色配色沒有參與演出 |
| `333–343` cascade 不 await revealOne；傳說每 1000ms 開下一張，但本張到 1470ms 才開始回槽，回槽再 460ms | 連續高階卡會有焦點重疊。神話星場 2200ms 與下一張 1500ms 起拍也交疊；可能上一張還在慶祝，下一張已搶畫面 |
| 原型沒有 AudioContext／GachaAudio／tone 的揭曉接線 | 少了與正面露出同步的合成音。比較時應分靜音與有聲，避免把聲音改善誤算成光效改善 |

不是以「粒子數少」概括退步：現在神話已經有 46＋34 顆粒子、三道衝擊波，份量不小。核心差別是出生點、節拍、前後層次及材質是否參與。

### 3.2 裝幀典藏是另一種情況

`src/gacha-mode-deluxe.js:63–67` 隱藏 back-leak、back-motes、back-sweep 與 face-holo／glare／embers／sheen，只在焦點 charging 時重開 card-glow。`195–205` **仍呼叫共用 R**，因此不能說它沒有舊 rays。它的 `material()`（130–153）在翻面後再加 900ms foil/gem/ink/particles DOM 效果；這些是 CSS 幾何疊層，並非 `card_face.js` 的角色 mask 材質。`freezeCards()`（161–170）又隱藏材質。

若使用者指的是這個入口，問題候選是「卡內透光／反光被遮掉、後加材質與既有揭曉分成兩段」，不是星軌的中央光源問題。本提案先針對星軌試抽驗證，不將兩條宿主一起改造。

## 4. 新能力的真實邊界

| 能力 | 現況／可用方法 | 不可假設的事 |
|---|---|---|
| subject-mask | `_art/holo-test/card_face.js:81–90` 用裸檔名索引 masks，非 flat 才掛材質；`demo.html:15,24` 定義 mask 與 foil/glare | 不是所有卡都有角色 mask；mask 是 alpha 區域，不是輪廓路徑、法線或光流資料，不能直接產生沿輪廓奔跑的火花 |
| palette | `card_face.js:51–56` 寫 base/glow/accent/ink；`pool_data.py:61–74` 由 `art/palette.json` 配給 CATALOG | 四張 `SCENE_CARDS` 目前沒有附 pal；用建立器 fallback。摯友之狐 accent 是 `#b0a572`，不是高亮光源，需在演出層提亮，不改原始配色檔或框色 |
| 材質座標 | `card_face.js:182–214` `paint(...,{tilt:false})` 可由時間軸送入 x/y，推動 fx/fy/cx/cy/gx/gy/phase，rx/ry 與圖內 shift 為零 | paint 同時寫 foil/grain/glare 與 Z；不能兩個控制器同時寫。高階 phase 同時影響框和字，不能為演出另改字效 |
| 共用建立器 | create／observe／paint／refit／unobserve 已有 | 沒有現成 `reveal()`、光效 scope 或任意材質 keyframe API；應由演出 wrapper 管有限時間軸，不重造卡面 |
| flat | create 不掛 subject-mask；現有 bg 材質又被 `.kind-flat .face-depth-bg{display:none}` 隱藏（`demo.html:92`） | 不能說只呼叫 paint 就能把整幅 flat 畫面掃亮。凍結內部 DOM 下，先讓既有 frame-material 回應，廣幅光在卡外演出層完成；新增 flat 圖面箔層不在本案 |

硬邊界：遵守 [HANDOFF 六之五](HANDOFF-holo-cards.md#六之五卡片製作工法凍結禁止隨意更動)，不改圖窗／文字框／文字層／寶石幾何、Z、字級字效、mask 工法、人物裁切。揭曉期間與結束後均不讓內部卡片傾斜／圖內平移。沿用既有外層入場和回槽動作即可。卡背不新增 CSS mask。WebAudio 合成、現有自製素材；不引第三方素材、WebGL 或新依賴。

效能規矩只管閒置。演出中保留足夠射線、粒子、層次及停留，不以省電名義先砍；離開／收下／取消才要求停止。reduced-motion 是另一個明確無障礙分支，不是一般演出的縮水預設。

## 5. 三個可行方向

以下數字是**首輪可試的節拍提案**，不是已定案工法。時間相對單卡開始，正常動態下以傳說為標準。三案共用：先準備／解碼正面與所需 mask；只有一個前景焦點；材質時間軸持有期間記錄但不套用游標，完成後平滑交棒，leave 回中立。全域音效與卡內亮峰以同一 reveal marker 排程。

### 方向一（推薦）：卡後蓄光 → 材質接光

| 時間 | 畫面／聲音 |
|---|---|
| 0–560ms | 卡背附近漸亮，卡後兩組寬窄射線起勢；其餘卡與環境壓暗。WebAudio 上升低頻，光源跟焦點卡走 |
| 560–1080ms | 光暈擴大、亮核收緊；延續既有外層卡背動作，不改內部 Z |
| 1080–1370ms | 開始既有翻面；側面轉向可見正面時觸發 reveal marker，同拍衝擊、星芒、合成揭曉音 |
| 1370–1820ms | 用 paint 的 x/y 從左上經中央走到右下（首版可用 −.8/−.5 → 0/0 → .8/.5）；卡後射線仍在，角色 mask 內的 glare/foil 接續同方向掃過 |
| 1820–2300ms | 卡內回到中立，外緣餘燼退場；保留讀卡停留後回槽，才讓下一張高階卡取得焦點 |

新能力：depth／framed 的 mask 接住掃光，palette.accent/glow 染卡外光暈和部分粒子；稀有度仍主導第一拍，保持史詩紫、傳說金、神話彩的辨識。flat 用 frame-material 的 phase 接光，外部射線沿卡後發散，不假造角色輪廓。

神話在翻面前加 120ms 亮核脈衝，接光段延長約 300ms，既有框字同 phase；不新增永轉動畫。普通／精良省去長蓄力，建議 120ms 預熱＋約 580ms 翻面與短回光；史詩約 400ms 預熱，紫色環與短掃光。這是階級差異，不是演出效能上限。十连普通可保留錯峰，高階需排焦點鎖，餘燼可並行。

落點：後續在 `build_deluxe_b.py` 的 `revealOne/cascade` 編排，以新的卡外 transient 層取代固定中心的 shock/burst 定位；重現 `GachaFx.rays` 的双組結構但不改舊檔案、不直接把全域 Canvas 單例接進第二宿主。卡內只經既有 paint API。

風險：放大卡在移動，外光用錯座標會漂；mask 的可見輪廓與原圖可能有對位偏差；glare 若過強會洗掉表情；多張高階的整體時間會增加。先以每張焦點卡的實際投影位置定位光，再驗明暗與停留，不用增加中央白閃補救。

**專屬驗收**：在左／中／右及十連上下排，光源中心距焦點卡中心 ≤ 卡寬 5%；錄製關鍵幀，確認正面初見、卡外爆發、合成音 marker 相差 ≤50ms；mask 內材質亮度峰由左上到右下依序發生，flat 則檢查框相位。光尾仍在時，名字／角色辨識不劣於現版。以第 6 節成對盲測決定是否勝出。

### 方向二：由角色亮起，再把光送到框外

| 時間 | 畫面／聲音 |
|---|---|
| 0–420ms | 卡背附近細光聚攏，短合成吸氣音；沒有先用舞台大爆光 |
| 420–1000ms | 翻面；約 710ms 正面初見。第一拍由既有 mask glare/foil 掃出角色的亮區，背景暫不搶峰值 |
| 1000–1400ms | 高光走過角色後，框的 phase 接續、卡後扇形射線展開，WebAudio 和弦在這個擴張點完成 |
| 1400–2200ms | 外緣火星散去，角色與框回中立，停留讀卡並回槽 |

新能力：同一組現有材質子節點可在演出期間接受局部 CSS 變數覆寫，讓 subject-mask 比 bg 的亮峰早 180–250ms；結束必須移除覆寫，恢復共用 paint，沒有新內部 DOM。palette 主要用於後段外光。depth 保留原分層，framed 只亮角色可用 mask；flat 改為「既有框先亮 → 卡後外光」，不聲稱有角色發光。神話增加第二道不同色的材質通過，傳說單道，史詩縮短後段，普通／精良短框光。

落點：`build_deluxe_b.py:revealOne` 的材質時間軸比方向一多管理 subject-mask、face-depth-bg 既有材質節點的暫時值；不讓 `HoloCardFace.paint` 與局部 writer 競爭。射線和音效仍由 wrapper 管。

風險：現有 mask 只定義區域，**不是發光輪廓描邊**；overlay／normal 混合未必能在暗角色上得到理想亮度。為顯亮若必須改 mask、混合工法或加法線，應判定這案不適合本輪，不能偷偷突破凍結。flat 與其他型的敘事一致性也较弱。

**專屬驗收**：同一時間點比較「原樣」與「只有揭曉材質增量」兩幀，mask 外的角色層增量應只有原遮罩羽化邊界，不新增發光漏邊；量 subject／background 的亮峰先後差應落在提案區間。暗色 framed、淺色 framed、四場景逐一看角色辨識時間；flat 獨立評估，不能拿 depth 的成功代替。盲測另外要求受測者指出光先來自哪裡。

### 方向三：一盞展品燈，卡面與卡後同向掃過

| 時間 | 畫面／聲音 |
|---|---|
| 0–450ms | 環境退暗，一束卡外暖白燈帶由左上進場，短掃頻與低音形成期待 |
| 450–1030ms | 翻面；燈帶掠過卡中央時觸發揭曉音與單次外緣爆光，卡內 paint 用相同方向跟進 |
| 1030–1600ms | 燈帶向右下滑出，留下 palette 色底光與框反射；神話多一次交叉彩光，傳說不交叉 |
| 1600–2300ms | 保留展品式停留，底光／星芒退場，卡回槽 |

新能力：以 `--gx/--gy` 與 fx/fy 同步一個可追蹤光方向，depth／framed 的既有 mask 接光；flat 以框和卡後燈帶接光。palette 給底光個性，主要燈核仍暖白，第一拍稀有度環維持辨識。不要從 stage 搬入簷幕、角色走路或重新搭劇場；這案只借它「有一盞燈照到獎品」的可讀性。

落點：`build_deluxe_b.py` 舞台 transient 層新增可定位燈帶，`revealOne` 以單一卡片局部座標的光路推進材質；使用 CSS gradient 或 Canvas 幾何，不加素材。普通／精良單次快速掠光，史詩紫色尾光，高階才有完整停留。

風險：大燈帶若繪在卡前会遮圖文，應把大面積亮度留在卡後，卡前只用現有材質。場景光與 material 的局部座標轉換不一致會穿幫；只剩柔和掃光也可能欠缺使用者喜歡的爆發，所以保留短射線與星芒脈衝。

**專屬驗收**：在卡外燈方向、卡內 glare 峰值各設取樣區，峰值時間差 ≤50ms，方向不得相反；移動焦點／resize 後仍同向。相同卡池做關掉外燈、關掉內材質兩個消融版本，受測者對「燈照到卡」的判斷應以完整版本最好；名字辨識和稀有度辨識依第 6 節驗證。

## 6. 怎麼驗證真的更好

以下是下一輪驗收設計，**本輪沒有執行，數值是提案門檻**。美感無法由粒子數或平均亮度證明；需要可重現的畫面證據加上使用者偏好。

1. **固定比較資料。** 先保存目前星軌原型；再有「卡面收尾修正後、揭曉未改」控制組。三案均從後者分支測，避免把任務 A 的修正誤算成新光效。相同卡序、槽位、視窗、圖片 bytes、輸入時機；測試用固定視覺 seed，不改正式抽率。舊五模式錄影作參照，尤其共用 R 與 stage；不同卡面／時長的舊錄影不能當嚴格光效因果實驗。
2. **覆蓋材料與節奏。** 四張 depth、兩張 flat、傳說 framed 摯友之狐、神話 framed、普通 toy、精良與史詩；尺寸 80/102/150/230/290px 的靜態幾何沿用現有回歸。實際演出測單／五／十抽，連續兩張傳說、神話後接普通、首末槽高階、reduced-motion、快速連點、resize、收下再抽。身份與終態數量一致。
3. **聲畫分開比較。** 第一輪靜音看光源連續性和可讀性；第二輪三案用等響度 WebAudio 比較完整回饋。記錄露面、爆光、材質峰、可讀、回槽、可收下時間。錄影慢放查空白正面與遮擋，不能只截最亮的一幀。
4. **可讀性與偏好。** 以固定卡名選項、稀有度五選一測辨識正確率及反應時間；每案至少 12 組相同情境、順序打散的成對片段，隱藏版本名稱，使用者分別評「抽到的瞬間有力」「光屬於這張卡」「看清角色／名字」，並做整體選擇。首輪採用門檻：對控制組至少 8/12 組偏好、辨識錯誤不增加，辨識時間中位數不慢超過 10%。這是單一使用者的採用準則，不宣稱統計普遍性；沒達到就記平手／失敗。
5. **不破工法。** 同卡同寬中立時，DOM 層次、字型、plate/text/gem 幾何與回歸控制組一致；revealing 與 revealed 的 rx/ry、ax/ay、bx/by 均為零。名字、框與寶石不越界。亮度 peak 另外量名字／角色 ROI 的可辨資訊，不能把亮度越高當越好。
6. **清理與時序。** 取消／收下／reset 後，該抽次擁有的 timer、rAF、動畫、transient DOM、音效節點與 detached observer 都歸零；舊抽次 callback 不得碰下一抽。一般播放完整保留演出量；閒置 5s／30s 探針不得有自動反光／粒子更新。pointer 事件可以觸發材質，停止輸入後不能留下常駐循環。記錄演出掉幀用於定位，不以任意粒子上限換通過。

三案共用 reduced-motion 終態：取消快速旋轉、震動、往返燈路與大閃光，用 150–240ms 正面淡入及一次溫和亮度轉換，仍可辨認稀有度、名字與收下狀態。它的通過不代表一般演出通過。

## 7. 採用順序與推薦理由

先做任務 A 的未結收尾與快轉生命週期，再只試方向一。它對應最有證據的三個缺口：卡後射線未啟動、外光沒有跟卡、材質沒有接揭曉；沿用既有 paint 就能先驗證，不必新增卡面工法。保留舊版蓄光與爆發的份量，再用 mask／palette／材質座標讓光有單卡個性。

方向二在 depth／framed 最可能做出新鮮感，但暗圖及 flat 的限制較大；方向三有明確光源，卻較容易變成柔和展示，未必解答「抽到那一下」的期待。若方向一只改善重量、角色仍像貼上去，才用方向二的材質先後作第二輪實驗。不要三套一起堆，讓使用者無法判斷是哪個改變有效。
