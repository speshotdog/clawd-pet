# 2.0 的美術方向：我在第一輪砍錯了範圍

## 一、事故本身

第一輪地圖派工簡報 `BRIEF-astra-2.0-map-round1.md` 白紙黑字寫著
「**廢墟地景美術**不在這一輪」。codex 照做，交出來的頁面：

```
頁面裡的圖像元素（img/picture/video/canvas）：0 個
body background-image：none
```

使用者的反應是「看起來超簡陋」。**這不是 codex 做壞，是我把範圍砍錯了。**

而且它是可以量出來的，不必靠感覺：
`PLAN-2.0-visual-C.md` 第五節（astra 出的門檻）寫著
**地圖常態時「地景可見面積」要占可用畫面 60～75%**——第一輪實測是 **0%**。
畫面 100% 都是介面骨架。**門檻表裡有一條下限沒有人去量。**

## 二、更根本的一層：C 的方向跟這個專案的畫風基準不相容

`BRIEF-cardback-art.md`（2026-09-08）已經寫死這個專案的畫風基準：

> 深藍底、奶油色描邊、**粗黑輪廓線、扁平上色、沒有寫實光影**。跟角色 PNG 同一套語言。
> 不要加寶石、鑽石、光暈特效那種廉價的「高級感」。

而我核准的 C＝「災後搶修工作盤」是**極簡工業風**（煤灰／氧化灰綠／骨白、直角、磨損）。

**極簡語言 ＋ 零美術 ＝ 線框圖。這是必然結果。**

跑過既有的兩個頁面當基準，結論很清楚：
**這條線的 UI 品質是美術素材撐起來的，不是 CSS 排版撐起來的。**
抽卡入口靠的是那張精裝包插畫＋召喚陣 SVG；卡面頁靠的是真的卡圖＋箔面材質。

## 三、使用者裁決（2026-09-10）

| 題目 | 答案 |
|---|---|
| 廢墟地景與地圖節點的畫風 | **跟卡面同一套手繪**（粗黑輪廓、扁平上色、手繪貼紙感），題材是廢墟 |
| 第二輪範圍 | **先做一段當樣品**（後院草地・廢墟），看過再決定要不要量產剩下四段 |

### 這改變了 C 在畫面上的地位

```
原本（第一輪做出來的）：工作盤 ＝ 整個畫面
改成：              地景 ＝ 畫面主體（60～75%），工作盤 ＝ 邊框骨架（覆蓋 10～20%）
```

**C 沒有被推翻，被推翻的是「C 佔滿畫面」。**
astra 第五節那張表本來就是這樣寫的，是我第一輪沒有把地景放進範圍才失真。

⚠ 這也代表**第一輪那兩個貼著下限的面積指標要重新解讀**：
導軌占非卡片 UI 65.96%、紋理 12.99%——分母是「非卡片 UI」，
加進地景之後**分母不變、但 UI 本身要縮**，這兩個數字會變，
不能拿第一輪的數字當基準線。

## 四、畫風硬限制（沿用 `BRIEF-cardback-art.md`，不要重新發明）

- 粗黑輪廓線、扁平上色、**沒有寫實光影**
- 手繪貼紙感，不是系統字型符號、不是 emoji
- **不要**寶石／鑽石／光暈特效那種廉價的高級感，**不要**金屬漸層寫實反光
- 參考基準：`src/gacha-cardback.jpg`、`_art/holo-test/art/card-*.png`

## 五、甲案的辨識契約

地景是**認得出來但毀了**的 1.0 舊場景。所以每一段都要：

1. 指定 **2～3 個識別物**（形狀必須保留，不能只是「都是草地」）
2. 隱去地名的場景配對正確率 **85～100%**
3. UI 開啟後仍須 85～100%，比 UI 關閉下降 **0～10 個百分點**
4. **識別核心被不透明面板遮住 0%**；地標輪廓被 UI 遮住 0～10%

⚠ **用名稱提示才認得、遮掉名稱就配錯，不算通過。**

### 第一段（後院草地・廢墟）的識別物

1.0 的後院草地實際長相（`clicker-scene1-*.png`）：
綠草地、**紅白格紋野餐布**、**粉紅爪印小旗**、白色柵欄、小花、藍天白雲。

指定識別物（三選三都要保留形狀）：**紅白格紋野餐布、粉紅爪印小旗、白色柵欄**。
廢墟化的方式是**破壞它們的狀態，不是換掉它們**：
布撕裂捲起、旗褪色歪斜、柵欄倒塌缺板、草枯黃倒伏、天空壓暗。

## 六、2026-09-10：編隊畫面改用精裝卡牌語言（使用者裁決）

使用者看過編隊第一輪的成品之後：

> 我覺得隊伍 綠底風格不好看
> 隊伍也沒有利用到 精緻卡牌的優勢
> **精緻卡牌就是好看 才存在的**
> 請以精緻卡牌的風格來製作相關 UI

### 這是三道門的第二道被判定不通過

`PLAN-2.0-visual-C.md` 第六節那三道門就是為這一刻設計的：

> **② 卡片仍被讀成獨立嵌入物** —— 單看成品仍像外掛，即觸發。

第二道門由使用者判定**不通過**。而且我自己量到的數字跟這個判定一致：
承載槽開／關只差 **0.954%** 的像素（`shots/team-round1/VERIFY-claude.md`）——
**那一招根本沒做出來，所以卡當然還是像被塞進格子裡的清單項。**

### 但解法不是退回備案 B

第六節寫的是「停止擴大 C，將後續介面方向切到 B」。**這裡不適用**，因為：

- B ＝ 1.0 牛皮紙的黑化版，astra 早就指出它會讓精裝卡**更**像外來物（圓體＋咖啡描邊）
- 使用者要的不是「換一套介面」，是「**讓卡當主角**」

**所以是分畫面決定，不是整體改方向：**

```
地圖畫面   →  維持 C（災後搶修工作盤）。它成立，因為畫面主體是廢墟地景，
              工作盤只是邊框骨架（實測地景可見 60.8%、UI 覆蓋 10.2%）
編隊畫面   →  改用精裝卡牌語言（＝ astra 最早推薦的 A）。因為這個畫面沒有地景，
              主體只能是卡；工作盤在這裡就變成「把卡塞進格子的容器」
```

⚠ **這不是推翻 C，是承認 C 沒有主體時撐不起畫面。**
第一輪地圖沒有地景時是線框圖，編隊沒有地景時是綠色表格——**同一個病，兩次發作。**

### 「卡是主角」要怎麼量

原本第一道門是「新語言占**非卡片 UI** 面積 65～85%」——那條在編隊畫面要反過來用：
它管的是 UI 內部的構成，卻**沒有管 UI 到底該占多少**。所以補上：

| 項目 | 編隊畫面 |
|---|---:|
| 卡片（總覽卡 ＋ 詳情卡）合計面積／可用畫面 | **45～70%** |
| 非卡片 UI 面積／可用畫面 | **12～30%** |
| 1440×900 總覽卡寬 | **≥ 140px**（上限 200px）|

⚠ 第一輪總覽卡寬是 88～104px——**那個尺寸看不到箔面，等於把精裝卡當縮圖用。**
使用者那句「精緻卡牌就是好看才存在的」講的就是這件事。
