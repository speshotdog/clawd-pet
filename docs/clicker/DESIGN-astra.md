**建議做成「珍母帶大家拆零食包裝」的單機放置遊戲：點珍母賺錢、升級手勁、招募夥伴、讓全隊自動工作。抽卡在遊戲視窗內演出，與抽卡試作區共用元件，但完全分開記帳。**

我不同意直接把「傷害」當成錢幣的另一個名字，又沒有受擊目標。建議玩家介面稱「拆包力」：珍母是操作主角，零食包裝是目標。每 1 點拆包力立即產生 1 枚錢幣，同時推進拆包進度。

以下是實作基準稿。數值有做簡化經濟試算，尚未經遊戲實機調校；本輪未修改任何檔案。

**一、核心循環與數值**

**1. 開局與手點**

開局錢幣 0、點擊等級 `L=0`、全隊訓練 `T=0`。中央珍母是固定主角，**不等於已獲得珍母卡**；抽到珍母才解鎖其被動與寄生技能。

完成第 50 次有效點擊，直接送玥玥 `yueyue2` 一張，提供每秒 4 幣。這是明示的教學獎勵，不偽裝成隨機抽卡，也不推進保底。

定義：

```text
B = 所有已擁有角色的基礎收益 × 各自星級倍率之總和
P = B × 1.15^T                         // 常態每秒收益
D = 1.18^L + 0.05 × P                 // 常態每次點擊收益
```

`D` 的第二項讓點擊隨隊伍成長，避免玩家養大隊伍後，點珍母只剩裝飾用途。暫時技能不回灌 `P`，避免技能之間遞迴放大。

| 項目 | 定案 |
|---|---|
| 有效輸入 | 左鍵或聚焦主按鈕後按 Space；忽略鍵盤自動重複 |
| 輸入上限 | 每秒最多 8 次有效點擊 |
| 按住連點 | 第一版不做 |
| 隨機暴擊 | 第一版不做；重擊交給角色技能 |
| 連點加成 | 只改動作節奏，不額外增加收益 |
| 連點判定 | 相邻點擊間隔 ≤400ms，連續第 3 下進入連點狀態 |
| 連點結束 | 600ms 沒有有效點擊即結束 |
| 金額精度 | 內部保留小數，餘額主顯示向下取整；詳細收益顯示至小數一位 |

不做「維持連擊才有效率」，避免桌面小遊戲變成長時間高速點擊作業。

| 全隊訓練，當前 `T` | `ceil(1000 × 1.60^T)` | 全部角色常態收益乘 1.15 |

介面直接寫「每次 12.5 → 14.2」，不要只寫「攻擊 +18%」，因為全隊貢獻的部分不跟著乘 1.18。

購買提供「1 級／最多」，最多購買以逐級費用總和計算；不增加另一條折扣規則。

**3. 招募價格與卡池**

遊戲的角色招募只抽 12 隻角色。共用的 17 筆素材目錄仍保留，但三個玩具與兩個 emoji 不進付費角色池；花錢想抽角色卻抽到熱狗，是這個循環不需要的挫折。

保留現有角色稀有度：

同階角色等機率。普通在角色池中權重為 0。

設已付費抽取張數為 `n`：

```text
下一抽價格 C(n) = ceil(150 × 1.30^floor(n / 5))
五連價格 = C(n) + C(n+1) + … + C(n+4)
```

| 已抽張數 | 下一抽價格 | 對齊該批起點的五連價格 |
|---:|---:|---:|
| 0 | 150 | 750 |

**五連不打折，也不另加保底。**玩家不用為了效率被迫存五連；五連的價值是少操作、一次看五張。價格只依已抽張數增加，不能跟當前收益連動，否則升級會讓商店偷偷漲價。

保底改為：

- `sinceLegendary` 計算連續未出傳說的**張數**。
- 前 39 張照常抽；若仍未出傳說，第 40 張必出。
- 任一傳說使計數歸零。
- 五連按順序處理五次，跨保底時從該張重新計數。
- 沒有軟保底、沒有額外五連保底。
- 教學贈卡與里程碑贈卡不計數、不重置。
- 招募入口常駐顯示「最多再 X 抽必得傳說」。

現有演示區的「10 包必出」保留原樣，不能把兩者存檔或計數混用。

**4. 重複卡＝自動升星，不留塵**

| 累計同角色張數，含首張 | 星級 | 收益倍率 |
|---:|---:|---:|
| 1 | 1★ | ×1.00 |
| 2 | 2★ | ×1.25 |
| 4 | 3★ | ×1.50 |
| 8 | 4★ | ×1.75 |
| 16 | 5★ | ×2.00 |

超過 16 張，每張再加基礎收益的 1%：

```text
星級倍率 = 對應星級倍率 + 0.01 × max(0, 張數 − 16)
```

例如累計 20 張是 ×2.04。滿星後不再加星，用「熟練 +4%」表示。

**遊戲區取消塵。**重複卡同時升星又給塵，會多出第二套商店與兌換平衡；這版沒有必要。演示區仍可保留原本的塵。

同一包連抽同角色，逐張計算「第幾張／是否升星」，結果卡顯示「2★ → 3★」或「升星進度 3/4」，不只顯示 DUP。

**6. 拆什麼：熱狗零食包裝，沒有戰鬥失敗**

舞台下方放既有熱狗 emoji，外面是 CSS／SVG 畫出的透明包裝與封口。只畫 UI 外殼、撕線與進度，不畫新角色或怪物。

每包需要的拆包力：

```text
第 k 包需求 H(k) = 100 × 1.12^(k−1)，k 從 1 開始
```

- 75%、50%、25% 剩餘時，各多一道撕線。
- 拆完外殼向兩側退開，下一包直接接上。
- 溢出拆包力繼續作用到下一包，不能浪費暴擊或離線收益。
- **拆完不再發一份金幣**，避免相同拆包力被算兩次收入。
- 包數提供進度與里程碑，沒有卡關、死亡或倒退。
- 一次結算拆完很多包，只演最後一包，文字寫「完成 23 包」。

第 10／25／50 包分別把小恐龍、黃色球、皮球放到舞台背景，純裝飾、不入抽卡池。第 100 包解鎖一次 12 選 1 贈卡，協助補缺角；不影響保底。

離線結算用等比級數累積需求，二分找完成包數，不逐包跑動畫或迴圈。

**8. 離線與 prestige**

第一版就做離線：

```text
可結算時間 = clamp(現在 − 上次結算時間, 0, 8 小時)
離線基礎收入 = P × 可結算時間
```

離線效率 **100%**，不扣到 50%。玩家沒有必要讓遊戲視窗一直掛著。

尚未結束的時間型技能，只對其剩餘有效區間結算；次數型技能不自動消耗，到期即失效。CD 可以在離線期间完成。

回來顯示一張簡短收據：「離開 12 小時，結算 8 小時，獲得 X 幣」。收入先存妥，再顯示收據；關掉收據不影響領取。

**第一版、第二版不做 prestige。第三版才做「換一張新桌布，重新開工」。**

第三版起始規則：

```text
可領永久印記 = floor(sqrt(生涯總收入 / 100,000,000)) − 已領印記
永久倍率 M = 1 + 0.05 × 已領印記
```

- 首次達 1 億生涯收入開放。
- 重開清除錢幣、手勁、訓練、當輪包數。
- 保留角色、星級、保底、已抽張數與招募價格。
- 保留生涯收入與一次性獎勵領取紀錄。
- 清除技能效果，所有技能從完整 CD 開始。
- 有待收下抽卡時不能重開。
- 重開後 `P=M×B×1.15^T`，`D=M×1.18^L+0.05P`，不重複乘倍率。

保留角色是必要選擇：這個作品的情感資產就是這 12 隻，不該要求玩家把牠們刪掉換效率。

**3. 夥伴如何出現**

- 舞台最多 **珍母＋3 位夥伴**。
- 夥伴站定，不自由走動，不做避碰與尋路。
- 三位展示夥伴優先對應技能槽，珍母卡使用中央本體。
- 首次收下新角色時，該角色短暫從側邊滑入 320ms、停步，最多展示 1 位。
- 同包多個新角色只讓最高稀有度者入場，其餘在角色入口標示「新增 3 位」。
- 未展示者照常提供完整被動收益。
- 同時最多兩個角色播放 rig：珍母與正在發動技能的角色。

**4. 抽卡在同一視窗內演出**

採滿版招募覆蓋層，沿用 960×640 演出座標。底下舞台停止視覺動畫，但被動收益照常結算。

理由是演出需要五張卡的完整寬度，不能硬塞進右側 304px 商店；跳到演示視窗則會混淆「免費體驗」與「花遊戲錢抽取」。

- 第一版預設沿用已存在的 `wish`。
- `hearthstone` 作為可選演出，不重新開發模式。
- 單抽放中央，五連沿用扇形；按模式的 `counts` 能力核對入口。
- 有未收下結果時禁止再抽。
- 略過只跳到總覽，不自動收下。
- 關窗保留 pending；重開直接進結果總覽。
- 關閉招募層前須收下；視窗本身仍可關閉。
- 招募層開啟期間不能發動技能，已存在技能照時間正常到期。

**5. 一個事件，一個主要聲音落點**

| 事件 | 聲音 | 主要動作 |
|---|---|---|
| 點擊 | 160→95Hz，約 55ms 的短軟碰聲，gain 約 .05 | 珍母壓縮回彈 |
| 升級 | 520→780Hz，約 120ms 的短上滑音，gain .09 | 升級數值上推 6px，180ms 落定 |
| 技能發動 | 110→70Hz，約 140ms 的低短聲，gain .12 | 該角色表內的招牌動作 |
| 抽到新角色 | 沿用該卡稀有度揭曉音，入隊不再補鐘 | 收下後單次入場 |
| 里程碑 | 880Hz、約 240ms 的單次鈴聲，gain .10 | 小徽章蓋下，220ms |

點擊音最多每秒 6 次，數字最多每秒 8 個、同時最多 12 個；多出的收益合併成下一個數字。被動收入只更新計數，不持續噴數字。

技能重擊當下取代普通點擊音，不疊兩聲。沒有常駐粒子、背景音樂或每秒進帳音。減少動態模式改成短淡入與文字提示，收益完全相同。

**3. 存檔**

獨立鍵名：`clicker_save`。不讀寫 `gacha_save`、桌寵角色解鎖或寵物數值。

結構範例：

```js
{
  version: 1,
  balanceVersion: 1,
  revision: 42,
  savedAt: 1788600000000,
  settledAt: 1788600000000,

  coins: 12345.67,
  lifetimeCoins: 54321.89,
  manualClicks: 240,
  clickLevel: 12,
  trainingLevel: 3,

  collection: { yueyue2: 4, dog: 1 },
  paidDraws: 17,
  pity: { sinceLegendary: 17 },
  pending: null,

  package: { index: 25, progress: 120.5 },
  claimedMilestones: ["tutorial50", "package10"],

  skillSlots: ["yueyue2", "dog", null],
  cooldownUntil: {},
  slotReadyAt: [0, 0, 0],
  effects: [],

  settings: { muted: false, mode: "wish" }
}
```

`effects` 保存類型、來源、到期時間、快照數值、剩餘次數；不存函式。每秒收益與星級從角色數量、等級重算，不把容易失同步的衍生值當權威。

付費招募流程：

1. 等素材 ready，結算到當下。
2. 驗證餘額、張數與沒有 pending。
3. 抽一次，生成不可變結果及升星預覽。
4. **一次 `setItem` 同時保存扣款、抽數、保底與 pending。**
5. 寫入成功後才開始演出。
6. 收下時驗證 `draw.id === pending.draw.id`，先按舊產能結算，再增加角色張數、清 pending，一次寫入。
7. 寫入成功後才播放入隊動畫。

這裡「收下才落帳」指角色獎勵；扣款與保底在建立 pending 時已確定。關窗不能退錢重抽，雙擊收下不能發兩次。

防呆規則：

- 金額必須有限、非負；等級和張數必須為合法整數。
- 未知角色 ID、錯誤 pending、無法支持的較新版本，不默默清空存檔。
- 重要交易前留一份已驗證備份；讀檔失敗時提供備份恢復或匯出原始資料。
- `setItem` 失敗時不更新權威記憶體狀態，顯示「尚未儲存」並暫停消費。
- 正常點擊每 5 秒存一次；升級、技能、招募、收下、隱藏與關窗立即存。
- 系統時間倒退給 0 收益，保留時間高水位，避免同一時間區間反覆領取。
- 同一開啟期間用單調時間計算經過時間；跨重開用壁鐘與 8 小時上限。
- 本地存檔不宣稱能防改時鐘或改資料，不為單機試作建防作弊系統。

**5. 結算與動畫預算**

| 項目 | 預算 |
|---|---|
| 可見時被動結算 | 每 1 秒一次，依真實時間差計算 |
| 點擊／消費／技能 | 操作前先結算到該時刻 |
| 收益數字刷新 | 有操作時最多 10Hz；只有放置時 1Hz |
| 冷卻顯示 | 1Hz 整秒，不做持續旋轉冷卻圈 |
| 無互動待機 | 0 rAF、0 無限 CSS 動畫 |
| 隱藏／最小化 | 停所有視覺與週期計時，回來補結算 |
| 可見角色 | 最多 4 隻 |
| 同時 rig 動畫 | 最多 2 隻 |
| 浮字 | 最多 12 個 |
| 遊戲粒子 | 最多 24 個；普通點擊不產粒子 |
| 動畫結束 | 注銷 rAF，取消暫時 `will-change` |

結算跨技能結束時間時，按到期時間切成少量區間積分；不逐秒重播 8 小時，也不把動畫完成 callback 當成收益來源。
