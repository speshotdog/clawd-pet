# 討論題：略過演出遇到新卡要停下來（草案）

使用者的話：「如果抽到沒抽過的卡，略過卡片翻開的過程會被暫停，直接快轉到該張卡片正常翻開的動畫，然後繼續快轉。」

這份是我（Claude）的整體表現方式草案。**還沒實作**，等使用者定案後才寫簡報派工。

## 一、判定「新卡」的訊號已經現成

`gacha-pool.js:170` 每一張抽出來的卡都帶 `dup` 與 `owned`：

```
{ key, entry, dup: had > 0, owned: had }   // owned = 存檔 + 同一包前面幾張已持有的張數
```

所以 **`!item.dup` 就是「圖鑑上沒有過的第一張」**，而且同一包裡抽到兩張同角色時，
只有第一張算新——這正是我們要的。

重點是這個欄位在 `draw` 裡是**凍結**的，不是每次重算的，所以：

- 不必新增任何存檔欄位。
- 重開視窗還原 pending 時也拿得到同一份判定（但那條路**不可以**重播，見第五節）。

卡面右上角的 `NEW` 標籤也已經在了（`clicker-economy.js:120`，`!owned` 時回 `{text:'NEW', cls:'new'}`），
所以「為什麼停在這張」視覺上已經有答案，不用另外設計徽章。

## 二、我建議的表現方式

按鈕從「一次全開」變成「**掃過去，遇到新夥伴就煞車**」。逐張照抽卡順序處理：

| 卡片 | 處理 |
|---|---|
| 重複卡（`dup`） | 快速翻正，一張接一張 stagger 40～60ms |
| 新卡（`!dup`） | 先煞車 ~180ms，再播**完整的 `reveal()`**（含傳說蓄力、轉彩、神話閃光），播完繼續掃 |

### 為什麼這樣排，五個判斷

1. **順序不能亂，一定要照扇形由左到右。**
   最省事的寫法是「先 `showSummary()` 全部翻正，再回頭補播新卡」——**不要**。
   那樣新卡是在一個已經全開的扇形裡孤零零翻一次，讀不出「這張是特別的」，
   反而像 bug。掃過去的順序本身就是敘事。

2. **重複卡不要「瞬間全部翻正」，要看得見它被掃過去。**
   現在的 `skip()` 是畫面瞬間變成總覽。如果保留這個瞬間感，
   玩家會覺得「快轉鍵有時候有效有時候沒效」。
   逐張翻正、stagger 40～60ms，整排五張也只花 200～300ms，
   但**快轉變成一個看得見的動作**，新卡的煞車才有對比。

3. **新卡前面要有一個 ~180ms 的煞車。**
   從 50ms/張直接切進 900ms 的傳說演出，體感是卡頓不是強調。
   停一下讓掃過去的殘影收住，眼睛才跟得上。

4. **要有一行字說明為什麼停下來。**
   `#recruit-hint` 打「新夥伴・○○○」。沒有這行字，玩家的第一反應是「快轉壞了」。

5. **逃生口：快轉中再按一次＝真的全部略過。**
   按鈕文字跟著換（`略過演出` →按下後→ `全部略過`）。
   **不能把玩家關在他自己按的快轉裡**——尤其五張都是新卡的時候。

### 減少動畫（`prefers-reduced-motion`）

**照樣停新卡**，只是每段都短（`reveal()` 本來就有 reduced 分支：翻牌 150ms、無位移）。
不要在 reduced 時退回「瞬間全開」——**新卡是資訊不是裝飾**，
跟第二十九輪「減少動畫時浮字仍要看得到」是同一條道理。

## 三、要使用者決定的三件事

1. **轉彩（veil）的重複卡要不要也停？**
   轉彩是「精良框翻開後才變傳說」，是整套演出裡最強的一拍（`reveal()` 裡最長的分支）。
   快轉直接掃過去等於把最好的一拍丟掉。
   **我的建議：新卡與轉彩都停。** 但使用者只講了新卡，所以這條要問。

2. **升星／突破的里程碑要不要停？**
   重複卡如果剛好跨過升星門檻，卡面標籤會是 `3★ → 4★`（不是 `升星進度 5/8`）。
   那也是一個值得看的時刻。
   **我的建議：先不要。** 停太多就等於沒有快轉；先讓新卡與轉彩上線，看實玩再說。

3. **早期玩家的快轉等於沒用，可以接受嗎？**
   收集期五張常常全新，快轉會照播整段演出。
   **我的建議：接受，而且這是對的。** 早期你本來就想看每一張；
   52 張收滿之後新卡稀少，快轉才需要真的快。
   要不要另外給一個「連新卡也略過」的設定？我傾向先不要，多一個開關就多一份解釋成本。

## 四、按鈕的命名

「略過演出」在新行為下已經不精確（它不再略過全部）。建議：

- 主鍵改叫 **「快轉」**，按下之後變成 **「全部略過」**（第二次按才是現在的行為）。
- 或維持「略過演出」，靠 `#recruit-hint` 那行字解釋。

我偏好前者：**按鈕的名字要說實話**，而且它剛好也把逃生口的存在講出來了。

## 五、實作地雷（寫簡報時一定要列）

1. ⚠ **`restore()` 絕對不能走快轉這條路。**
   `clicker-gacha.js` 的 `restore()`（重開視窗時把還沒收下的 pending 還原）現在用的就是
   `runtime.skip()`。那是「**還原已經看過的結果**」，不是快轉——
   如果它去重播新卡演出，玩家會以為自己又抽了一次。
   **「快轉」與「還原」必須是兩個入口。** `suspend()` 同理。

2. ⚠ **`skip()` 現在是 `stop()` + `showSummary()`，而 `stop()` 會 abort 整個 runtime。**
   快轉不能 abort（abort 之後 `wait()` 全部 reject，什麼都播不了），
   要在 runtime 內部走一條新流程，`stop()` 留給真正的「全部略過」。

3. ⚠ **`rip` 與 `stage` 兩個模式的 `all()` 走的是另一條路**
   （`host.root.dispatchEvent(new Event('reveal-all'))`，交給模式自己處理）。
   拉幕登場本來就是一位一位登場的，「快轉」在這兩個模式的語意要另外定義，
   不能假設 `reveal(key)` 到處都通。

4. ⚠ **`collect-again`（收下並繼續五連）** 每一輪都會建新的 runtime，
   快轉的狀態（有沒有按過、是不是第二次按）要 per-runtime 重置，不能掛在模組層。

5. `automatic` / `busy` 這兩個旗標現在控制著「不要讓玩家在演出中亂點」，
   快轉是第三種狀態，要一起想，不要用 `automatic` 硬兜。
