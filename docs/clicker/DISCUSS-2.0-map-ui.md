## 一、脈絡：這是什麼東西

**2.0 =「末世地圖」**：打完 1.0 第七站「滅世都市」的 BOSS 之後才解鎖的關卡區域，
**只能用精裝版卡（deluxe）戰鬥**。抽卡系統就是為它而生——精裝卡池不是收藏側線，
是 2.0 的戰鬥單位。

已由使用者定死、**不要在你的提案裡挑戰**的規則：

- **地圖是線性的**（不是自由選路）。
- **BOSS 戰要額外設計**，跟一般關卡不同一套。**最後一關 BOSS 是「真・滅世珍獸」**。
- **編隊最多 20 張卡**，累加上限：神話≤2、神話+傳說≤6、神話+傳說+史詩≤12、總數≤20。
- **技能 4 格**，神話技能最多 1 張（硬限制）；任何組合的戰力不得超過 1神話+1傳說+1史詩+1精良。
- **開發順序：先做關卡 → 之後再提機制 → 一步一步做。**

還沒有答案、**你可以假設兩種都可能**的事（請在受影響的地方標明「這題取決於 X」）：

- 戰鬥是**自動**還是**有操作**（決定技能格是被動加成還是主動技，也決定戰鬥畫面要不要留操作區）
- 失敗的代價是什麼
- 真・滅世珍獸的素材從哪來

## 二、現在有兩套視覺語言，而且它們互斥

| | 1.0 點擊本體 | 抽卡演出 |
|---|---|---|
| 底 | 牛皮紙 `#E9D6B4` ＋ repeat 貼圖 | 近黑 `#010203`／`#091221` |
| 字 | Huninn（圓體），`#54382b` | Noto Sans TC，`#eadfc4` |
| 按鈕 | 圓角 9px、2px 咖啡色描邊、下方 2px 實心陰影、按下位移 2px | 六角切角 `clip-path:polygon(8% 0,92% 0,100% 50%,…)`、無圓角、`::before` 內縮 1px 當底 |
| 舞台 | **固定 960×640** ＋ `#zoomer` 等比縮放 | **滿版** `100vw/100dvh`，`.win` 用 `data-screen` 切畫面 |
| 質感 | 拼貼（膠帶、貼紙、標籤 PNG）| 材質（箔面、光暈、召喚陣 SVG、六層背景） |

**這就是這一題的核心矛盾**：使用者說「2.0 的 UI 都要用新的設計」，
但 2.0 的戰鬥單位是精裝卡，而精裝卡長在抽卡那套深色材質語言裡；
2.0 又是 1.0 的續章，玩家是從牛皮紙那邊走過來的。

### Q1（先回這題，它決定後面全部）

**2.0 應該是「第三套語言」、還是「抽卡那套的延伸」、還是「1.0 那套的黑化版」？**

請三個選項都評，各給：

- 玩家走進去的第一秒會感覺到什麼
- 要付出的成本（要新做哪些資產、哪些既有 CSS 可以直接吃、哪些一定要重寫）
- 它會不會讓精裝卡在戰鬥畫面上「看起來不對」
- **一個可量測的判準**，讓我能驗收「這確實是新設計，不是換個色票」
  （這條線的教訓：只寫上限的門檻＝做出看不見的東西。你的判準要**上下限成對**。）

給出你的推薦，並說被你淘汰的那兩個是**在什麼情況下**反而會是對的。

### Q2. S1 轉場：換世界的那一刻

請提出**具體**的轉場設計：元素以什麼順序消失／出現、各自的時間與位移、為什麼是這個順序。

注意兩件實作事實，你的提案要能落在上面：

- 1.0 是 `#zoomer` 縮放的固定 960×640；抽卡是 `100vw/100dvh` 滿版。
  **轉場必須跨越這個座標系差異**——請說明你打算怎麼處理（先縮放再展開？黑幕蓋住換？還是別的）。
- `ceremony.js` 已有 `setScreen()` 的三態機（`entry`／`ceremony`／`results`）＋
  `win.dataset.screen` 驅動 CSS。2.0 要沿用這個模式，還是另起一套？說理由。

### Q3. S2 地圖：線性的路線怎麼畫才不無聊

線性是定案。但線性有很多種畫法（垂直捲軸、水平推進、蛇形、單節點推進…）。

請針對**看得見的東西**提出：節點的視覺、路線的視覺、當前位置的表示、
已通關與未解鎖的差別、BOSS 節點的差別、玩家推進一格時的回饋動畫。

每一項給**時間／位移／對比的上下限**。對比類請直接給數值（例如亮度比或 alpha 區間），
不要寫「明顯一點」。

### Q4. S3 編隊：20 張 5:7 的卡要怎麼放進一個畫面

這是整個 2.0 最難的版面題，也是最可能做壞的。事實：

- 卡面幾何走 `card_face.js` 的凍結工法，**那個檔案不能動**，卡是 `aspect-ratio:5/7`
- 已有的版型模組 `CeremonyTable.layout(n,…)` 是為 **1／5／10 張**寫的
  （桌面最多兩排、`cw` 上限 208px、手機是「有間距的單卡瀏覽」）
- 20 張是它沒處理過的數量

請回答：

1. `CeremonyTable.layout` **該擴充成支援 20 張，還是編隊畫面要另一個版型模組？**
   如果擴充，`cw` 該掉到多少（給下限，低於多少就看不出是誰）；如果另寫，說它跟現有那個的關係。
2. 編隊時卡要用**完整卡面**還是**縮圖／頭像**？兩者的取捨是什麼？
   如果縮圖，縮到什麼程度玩家還認得出是哪張卡（給可量測的判準）。
3. 四條累加上限（神話≤2、+傳說≤6、+史詩≤12、總數≤20）**在畫面上怎麼呈現才不用讀說明**？
   使用者拖第 7 張傳說進去被擋下來的那一刻，他要怎麼知道為什麼。
4. 四個技能格跟 20 張卡的關係要怎麼在版面上表達（技能是從隊伍裡的卡來的嗎？這點還沒定，
   兩種都講）。

## 四、不准動的東西（提案碰到這些就直接不用提）

- 揭卡演出本身的特效、時序、分層契約（使用者已滿意）
- 「不預告品質」：`face-visible` 之前 common／rare／epic 必須逐像素零差
- 「無限等待點擊卡包」不得改成自動逾時
- 正式版 RATE 與初始 30 券
- `src/`、`card_face.js` 的凍結工法（卡面幾何、Z、字級）
- 不引入 npm 相依。產物必須是**單檔自包含的 HTML**（圖與腳本全內嵌）。
  WebGL 只在神話折射那一項被授權評估過，其餘一律 CSS／DOM／SVG。
