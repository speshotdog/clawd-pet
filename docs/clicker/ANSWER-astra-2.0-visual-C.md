**Q2．怎麼讓箔面精裝卡不像嵌入廣告**

**① 先修正成因判斷。規模：小；取決於：無。**

「平面 UI → 卡像廣告」不是必然關係。真正的問題是：**卡片自成一個精密、明亮、會動的視覺區域，但周邊沒有交代它為何在這裡、由誰承載、與哪個操作有關。**

原始碼可指出具體斷點：

- `card_face.js` 的 `material()` 建立 spectrum、relief、etch、fiber、grain、glare，卡面本來就有高密度材質；旁邊若只有一大片無關純色，密度會突然中斷。
- `HoloCardFace.paint()` 會依游標更新 `--gx`、`--gy`、`--phase` 等參數。**卡不是單一固定光源模型**；替 UI 畫一道固定斜光，不能保證互動時仍一致。
- 卡內已有框、寶石、文字背板和名稱；外面再套一個厚框、獨立標題與專屬亮底，就形成「框中還有一套系統」。
- 卡若一直掃光，其他控制靜止，它會持續搶走操作注意力。這與卡的面積是否落在 **35～50%**無關。
- 沒有選取標記、來源關係與裝備狀態時，玩家只看到展示品。**視覺接近不等於功能整合。**

因此，卡可以比 UI 精細、華麗；需要連續的是**承載與操作關係**，不是要求兩邊材質密度一樣。

**③ 並排圖怎麼拍、量什麼。規模：中；取決於：無。**

先固定量測分母：

- **詳情區 D：**預先標定、包含卡片、名稱、資訊與操作的完整區域；開關圖不可重新縮小它來湊比例。
- **卡片 K：**中立姿態下完整卡片的投影，不計承載槽、陰影與外光。
- **非卡片 UI：**可見面板及控制區域的面積聯集，不含地景、卡面與視窗空白；巢狀面板不重複計算。
- **接合區 R：**卡片外側 **8～24px**範圍內的槽板，排除文字。兩張圖使用完全相同的遮罩。

拍攝規則：

1. 以固定桌面、窄桌面與手機視窗分別拍攝，例如 1440×900、1024×768、390×844；不把手機圖縮成小縮圖判斷。
2. 同一隊伍、同一卡、同一尺寸、同一游標位置、同一動畫時刻。涵蓋可用稀有度，以及 `depth／flat／framed`；亮暗卡都要出現。
3. 左圖「關」：保留完整卡和功能，把承載、接合材質及共同選取標記關閉，空間仍保留。右圖「開」：只開啟上述項目。另交各項獨立開關圖，避免不知道哪一项產生差異。
4. 提供原尺寸全圖與接合區裁圖。靜止、游標偏左上、偏右下分別取樣；須等畫面確實重繪，不能設定狀態後立刻截到上一格。
5. 卡的大小、亮度、飽和度、文字及箔面參數不得為了右圖比較好看而改動。

**Q4．從 1.0 牛皮紙轉場到 C**

**保留遮幕換座標系，改掉「先見泛用土地與道路」。規模：中；取決於：無。**

陌生土地只能證明換場景，不能解釋為什麼來到這裡。C 首次入場應先交代：

**離開城市 → 回到熟悉卻被毀的後院 → 看見重新走過舊地點的路 → 新操作介面就位。**

這裡不能把城市直接形變成後院；兩者不是同一位置。遮幕下切換，揭幕先出後院的識別構圖與地名，讓玩家理解是「回到起點」。

| 階段 | 改法 | 提議驗收 |
|---|---|---|
| 收起舊控制 | 城市保留，周邊操作退場 | **140～180ms**；視窗位移 **8～12px** |
| 遮幕 | 舊舞台不放大，由 `#zoomer` 外的满版遮幕接手 | **160～200ms**；終點覆蓋率 **100～100%**、alpha **1～1** |
| 幕後換根容器 | 切至滿版 C 與已準備的後院地景 | **40～80ms**；舊 UI 穿透 **0～0%** |
| 揭出熟悉地標 | 先出後院構圖，不先出路線與大面板 | **220～280ms**；關鍵地標可見率 **90～100%** |
| 留出辨認畫面 | 地景與簡短地名維持，停止鏡頭運動 | **320～440ms**；非必要 UI 覆蓋 **0～5%** |
| 路線與操作就位 | 路線指向目前站點，工作盤自邊緣進場，避開識別地標 | **180～240ms**；位移 **6～10px** |

以上首入場按順序執行，總長目標 **1.06～1.42 秒**，不含載入。這是編排提案，**這需要實機量**，不能宣稱該停頓已足以讓玩家辨認。

回訪保留較短的 **0.70～0.92 秒**；不重播首次辨认停頓。減少動態模式採 **120～180ms**淡換、位移 **0～0px**，之後仍保留地標清楚的靜態版面。

並排驗收比較「舊提案的土地道路先出」與「地標先出」之同步分鏡。地標先出方案在該階段的地標可見率須 **90～100%**，玩家將新後院與舊後院正確配對須 **85～100%**。若仍不認得，先改地景識別與構圖，不能只延長黑幕。

**Q5．UI 與「1.0 廢墟」地景怎麼共處**

**採形狀對比、材質有限融合、位置主動避讓。規模：中；取決於：無，城市終段另取決於真身素材。**

對比與融合不是只能擇一。對玩家最重要的三件事，應分別處理：

- **操作輪廓與地景對比**：平直導軌、穩定文字和清楚按钮，讓玩家知道哪裡能操作。
- **承載材質與世界融合**：霧面、刮痕、氧化色可以呼應環境，但不让整張 UI 都像碎石。
- **地景識別靠構圖與物件保留**：這件事不能交給色票。

| 做法／規模／取決於 | 後果 | 驗收 |
|---|---|---|
| **先避讓地標／小／無** | 投資報酬率最高。面板靠邊，路線繞過識別核心；無須先增加材質。 | 指定地標輪廓遭 UI 遮住 **0～10%**；識別核心遭不透明面板遮住 **0～0%**。 |
| **控制輪廓保持對比／中／無** | 易讀、易點；若面板過大會像工具覆蓋插畫，因此須受面積限制。 | 主要控制輪廓對比 **3～6:1**；一般文字 **4.5～12:1**。 |
| **局部材質融合／中／無** | 卡、工作盤、地景較有共同物質感；全面磨損則會降低可讀性，也把 C 拉回拼貼。 | 有紋理 UI 面積 **12～22%**；功能文字被磨損遮掉 **0～0%**。 |
| **重畫可辨識地景／大／真身素材僅影響城市** | 情緒來源最強，但成本最高；不能用「都是貨架」取代「就是以前那組貨架」。 | 每個舊站指定 **2～3 個**識別物及相對位置；隱去地名的場景配對正確率 **85～100%**。 |

`clicker-scene.js` 已提供可用的構圖線索：後院樹在左、廚房層架與後櫃有相對位置、便利商店前後貨架錯開、夜市有攤架與燈籠、冰箱又是不同配置。這些可作重畫的構圖依據；**哪些細節最能喚起玩家記憶，仍需以舊畫面對照驗證**。

建議量測區間：

| 畫面 | 地景可見面積／可用畫面 | UI 覆蓋地景的面積／可用畫面 | 已標定識別物的可見面積／可用畫面 |
|---|---:|---:|---:|
| 首次地標揭示 | **80～95%** | **0～5%** | **18～30%** |
| 地圖常態 | **60～75%** | **10～20%** | **15～25%** |
| 一般戰 | **55～70%** | **15～25%** | **12～22%** |
| 王戰 | **50～65%** | **15～25%** | **10～18%** |

地景可見面積扣除不透明 UI 與角色遮蔽；「UI 覆蓋」另計透明面板與標記實際壓在地景上的區域，不讓透明黑板鑽漏洞。這些欄位不是相加等於全部畫面的分區表。

並排圖用同一新地景的「UI 關／UI 開」，另放對應的 1.0 原場景：

- UI 開啟後，場景配對正確率仍需 **85～100%**。
- 相較 UI 關閉，正確率下降 **0～10 個百分點**。
- 地標輪廓可見率 **90～100%**。
- 用名稱提示才認得、遮掉名稱就配錯，不能判定地景通過。

王②的粗白邊是護盾機制，必須保留可讀；不要為了材質融合把它磨掉。王③的節拍標記與王④的部位標記只在王關工作，一般關不鋪滿同類 UI。
