# 第二十九輪設計：配得上新卡面的抽卡演出（同一個概念，新的技術）

本輪保留滿版印刷箔面卡包，將「小卡展廳」改成「進入抽卡畫面、拆包、逐張取得大卡、收下」。演出的力量來自明確的落點、材質反應與收勢：玩家每翻出一張卡，都能看懂自己得到了什麼。

沿用 `_art/holo-test/deluxe-gacha-b.html`、`build_deluxe_b.py`、`ceremony.js`、`ceremony.css`。`HoloCardFace` 保持不變。以下為設計規格；本次未修改檔案，也未執行實作驗收。

**一、畫面流程與刪除範圍**

`入口 → 準備素材 → 滿版拆包 → 逐張揭曉 → 滿版結果 → 收下 → 入口`

入口只保留一包 `fx/foil-pack.webp`、卡池名稱、券數、單抽／五連／十連，以及次要的機率說明與音效控制。

- 1440×900：卡包 300×420px，中心 `(720,410)`，固定傾斜 −4°；抽卡鍵位於下方。
- 三個抽卡鍵寬 136／160／192px、高 56px，間隔 12px。十連以面積及實心奶油色建立主次。
- 券數使用一行小字；機率只在點開說明後呈現，不佔主視覺。
- 保留試抽、無保底設定；不更動 `pool_data.py`、`RATE` 或抽取結果。

按下後立即鎖定本次結果與抽數。入口按鍵下壓 80ms，銀白掃光 160ms；同步進入滿版抽卡狀態。素材未完成時沿用同一包，顯示「準備卡片…」，完成後才啟動時間軸，不交付空白卡。

新增 `setScreen('entry'|'ceremony'|'results')`。滿版生命週期由畫面狀態控制，不能再讓 `updateFinish()` 在可收下時移除滿版樣式。結果一直維持 `100vw × 100dvh`，直到按下收下。

具體刪除：

- `.win` 的懸浮視窗尺寸、18px 圓角、外框光暈及拖曳程式。
- `.bar` 展廳標題列、`.rail` 整條側欄、`.body` 左右分割。
- 假金幣 `.chip`、一般卡池停用鍵、尚未開放的典藏冊。
- `.rate` 主畫面機率列、`.foot` 固定玻璃底欄。
- `.orbit`、三道常駐圓環、`.charge`、`.core`、`.starfield`、舊 `.rays`。
- 卡背冒充卡包的 `.idlepack .veilback`。
- 「從軌道上取下你的卡」及「星軌召喚」文案。
- 正式畫面的重設鍵；測試重設留在 `__ceremony`。

保留 `#p1/#p5/#p10/#revealall/#finish/#sound` 的操作責任，換成新的視覺結構。收下後卡組以 220ms 縮至 0.96、下移 20px 並淡出，返回入口；不新增飛入不存在的典藏冊動畫。

**二、卡片尺寸與排版**

尺寸均指未變形的卡片 content box，比例固定 5:7。不能用 hover 後的 `getBoundingClientRect()` 當卡寬。

| 抽數／用途 | 1440×900 | 1024×640 | 390×844 |
|---|---:|---:|---:|
| 單抽 | 420×588px | 298.7×418.1px | 304×425.6px |
| 五抽，每張 | **380×532px** | **270.2×378.3px** | 主卡 288×403.2px |
| 十抽，每張 | 380×532px，兩組五張 | 270.2×378.3px，兩組五張 | 主卡 288×403.2px，逐張瀏覽 |
| 多抽揭曉焦點 | 420×588px | 298.7×418.1px | 304×425.6px |

桌面五卡扇形，以 `(W/2,H/2−12s)` 為中心，`s=min(W/1440,H/900)`：

- X 位移：`[-420,-210,0,210,420] × s`
- Y 位移：`[44,12,0,12,44] × s`
- Z 軸旋角：`[-12,-6,0,6,12]°`
- 1440px 下每卡寬占視窗 **26.39%**。
- 整組投影寬約 1322px，左右仍有約 59px 空間。

五張大卡允許重疊，閱讀由揭曉焦點與結果選取解決。結果時點擊卡片露出的區域，180ms 提到最前；固定扇形角度不隨游標改變。hover 僅 `scale:1.04`。鍵盤方向鍵可切換前景卡。

十抽採同一個大卡尺度，依序揭曉第一組五張、第二組五張。組間 320ms 水平交接，結果以「1–5／10」「6–10／10」兩頁瀏覽；不縮成十張小格。跳過後十張都完成，只是結果分頁顯示。

390px 直式不硬塞五張扇形：

- 主卡中心 `(195,398)`，旁卡中心偏移 ±224px、下移 18px、旋角 ±6°，只露出側緣。
- 使用單一水平卡帶；底部顯示 `目前張數 / 總張數`。
- 拖曳卡面仍是旋轉。切換卡片使用左右鍵、箭頭或底部分頁區，避免手勢衝突。
- 安全區納入 `env(safe-area-inset-*)`，卡名與操作列不得被裁切。

`layout()` 改成回傳 `{cw,x,y,rz,page}`；`position()` 只管外層位置。卡面仍由 `HoloCardFace.create/observe/refit/paint` 負責，保留原有幾何、Z、文字比例與箔面層。`flat/framed` 圖層按六之五採 6px，不回到舊文矛盾的 0px。

**三、背景：一張有箔材質的深藍舞台**

背景的幾何取自卡包封口的平行壓紋、折面與斜切邊。配置偏心、部分出框；中心保持安靜。

| 層／class | 外觀與混合 | 循環 |
|---|---|---|
| `.stage-base` | 純深藍 `#091221`，normal／1 | 靜止 |
| `.stage-substrate` | 箔底材貼圖，soft-light／0.12，飽和度烘焙至約15% | **靜止**，紋理不游動 |
| `.stage-geometry` | 左上斜切面、右下開口框；奶油色，normal／0.06 | 28s，`translate(0,0)→(12px,-8px)→(0,0)`，ease-in-out |
| `.stage-glow` | 卡後低飽和藍灰橢圓光，screen／0.08–0.12 | 12s，scale 0.98→1.03→0.98 |
| `.stage-sheen` | 一道寬而淡的方向性反光，soft-light／0.035 | 18s，斜向移動 48px 往返；無完整彩虹 |
| `.stage-vignette` | 四角壓暗，multiply／0.32 | 靜止 |

以 `fx/build_foil_pack.py` 的材質函式為依據，新增製作腳本 `fx/build_foil_stage.py`：

- 不加印刷圖，保留 metallic 1、roughness 0.28。
- Noise：scale 9、detail 6、roughness 0.62。
- Wave bands：scale 0.55、distortion 7、detail scale 1.5，方向旋轉 32°。
- 背景版 crinkle 降為 0.25，rainbow 混合降為 0.06；使用寬面積光，避免亮點。
- 正交輸出 1536×1024 RGB WebP，≤110KB。

這是相同材料的背景版本，不把卡包印刷放大鋪滿整個視窗。

循環只准 CSS `transform/opacity`；不動畫 noise、filter、background-position。揭曉持有焦點時，循環暫停並壓低亮度；分頁隱藏或 reduced-motion 時全部暫停。閒置 JS rAF 為零，不宣稱 CSS 動畫完全不消耗 GPU。

卡片始終是視覺最亮的實體。背景光效放在卡後，不用整頁白幕蓋住卡面；固定測試卡的灰階截圖中，卡外背景亮度 P95 應低於焦點卡 P95 的 65%，主波峰值放寬至 85%。

**四、揭曉：先讓卡面成立，再讓整個畫面回應**

舊版值得保留的是節奏原理：

- `ring()` 快速擴張、逐漸減速，同時變薄消退，形成明確衝擊。
- wish 撞擊以 600ms 大環、400ms 內環與約 70 顆粒子分出主次。
- 傳說有近卡環、外射火星、慢餘燼；神話 `rainbowRing` 與間隔 120ms 的第二次衝擊提供第二拍。
- `ctx.cards.deal()` 使用共同出發點、錯峰與回彈，卡有來源、有重量。

舊程式包含神話提前預告，本輪不採用。舊 `.mythic-ripple` 的 class 名稱也不能直接當成成功效果的證據。新演出以實際畫面與時序驗收。

**共用拆包時間軸**

以素材就緒後為 `P=0`，所有結果完全相同：

| 時間 | 動作 |
|---|---|
| 0–240ms | 入口卡包連續移至舞台中心並轉正；操作列退出 |
| 240–440ms | 封口承受張力：包身下沉 5px、壓縮至 0.985 |
| 440–780ms | 上封條向右上剝離，顯露既有 `foil-tear.webp`；播放中立撕膜音 |
| 680ms 起 | 卡背由封口下方抽出，與撕封末段重疊 100ms |
| 每張 480ms | 沿弧線到扇形槽位；五張 stagger 70ms；終點超出 8px，再收回 |
| 最後一張落定後 | 啟動第一張揭曉；包身已淡出，材質背景保留 |

移除召喚陣、流星投遞及印章。拆包動作本身就提供期待感。

**共用單卡鏈**

新增 `beginReveal()`、`commitFaceVisible()`、`runRarityFx()`、`settleReveal()`，由既有 `revealOne()` 管理同一 Promise。

以真正第一個正面可見幀為 `F=0`：

- `F−320～−180ms`：卡背從槽位移往中央，同步轉正；全部階級一致。
- `F−180～0ms`：外層 `.reveal-flip` 翻至側面；不發環、不改階級色、不播階級音。
- `F=0`：正面開始有可見投影才記錄 `face-visible`。不能只設 `visibility:visible`，在仍完全側面時提前打 marker。
- `F～180ms`：完成後半翻面；外層抵達焦點尺寸。
- `F+180～260ms`：2% 尺度餘勢收至 1，位置收回 4px。內部卡面角度不參與。
- 普通／精良／史詩／傳說／神話分別於 `F+300/420/640/900/1200ms` 開始回槽。
- 回槽分別 220／240／280／320／360ms，`cubic-bezier(.4,0,.2,1)`。

普通、精良的回槽最後 100ms，可以與下一張的中立移入重疊；下一張尚未露面。史詩以上完整回槽、特效與聲尾結束才釋放焦點。排程只依**已揭曉前卡**決定等待，不能讀取下一張階級預先延長停頓。

共用外擴曲線為 `easeOutCubic`，亮度 24ms 內抵達峰值再衰減；所有下列事件均在 `F` 或之後。

| 階級 | 元素、時序、空間與聲音 | 告訴玩家什麼 |
|---|---|---|
| 普通 | `0–180ms` `.fx-confirm-ring`，卡後銀白細環，直徑 0.88→1.25 卡寬，線寬 2→1px | 這張已確實取得 |
|  | `0–220ms` `sweep()`，沿卡面既有箔層掃過一次，不另蓋白片 | 這是實際卡片材質 |

**技術裁決**

第29輪完整交付 CSS／WAAPI 版本。`.fx-substrate-wave` 以靜態箔底材、環形遮罩及縮放呈現；`sweep()` 仍呼叫 `HoloCardFace.paint(...,{tilt:false})`，時間軸與 pointer 嚴格交接單一 writer。

第30輪只在「神話波穿過皺摺時需要真正折射位移」這一項使用單一 WebGL／three.js canvas：

- 僅渲染背景底材，使用法線貼圖改變環帶中的 UV 與光譜偏移。
- 不擷取、不重建 DOM 卡面，不做神話影片。
- 僅在 `F+60～1040ms` render；結束立即停止。
- 初始化失敗或 context lost，250ms 內回到同時間進度的 CSS 雙環；不重播、不換卡、不重設完成狀態。

這修正第28輪「所有舞台效果全面 three.js 化」及「神話影片提前120ms開始」的提案，遵從本輪最新裁決。

**五、去除 AI 感：每一項 UI 的替換**

舊 UI 的手作感來自厚邊、按壓位移、材質接縫與有理由的不對稱。此產品把這些原理轉譯成卡包的深藍印刷、奶油色標籤與封口壓紋。

| 現有元素 | 本輪替換 |
|---|---|
| 玻璃懸浮視窗 `.win` | 無外框滿版底材，空間直接服務卡包與卡片 |
| 展廳標題 `.bar b` | 左上小型奶油色卡池名；系統明體標題，操作文字維持清楚黑體 |
| 金幣／券數膠囊 `.chip` | 刪除假金幣；券數改普通文字，無圓膠囊 |
| 側欄卡池與典藏冊 | 刪除；入口只做已存在的精裝卡池 |
| `.rate` 英雄機率列 | 次要「機率說明」文字鍵，打開實色說明區 |
| `.foot` 等寬按鈕排 | 三個不同寬度的厚印刷按鍵，2px 深色邊、3px 底厚度、4px 圓角 |
| 粉紫青漸層主 CTA | 奶油色 `#eadfc4` 配深藍字；按下 80ms 下沉 2px |
| 音效／跳過／收下 | 上角簡潔音效與跳過；收下固定下方，奶油色實心鍵 |
| `.orbit` 同心圓、星點 | 偏心斜切幾何、箔底材與緩慢方向光 |
| `.idlepack` 卡背 | 使用真正的滿版 `foil-pack.webp` |
| 召喚陣／印章／投遞光線 | 封口張力、剝離與卡片出包 |
| 整齊小卡格 | 大卡扇形／直式卡帶 |
| 均勻放射 `.reveal-rays` | 有明確起點、方向、衰減的材質環與箔片 |
| `.result-mark` Unicode 圖示＋重複階級文字 | 刪除；使用卡面既有階級資訊，卡外只留張數 |
| 長篇常駐 `.hint` | 演出時「點空白處跳過」；結果時簡短互動提示 |
| 正式重設键 | 移入測試介面 |

不對稱使用固定構圖值，不每次隨機歪斜。按鈕文字保持水平；質感由材料與厚度提供。普通控制項沒有常駐彩虹、跑馬框、玻璃模糊或呼吸光。UI 混色限制在元件內，效果層一律 `pointer-events:none`。

**六、輪次與可驗收契約**

第29輪必須交付完整的入口、拆包、大卡、五階回饋、结果與收下。不能只改背景，將普通卡回饋或手機排版留到下一輪。

建議新增 `_art/holo-test/check_ceremony_round29.py`，擴充現有 `__ceremony` 的固定時間取樣、工作計數與事件紀錄。

| 驗收 | 可斷言條件 |
|---|---|
| 不預告零差異 | 固定 viewport、視覺 seed、載入完成與時間軸；五階 fixture 在所有 `t < face-visible` 取樣，整畫面像素差異為 **0**；聲音事件亦一致 |
| 後續卡不洩漏 | 固定已揭曉前綴，只替換下一張階級；下一張露面前畫面及啟動時間相同 |
| 真正露面 | marker 對齊第一個正面像素幀；不接受側面零投影時僅 DOM visibility 改變 |
| FX 時序 | 每個 `fx-start/end` 含 run、index、effect；起點不早於 F，與表定時間誤差 ≤34ms；主撞擊音與 F 差 ≤50ms |
| FX 確實可見 | 各效果峰值截圖需在指定卡外區域產生像素差；不能只驗 class 存在 |
| 焦點與定位 | 高階焦點最多一張；光源中心距焦點卡中心 ≤卡寬5%；resize 後仍成立 |
| 卡片尺寸 | 三種 viewport、1／5／10抽均符合尺寸表 ±1px；量 content width，另驗投影安全區 |
| 卡面凍結 | 三型、原有80／102／150／230／290px與新增大尺寸回歸；文字用 Range；Z、mask、palette 不變 |
| 拖曳像素 | drag→放開→移開後 `selection.rangeCount=0`，選取藍色污染像素比 ≤0.01；使用基準圖排除原畫藍色 |
| 互動分工 | hover 僅1.04倍；無拖曳時角度固定；拖曳角度上限±18°，放開保留，雙擊／Esc回正；圖內位移維持0 |
| 閒置 | 可見靜置5／30秒，背景 JS rAF、render、timer增量為0；允許指定CSS循環，不允许定時DOM寫入 |
| 隱藏 | 觸發背景分頁後，CSS動畫paused；前景演出亦暫停，無輪詢或音效續播；恢復不爆量補播 |
| 完成 | 全部 `complete`，cascade退出，演出 anims／timers／rafs／voices為0才顯示收下；結果維持滿版 |
| 跳過 | 準備、撕封、發牌、F前後、回槽、換組各20次；身份、順序、數量不變，每卡只完成一次 |
| 跳過速度 | 素材就緒時180ms結果淡入；清理後100ms內可收下；舊回呼不得再写入 |
| reduced-motion | 直接180ms淡入完整結果；不啟動撕封、波紋、震動或WebGL |
| 可攜性 | dev與搬到其他資料夾的standalone都驗，離線、無CDN、無遺漏相對圖片 |

保留 `generation`、`revealed`、`complete`、`cancelWork()`、`skipAll()` 的 A5 語意。背景循環由獨立 `backgroundScope` 管理，不混入「尚未完成的演出工作」計數；`cancelWork()` 改為清理當抽所擁有的工作，避免目前全域取消動畫一併殺掉背景。

第30輪僅做神話折射與調音，加入 context loss、渲染停止及20抽資源不累增測試。桌機 frame interval P95目標≤20ms，實機手機≤34ms；viewport模擬不等於手機GPU驗證。
