### 1. 卡冊翻頁／點開卡面「破圖」（最大的一條）
現象：卡圖本體放大到約 2.7 倍從卡框溢出、名字跟稀有度擠成一行、其他卡被蓋住。
四種環境（本機無頭、線上無頭、真 Chrome 有頭、125% 縮放）在 400ms 後量都正常——

### B3. 黑角測試的負控制 `tools/test/clicker-v3-black-corner.py`

### B4. 收藏卡 16 顆愛心不動（追加項）

#### 真兇與對照實驗

不是只有 pointermove 太多。這次找到三個不同問題：

1. **額外的 700ms CSS 旋轉過渡讓畫面追趕舊角度。** `holo-special.css` 的 `.r-special .card-lift` 還在套獨立頁過渡，這裡沒有 `gift-following`。固定送出 X=-6°／Y=12°，兩個 rAF 後，原版可見矩陣與目標的最大元素差為 0.1947（對照卡約 0.00000046）；放手 350ms 後仍有 0.0651 的回正誤差。只關過渡就能消除追蹤／回正誤差，但手機 6× p95 仍為 83.4ms，不能把「跟手」與「幀率」混為一談。
2. **共用路徑每格改整棵卡面繼承的 CSS 變數。** 原版每次拖曳呼叫完整 `HoloCardFace.paint()` 60 次，之後又在 `.hcard` 寫 `--rx/--ry`。只跳過完整 paint、仍寫角度變數，手機 6× p95 83.3ms；改為直接更新 `.card-lift.style.transform` 並固定拖曳中的反光，降到 33.3ms，整頁 trace Paint 從 1,318 次降到 90 次。一般 2.0 卡也受益，不能只改收藏卡加工。
3. **大尺寸放大層的半透明背景讓後方動畫卡仍參與合成，愛心即使暫停仍有繪製成本。** 直接 transform 後，桌機 6× 放大卡仍有 66.6ms。只隱藏後方卡面的診斷組降到 33.3ms；背景不透明、再加全頁愛心暫停，各自曾單次通過 33.4／33.2ms，但完整批次仍曾有 50.0ms，不能只挑單次通過。最後再讓**前景愛心暫時 visibility:hidden**，同時保留其動畫進度，單組 p50 16.7ms、p95 16.8ms。正式保留的組合是：反光固定＋直接 transform、不透明放大背景、全頁收藏卡愛心暫停、前景愛心暫時隱藏。回正後全部自動恢復；主圖、文字、材質、遮罩、大小不改。實測放大頁的 64 個 CSS 動畫在拖曳時全暫停，回正後暫停數為 0。
