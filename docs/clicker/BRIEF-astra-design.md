# 點擊放置遊戲（暫名「珍母點點」）─ 給 GPT-6 Astra 的設計簡報（只設計，不改檔）

這是 ClawdPet（Tauri 2 桌面寵物，`D:\claude研究\clawd-pet`）的第二個試作區。第一個試作區是抽卡（`src/gacha*.js`，看 `docs/gacha/DESIGN-astra-round1.md` 與 `src/gacha-mode-runtime.js`），現在要做一個**獨立的新視窗**放「點餅乾」類型的遊戲，抽卡系統作為它的模組被套用。**兩個區域分開**：抽卡視窗是純演示／體驗，點擊遊戲視窗是完整遊戲；兩者共用卡池、卡面元件、演出模式與音效積木，但存檔分開。

## 使用者的概念原文
> 主畫面是珍母，點擊他會讓增加錢幣。錢幣可以強化點擊的傷害，或是拿去抽角色。角色有特殊能力，與被動的持續基本傷害（玩家不用手點）。

## 素材與限制
- 角色：12 隻（`src/pet.js` 的 `CHAR_CFG`、`src/index.html` 的 `<template>`），都是厚描邊平塗貼紙風小動物，有 rig（腿／手／尾巴／眨眼）。珍母＝白色圓頂水母（`zhenmu`），會「寄生」別人（見 `PARASITE-V2.md`）。玩具三個、emoji 兩個。
- 不能畫新圖；需要的 UI 用 CSS／SVG／canvas。
- 純前端 classic script，Tauri 視窗，localStorage 存檔。閒置時零 rAF（放置收益用時間戳結算，不用每幀跑）。
- 抽卡模組的介面：`rollPack()` 產生 draw、`GachaModes[name].create(ctx).open(draw)` 演出、收下時落帳。這個遊戲要能呼叫它，但幣種、卡池權重、保底由遊戲決定。

## 請產出設計文件（繁體中文，具體到數值）

### 一、核心循環與數值
- 點擊 → 錢幣：珍母的點擊回饋（擠壓、觸手抖、數字彈出、連點加速？暴擊？）。
- 錢幣用途：升級點擊傷害（費用曲線公式、成長倍率）、抽角色（單抽／五連價格、與抽卡模組的 pity 如何接）。
- 角色＝被動收益（每秒錢幣）＋主動技能（各角色一個，冷卻制或條件觸發）。請替 12 隻各寫一個符合人設的技能（例：珍母寄生＝暫時複製一隻角色的收益；膠布拿刀＝下一次點擊 ×10；玥玥＝…）。重複抽到＝升星（收益倍率），對應現在的「塵」要不要保留。
- 「傷害」打在誰身上？請提議目標物（例：一顆會裂開的巨型熱狗／怪物列／關卡進度條），讓數字有意義，並給前 30 分鐘與前 7 天的成長曲線草稿（每段時間玩家看到什麼新東西）。
- 離線收益、prestige（重置換永久加成）要不要做，第一版做到哪。

### 二、畫面與互動
- 視窗尺寸（建議 ≤ 960×640，和抽卡一致）、版面分區（主舞台珍母／角色列／商店／抽卡入口／統計）。
- 珍母在中央的狀態機：閒置、被點、連點、技能中；用 rig 做的動作清單。
- 抽到的角色怎麼出現在畫面上（站在珍母旁邊排隊？走來走去？），上限幾隻可見。
- 抽卡入口：按下去是在本視窗內演出（沿用 `GachaModes`），還是跳去抽卡視窗？建議做法與理由。
- 每個回饋都要有重量：點擊、升級、技能發動、抽到新角色、里程碑，各一個聲音與一個動作，不要堆。

### 三、架構
- 檔案安排（`src/clicker.html / clicker.js / clicker-*.js`），與抽卡共用哪些檔（`gacha-card.js`、`gacha-audio.js`、`gacha-fx.js`、`gacha-mode-*.js`）、共用時要抽出哪些介面（例：卡池與 rollPack 要從 `gacha.js` 搬到 `gacha-pool.js`）。
- 存檔結構（版本化、離線結算時間戳、防呆）。
- Rust 端：新視窗 label `clicker`，比照 `show_gacha_window`；右鍵選單入口。
- 效能：放置收益的結算節奏、數字顯示的節流、可見角色的動畫預算。

### 四、分期
第一版（可玩的最小循環）、第二版、第三版各含哪些；每期估工時。
