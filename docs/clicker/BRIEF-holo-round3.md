## 二、四件事

### 1. 珍珍JPG 的透明格子底 —— 保留，不要修

那是卡本身的美術梗（卡名就叫 JPG）。**不要當成破圖去修掉**。
唯一可以做的是讓格子在滿版背景上仍然讀得出是「梗」而不是「破圖」
（例如格子那層不吃背景的景深位移，或在合成時留一圈底），但**不要把格子拿掉**。

### 2. 修暈邊

指的是**第一輪那四張 GrabCut 場景卡**（`layer-{rocketdog,astronaut,alienkitty,fluffdog}-*`）。
主體從場景切出來時邊緣有殘留光暈／拉抹，大角度、高景深時特別明顯。
第二輪那 10 張合成卡沒這問題（角色本來就有乾淨 alpha），**不要動那批**。

修的方向自己判斷，可考慮：alpha matting 取代硬邊 GrabCut、
邊緣去色溢（decontaminate，把背景色從半透明邊緣像素裡扣掉）、
背景補底改用更大範圍的取樣、或主體邊緣往內收一兩像素再羽化。
**修完要並排截圖 before/after 證明有改善**，不要只說改了。

### 3. 階級的寶石擋到名字 —— 版面 bug

使用者截圖：菱形寶石壓在名字帶上，跟「滅世珍獸」「玩物就玩物」的字疊在一起。
**四個字的名字就會撞到**，所以不是特例是常態。

要求：
- 寶石與名字**任何情況都不重疊**（含最長的卡名）。
- 名字**不准縮到看不清楚**來閃避寶石；優先改版面（寶石移位／銘牌加高／名字讓出安全區）。
- 寶石仍要是「一眼看出階級」的元素，不要為了閃避就縮到看不見。
- 做一個**排版驗證**：對所有卡（含最長名）量寶石與名字的矩形，斷言不相交。
  本專案第十九輪做過同類驗證（技能名字矩形不相交），照那個做法。

### 4. 懸浮文字 ＋ 字體設計（本輪重點）

> 「文字是不是也可以懸浮? 更有感」

**4a. 懸浮**：名字／稀有度／銘牌要有自己的 Z 深度，跟角色、背景分開，
隨視角有自己的視差。但**可讀性優先**——文字是資訊，
角度大的時候不能糊掉、不能被箔面蓋掉、不能跟背景撞色到讀不出來。
參考自己在 `DESIGN-holo-cards.md` 寫的「保護印刷文字」那條。

**4b. 字體設計**：使用者要你**思考並提案**，不是隨便挑一個。要處理的：

- 目前是什麼字體？（大概是系統預設）為什麼它撐不起「精美卡牌」的感覺。
- 提**2～3 個方向**並在展示頁做出來讓使用者看，例如：
  襯線／黑體／圓體的差異、字重、字距、中文與英文稀有度標的搭配、
  數字與星等的對齊。
- ⚠ **授權與載入是硬限制**：
  - `demo.html` 必須 `file://` 開得起來，**不能連 Google Fonts、不能用 CDN、不能 fetch**。
  - 所以要嘛用系統字（Windows 上的正黑體等，但別的機器不一定有），
    要嘛**把開放授權字體子集化後內嵌成 data URL**。
    中文字體很大，但**卡名用到的字只有幾十個**，子集化後通常只有幾 KB —— 這條路可行。
  - 選字體**只能用明確開放授權的**（例如 SIL OFL），**要實際去讀授權原文**，
    不要看到「免費」就用。授權結論寫進 README。
  - 不要用生成式 AI 產字。

**4c. 字體因顏色改變**：使用者提的想法是「說不定字體也可以因顏色改變」。
你要判斷並提案這是什麼意思比較合理，並做出來讓他看，可能的解讀：
- 依稀有度換字重／字距／描邊（低階樸素、神話厚重）
- 文字本身吃箔面（字是金屬色、隨角度流光），但**必須保住可讀性**
- 依卡面主色自動決定文字顏色與描邊（避免撞色）
**不要三個都做一半**，選你認為最好的做完整，其餘在 README 說明為什麼沒選。
