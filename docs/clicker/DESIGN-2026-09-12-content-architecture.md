## 一、獨立技能格：拖進去之後發生什麼

### 1.1 行為【定案】

- 四格是**按鈕**，跟 1.0 舞台旁的技能槽同型：按了發動、進冷卻、冷卻中 `disabled`。
- 拖進格子＝**裝備**，不消耗任何東西、隨時可換；換掉時若原技能在冷卻，冷卻**不清**（同 1.0 `slotReadyAt` 綁格子的做法，防止換卡刷 CD）。
- 連鎖窗沿用 1.0：任一技能發動後 8 秒內發動第二個 ×1.3、第三個 ×1.6。
  【假設】末世天生四格，所以第四個吃 ×1.9（1.0 印記商店「第四技能槽」那條的數字）。
- 神話 ≤1 的硬限制**在 `assignSkill()` 已實作**（`team20.js:51`），拖曳與挑選器共用同一入口，不動。
- 拖進格子的卡必須在 20 人隊伍裡（現況：拖曳來源就是隊伍網格，挑選器也只列隊伍）。
  【假設】卡從隊伍移除時，它佔的技能格一併清空。

### 1.2 效果從哪裡來【定案 #12】

**每張精裝卡有一個末世專屬技能，全部重新設計**，資料放新表（見第六節），
**不讀 `clicker-balance.js`**，也不沿用 1.0 的 click／clickAdd／burst／self／team／passive 六型別當骨架。
骨架改成四階分工（`DESIGN-team-and-map.md` §三、§7-2）：

| 階級 | 技能做什麼 | 設計語言 |
|---|---|---|
| 神話 | 改寫規則的一次性大招 | 一場（一關）一次；無視／逆轉某條規則，例如「直接打穿王的護盾」「本關剩餘血量減半」 |
| 傳說 | 整場持續加成 | 發動後整關生效或長時效；撐骨幹，例如「本關點擊 ×1.8」 |
| 史詩 | 應對特定狀況 | 反制王關機制：清召喚小怪、擋一次時限、補一拍節奏 |
| 精良 | 資源與穩定度 | 回復、CD 縮減、容錯：「其他三格 CD −30%」「下次連鎖窗 +4 秒」 |

1.0 的技能只留**風味**（玥玥還是點擊系、珍母還是寄生／複製系），數值與型別全部重寫。

流派層（§7-2）：特定組合要能形成「爆發單點」「經濟」「持續傷害突增」三種以上玩法風格，
但**在同一個指標上不能贏過 1/1/1/1**——這條是模擬器的驗收項，不是設計時手算的。

### 1.3 數值預算【定案 #4】

四階「第一張」的價值 100／85／72／60，同階第 n 張乘 0.55^(n−1)。
驗算：傳說第二張 85×0.55＝46.75 < 精良第一張 60 ✅；史詩第二張 39.6 < 60 ✅。
所以「把第四格拿去補一個還沒有的階級」永遠比疊同階划算，1/1/1/1 是唯一最大值。

「價值」是**預算單位**，不是一個顯示給玩家的數字：設計每個技能時把它的
（效果量 × 覆蓋時間 ÷ 冷卻）折成這個尺度，落在該階級預算 ±10% 內。
【待模擬】折算公式本身要在模擬器裡驗（讓模擬器自己組隊互打，量 §五那六條）。

同階不同卡之間允許有差（不然全部同階的卡都一樣就沒有選擇），
但**同階最強與最弱差距 ≤15%**【假設】，否則遞減係數保不住天花板。

### 1.4 升星對技能的影響【假設，照 1.0 §2.5 的形狀】

主軸／副軸各一條、按 (★−1) 線性、全型別 CD −3%／星；5★ 合計約 +30% 效果、+12% 頻率。
（超越第一版不做，見 §四。）
**5★ 傳說技能約新卡 1.3 倍**——這個倍數要進模擬器，天花板規則必須在「滿養」下仍成立。

### 1.5 跟 1.0 系統怎麼疊【定案 #3：不疊】

- 印記倍率 `1+.5×√印記`：**不作用於末世**。
- `bossDamage` 的 share（滅世光線 .22／飛沫月月 .08）：那是 1.0 王包的規則，末世王另有一套（`DESIGN-team-and-map.md` §7-3 的 gimmick 制），**不沿用**。
- 1.0 的訓練、升星、超越、羈絆、當家：**全部不作用**。同一隻角色的精裝版在末世從 1★、Lv.0、階級＝原生稀有度、超越 0 開始。

好處：末世的平衡是一張白紙，模擬器不用背 1.0 的印記曲線；
代價：「我 1.0 養到超越五的珍母，進末世是新人」——這要在進末世的第一個畫面講清楚（一句話即可，別做教學關）。

## 二、隊員的被動收益【定案 #2】

- 隊伍 20 張（含技能格四張）每張按稀有度給**末世金幣／秒**，只有在隊伍裡的才算，卡冊裡沒編入的不算。
- 基礎值【待模擬】：形狀照 1.0（精良 4／史詩 8／傳說 16／神話 ?），尺度用「進末世 5 分鐘內抽得起第一張券（1000）」反推。
- 升星 ×2.0（5★）；**沒有升階**；訓練每級 +1 倍（線性，同 1.0）。
- 點擊：一下的傷害／收益 = 手勁 × (Σ 隊員 pᵢ 的一個比例)【假設，1.0 是 `D + Σ clickAdd`】。手勁在末世用末世金幣升，公式形狀照 1.0 `10×1.35^L`，尺度待模擬。

| 十連 | 10 券，**不折** |

### 3.2 抽率【定案 #8】

| 階級 | 率 | 期望抽數 |
|---|---:|---:|
| 神話 | 0.25% | 400 抽＝40 萬末世幣 |
| 傳說 | 4% | 25 |
| 史詩 | 20% | 5 |
| 精良 | 75.75% | — |

⚠ 無保底＋0.25%：**10% 的玩家要抽超過 920 抽才見第一張神話**（幾何分布 0.9 分位）。
【待模擬】長尾體感要跑過；如果太慘，調的是**神話卡的數量**（池子裡神話少，每張的單卡率就高）或末世金幣的產速，**不是加保底**（保底已定案不做）。

每階內各卡等分【假設】。

### 3.3 舊金幣換券【定案 #10】

「舊區一包的時間換一張券」，寫成式子：

```
1 券的舊金幣價 = 玩家當下在 1.0 所在場景的「一包需求」（幣）
             = 當下每秒收益 × 拆一包要花的秒數
```

也就是**用舊區的錢買一張券，價格等於你在舊區現在拆一包的代價**——舊區越強換越貴，
不會出現「舊區存款一次灌空末世卡池」。
【假設】以玩家**當前場景**（第七站滅世都市）的需求算，不是最低場景；
【假設】不設每日上限（價格本身會隨舊區進度水漲船高，已有節制效果）；
【假設】換券是單向的，末世金幣不能換回舊金幣。

### 3.4 普發月月【定案 #11】

- 精良；進末世**累計**點 50 下送一次【假設：累計，不是單場】；
- 也在券池裡，抽到重複照 3.5 升星；
- 【假設】計入卡冊完成度、走裝幀典藏演出（同一般精裝抽卡的單張揭曉）。
- 素材未到（先前紀錄）；架構上它跟其他精良卡沒有任何特殊欄位。

## 四、養成：末世自己的一套【定案 #5、#6，追問後縮成兩條線】

**完全鏡射 1.0 的形狀，但資料、貨幣全部是末世自己的；而且沒有升階。**
使用者原話：「末世的卡片只能升星、不能提升階級，不然編隊系統會很麻煩」——
升階會把一張精良變史詩，前綴上限 2／6／12／20 就得跟著重算，隊伍可能突然違規。

| 線 | 來源 | 公式（形狀照 1.0，尺度待模擬） |
|---|---|---|
| 升星 | 重複卡直接升【定案】 | 【假設】門檻同 1.0：累計 16 張重複＝5★（內部仍用「顆數」存，顯示叫張數） |
| 訓練 | 末世金幣 | `200×base×1.15^L`，10/25/50/100/150/200 級 ×2、上限 200（1.0 數值定案 v2） |
| ~~升階~~ | — | **不做** |
| 超越 | 末世粉塵（5★ 之後的重複卡） | **要做，但不改稀有度**（追問定案：「精良就是精良、傳說就是傳說」）。每級被動 +N%、技能 +5%、CD −2%，N 看出身（精良 +6／史詩 +9／傳說 +14／神話【假設】+14），顆數照 1.0 §3.2 |

- 末世粉塵只有一個去處：超越。5★ 之後的重複卡→該角色末世粉塵；超越五之後的重複【假設】折末世金幣（精良 200／史詩 500／傳說 2000／神話 5000）。
- 精裝專屬新角色與舊角色精裝版**沒有任何養成上的差別**。
- 卡的稀有度在末世是**永久不變**的，編隊的前綴上限因此可以在拖曳當下一次算完，不需要「養成後重驗隊伍」。

## 五、末世卡冊【定案 #13、#14、#15】

## 六、存檔【假設，全部】

`clicker-save.js` 的 `REPAIRS` 表與 `repair()` **不動**。末世狀態放同一份 `clicker_save` 底下一個新子樹，匯出／匯入自然一起搬：

```js
apoc: {
  unlocked: false,          // 打完滅世珍獸時翻 true（economy.finishBoss 那三處）
  coins: 0, lifetime: 0,    // 末世金幣
  tickets: 0,
  clicks: 0,                // 普發月月的累計 50 下
  giftGiven: false,
  collection: {},           // id → 累計張數（含專屬新角色）
  training: {}, dust: {}, transcend: {},   // 沒有 promotions（不升階）
  roster: [],               // ≤20，前綴上限在 team20 的 violations() 驗
  skills: [null,null,null,null],
  slotReadyAt: [0,0,0,0], chain: {count:0, expiresAt:0},
  grip: 0,                  // 手勁
  map: { stage: 0, bossCooldownUntil: 0, cleared: [] },
  pity: null                // 刻意沒有
}
```

- `validate()` 對缺 `apoc` 的舊存檔補預設，**不進 REPAIRS**；末世自己的修復規則另開 `APOC_REPAIRS`，只在 `apoc` 子樹上跑，失敗最多把 `apoc` 整個重置，**不碰 1.0 的任何欄位**。
- `roster`／`skills` 的合法性（前綴上限、神話 ≤1、卡必須擁有）在 `validate` 裡 check，壞掉就清空那一項，不清整個 `apoc`。

## 七、併回 main【定案 #16】

**等末世第一張圖能玩才併。** 「能玩」的定義【假設，請確認】：

1. 1.0 打完滅世珍獸 → 出現末世入口
2. 進末世 → 點 50 下送普發月月（裝幀典藏演出）
3. 末世金幣累積 → 買券 → 抽卡（單抽／五連／十連，率照 3.2）
4. 編隊（20 張上限）→ 拖卡到技能格 → 技能能按、有 CD、連鎖窗生效
5. 第一張圖的一般關卡能拆包推進，**第一個王關**（含一種 gimmick）打得贏也打得輸、輸了 3 分鐘冷卻
6. 卡冊能看、剪影、展示頁三顆鍵能用
7. 存檔能關掉重開、匯出匯入不壞 1.0

在那之前 `holo-5.0` 繼續當研發線，接線工作直接在這條分支的 `src/` 做；
main 的 exe／gh-pages 不受影響。到時候**再單獨問一次**才動 main。

## 十、1.0 印記系統重設計（2026-09-12 追加，使用者：「之前太好取得、戰力膨脹、新版要更嚴格」）

### 10.1 現況診斷（以程式為準，不是憑印象）

| 條目 | 現行（`clicker-prestige.js`／`clicker-economy.js`） | 上限 |
|---|---|---|
| 印記產出 | `floor(√(生涯幣 ÷ 1e8)) − 已領` | **無** |
| 永久倍率 | `markMul = 1 + .5×√已領印記` | **無** |
| 收益祝福 | `blessMul = 1 + .1×Lv`，第 L 級收 L 枚 | **無** |
| 招募券 | 2 印記 → 5 次免費單抽 | **無**（可把整個卡池抽滿養滿） |
| 粉塵兌換 | 第 n 次 n 印記（已改遞增） | 每輪自然封頂 ✅ |

使用者截圖：收益祝福 **Lv.1462（×147.20）**。反推：祝福共花 Σ1..1462 ≈ **107 萬枚**印記 →
生涯幣 ≥ (1.07e6)²×1e8 ≈ **1.1×10²⁰**；同時 `markMul = 1+.5×√1.07e6 ≈ ×518`。
兩條相乘 **≈ ×76,000**。1.0 的王血量只跟包需求走（最高第七站 ×12000），所以所有王都是秒殺。

**根因不是係數，是形狀**：印記的產出是「幣」的函數，而印記買的東西又乘在「幣」上，
兩條無上限的倍率互相餵。第二十三輪把線性改成開根號、第二十四輪把粉塵兌換改遞增價，
都是「形狀不改、係數延後」的同一個教訓（程式註解自己也寫了）。

### 10.2 新版原則（三條，缺一條就會再膨脹一次）

1. **印記的產出不能是幣的函數。** 改成**事件計數**：每次輪迴結算時，數「本輪做到的事」
   （首次到達第 k 場景、打贏第 k 個王、本輪包數里程碑），不看生涯幣。
2. **每一項印記買得到的東西都要有上限**，總印記需求是一個算得出來的常數。
3. **兩條倍率只留一條。** `markMul`（自動隨印記數成長）拿掉，只留「收益祝福」這種要花印記買、有頂的。

1.0 的定位現在也變了：它是通往末世的**前段**，不是無限長的放置遊戲。
1.0 需要的只是「讓玩家在合理時間內打到滅世珍獸」，之後的成長歸末世。所以 1.0 的印記可以是**有限的**。

### 10.3 建議形狀（數字是建議值，要跑 `tools/sim/clicker-curve.js` 加輪迴策略再定）

| 項目 | 建議 |
|---|---|
| 每輪印記 | 本輪打贏的王 每隻 1 枚（最多 7）＋ 本輪首次拆滿 100／300 包各 1 枚 ＋ 本輪打贏滅世珍獸再 +3 → **每輪最多 12 枚** |
| 收益祝福 | 每級 +10% 不變，**上限 Lv.20（×3.0）**，第 L 級收 L 枚 → 全滿 210 枚 |
| `markMul` | **拿掉**（保留欄位、係數設 0，存檔不動） |
| 招募券 | **拿掉**（追問定案） |
| 商店六項 | 不變（15 枚），本來就是一次性 |
| 生涯總需求 | 210＋15 ＝ 225 枚，每輪最多 12 ≈ **約 19 輪全滿**；輪迴的「桌子滿了」提示照舊 |

驗收（模擬器）：從零到打贏滅世珍獸的真人時數；全滿 20 輪之後的倍率恰好 ×3.0，
第七站王在「連點＋技能」下仍要 30 秒以上才倒（不能秒殺）；**沒有任何路徑能讓倍率超過 ×3.0**。

## 十一、舊玩家進度怎麼回收、怎麼補償

### 11.1 原則

- **回收的是「膨脹」，不是「努力」。** 玩家在 1.0 收集到的角色、星、粉塵、升階、超越、徽章、更衣室、王勝紀錄、輪迴次數**一律保留**——那些本來就是輪迴時保留的東西，玩家心裡認定是自己的。
- **只回收會膨脹的三個欄位**：`marksClaimed`（已領印記）、`blessing`（祝福等級）、`marks`（手上印記）。
- **用新規則重算，而不是歸零**：把玩家「已經做過的事」拿去套新版的事件計數，算出他**在新版下本來就會有**的印記數，直接發給他。做過 12 輪、每輪都打到第七站的人，新版下就是 12×12＝144 枚，那就給 144 枚——他沒有損失任何一次輪迴的價值，只是不再有 107 萬枚。
- **補償放在末世，不放在 1.0。** 1.0 剛剛才把倍率壓回來，任何放在 1.0 的補償都會把它再撐開。末世是全新戰力、正好是「老玩家的新起點」。

### 11.2 結算公式（一次性遷移，`validate()` 的 v2→v3 步驟，`REPAIRS` 不動）

```
新印記 = Σ 每次輪迴的事件印記（用保留的 bossWins／prestiges／里程碑 反推；
          反推不到的，用「每輪 12 枚 × prestiges」上界給滿——寧可多給不少給）
祝福等級 = min(20, 用新印記能買到的最高級)      ← 自動幫他買到頂，剩餘留在手上
markMul  = 係數 0
legacy   = { marksClaimed, blessing, marks, lifetimeCoins, migratedAt }   ← 原值封存，可回溯
```

`legacy` 留著有兩個用途：補償分級要看它；日後如果決定補償不夠，還能再算一次而不是「已經沒資料了」。

### 11.3 補償內容【追問定案：徽章＋魔花少女老玩家變種卡，不發券】

| 對象 | 補償 |
|---|---|
| `legacy.prestiges ≥ 1`（輪迴過至少一次） | 徽章「舊時代的珍母」＋ **魔花少女・老玩家收藏卡**（§十二） |
| 沒輪迴過的存檔 | 只做印記重算，不補償（他沒有被膨脹曲線帶走） |

不發末世券：末世的第一張圖要讓老玩家跟新玩家從同一條線起跑。
收藏卡沒有戰力，所以這份補償**完全不碰任何平衡**。

### 11.4 怎麼告訴玩家（理由）

用遊戲已經有的語言：輪迴叫「換桌布」，這次叫**「珍母大掃除」**——末世來了，舊桌布收進相簿。
一次性結算畫面（不是彈窗，是一整頁，玩家自己按「收下」才關）：

```
珍母大掃除
  保留：52 隻夥伴、星與超越、徽章 23 枚、更衣室、輪迴 12 次
  整理：印記 1,069,453 → 144（新版印記照「做過的事」算；祝福已為你升到 Lv.20 上限）
  補償：末世券 ×30、變種卡「小丑玥玥・舊時代」、徽章「舊時代的珍母」
        [ 收下 ]      [ 這是怎麼算的？ ]
```

「這是怎麼算的？」展開就是 11.2 的式子，用他自己的數字填。**透明本身就是補償的一部分**：
玩家最不能接受的不是變少，是「不知道為什麼變少」。

⚠ 這頁要能在存檔匯入時重播（同一份存檔在另一台機器第一次載入也會看到），
而且要 idempotent：`legacy.migratedAt` 存在就不再結算第二次。

### 11.5 要問使用者的

- 「大掃除」這個名字與整頁結算的做法。

## 十二、變種卡（`KICKOFF-5.0-window.md` 任務二）在這套架構裡的位置

使用者原話（2026-09-11）：「把一些卡做變種，有更炫麗的特效與外框，之後會有方式入手，收藏價值用。」起點是魔花少女（`special`）。

### 12.1 定位【建議】

- **變種卡＝同一張卡的收藏版本，不是另一張卡。** 資料上是 `edition`（`base`／`deluxe`／`variant-<name>`），跟 `DESIGN-deluxe-gacha.md` §3.1 拆 `characterId` 與 `cardId+edition` 那一層同一個模型。
- **沒有戰力、不能裝備、不進編隊計數。** 編隊拖的是本體；變種只在卡冊裡、以及「展示這張卡時用哪個版本的卡面」——玩家可以在展示頁選「用變種卡面顯示」，編隊網格裡那張卡就換成變種外觀，數值不變。
  這樣它才能無上限地當補償（§11.3）、當活動獎、當里程碑獎，永遠不碰平衡。
- 卡冊：本體格子角落一個小徽記表示「有變種」，點進展示頁可切換；收集度另列「變種 n／N」，**不計入本體的 n／N**。

### 12.2 入手方式【追問定案】

| 來源 | 變種 |
|---|---|
| 舊玩家補償（輪迴過的存檔） | **魔花少女・收藏卡**：**除此之外沒有任何取得方式**，不在任何池、不在任何獎勵表 |
| 魔花少女本體（禮物卡）| 維持特別，照 `SPEC-gift-card-into-gacha.md` |
| 其他變種 | 之後再說；末世王首勝**不**給變種 |

### 12.3 視覺規則（照 KICKOFF 已列的限制）

- 精裝版「只有一種版型」的規則**變種也要守**：階級寶石＋文字框＋名字＋稀有度都要在，變種只能加不能減。
- 不能違反「不預告品質」：變種抽不到（不在券池），所以揭卡預告契約不受影響；但**如果日後放進券池，common／rare／epic 的變種在 `face-visible` 前必須逐像素零差**。
- **先做一張樣品**（KICKOFF 的原話），門檻上下限成對、交「本體 vs 變種」並排圖。第一張建議就是補償用的那張，做出來直接兩用。

### 12.4 已答
- 變種＝無戰力、只換外觀 ✅
- 老玩家變種＝魔花少女，絕版 ✅

## 十三、1.0 難度重設計（2026-09-12 追加；細節見 `REFERENCE-2026-09-12-sakura-clicker.md`）

使用者：「1.0 的難度關卡也要重新設計，可能考慮也引用編隊系統，方便重新調整戰鬥力平衡。」

### 13.1 1.0 現在為什麼沒有難度

兩個根因，印記只是其中一個：

| | 現況 | 後果 |
|---|---|---|
| 印記 | 產出∝√生涯幣、兩條無上限倍率 | ×76,000（§十） |
| **王包血量** | `max(門檻包需求, 1.25×(30P+180D))`——**跟玩家自己的 P 與 D 掛鉤** | 王永遠是「30 秒左右的固定戰鬥」，你變強它也變強；**沒有牆**，所以沒有「這關過不去、得回去養」的時刻，輪迴與編隊都沒有存在的理由 |
| 場景需求 | 1／8／64／500／2000／12000 六級階梯 | 站與站之間是懸崖，站內沒有曲線 |

Sakura／Clicker Heroes 的做法正相反：**血量純粹是關卡的函數**（`16.5×1.55^zone`），
你的強度是你自己建的；每區 10 隻＋1 王、王 30 秒計時，打不贏就回去刷——牆自然出現在第一天末，隔天輪迴。

### 13.2 建議方向【待裁】

1. **王血量改成關卡函數**，不再讀 P／D。每站內部拆成 N 關（例：10 包＋1 王），關與關之間血量 ×r（r≈1.5，實際值模擬定），收益成長率略高於 r。
2. **編隊進 1.0**：隊伍 20 張、前綴上限 2／6／12／20、技能 4 格同末世；隊伍每秒收益＝1.0 的 pᵢ 加總（現在是「所有擁有的角色都算」，改成「只有隊伍裡的算」——這一刀才是讓戰力可控的關鍵）。
3. 兩區共用同一套編隊規則與 UI，但**卡池、養成、存檔各自獨立**（§一 1.5 的隔離不變）。
4. 印記照 §十；輪迴獎勵改成線性於「本輪到達的站／關」。

### 13.3 ⚠ 編隊進 1.0 會撞到的東西（要先拍板）

- **1.0 有升階，升階會改稀有度**——跟你剛剛在末世否決升階的理由完全一樣。三個選項：
  (a) 1.0 的前綴上限看**出身**（原生稀有度），升階只改數值不改「算哪一層」；
  (b) 1.0 也拿掉升階（老玩家已升的保留數值、以後不能再升）；
  (c) 1.0 的編隊不設前綴上限，只設 20 張總數。
  **使用者定案：(a)**——前綴上限看出身，升階只改數值不改所屬層。
- 羈絆、當家、推薦組合是「三槽」時代的規則，四格＋20 人隊伍要重驗。
- 1.0 的 52 張卡 vs 20 格：收集完之後有 32 張不上場，卡冊要能顯示「在隊／不在隊」。

### 13.4 要問使用者的

- 站內拆幾關、王的計時要不要沿用 30 秒。
- 1.0 重設計跟末世第一張圖，**哪個先做**（兩個都動 `src/`，順序決定分支怎麼開）。
