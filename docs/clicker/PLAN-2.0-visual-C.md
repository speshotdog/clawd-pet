## 二、「箔面卡像嵌入廣告」的真正成因 ★這是這輪最有價值的一段

astra 修正了自己上一輪的判斷。**不是「平面 UI 一定會讓卡像廣告」**，真正的成因是：

> 卡片自成一個精密、明亮、會動的視覺區域，
> **但周邊沒有交代它為何在這裡、由誰承載、與哪個操作有關。**

它從原始碼指出斷點：

- `card_face.js` 的 `material()` 已建立 spectrum／relief／etch／fiber／grain／glare，**卡面本來就是高密度材質**；旁邊若是一大片無關純色，密度會突然中斷
- `HoloCardFace.paint()` 依游標更新 `--gx`／`--gy`／`--phase`——**卡不是固定光源模型**，替 UI 畫一道固定斜光在互動時就對不上
- 卡內已有框、寶石、文字背板與名稱；外面再套厚框＋獨立標題＝**框中還有一套系統**
- 卡一直掃光而其他控制靜止，它會持續搶注意力，**這跟卡佔 35～50% 無關**
- 沒有選取標記、來源關係、裝備狀態時，玩家看到的就是展示品

**結論（重要）：卡可以比 UI 精細華麗。要連續的是「承載與操作關係」，不是要求兩邊材質密度一樣。**

### 解法（依投報率，首版做前三項）

| 解法 | 做法 | 驗收 | 規模 |
|---|---|---|---|
| **同一組選取關係** | 代理圖／詳情標頭／「已編入・替換」共用編隊序號與側邊標記，選卡時**三處一起換**（不能只同步換顏色）| 序號與卡片身分一致 **100%**；玩家由詳情指出隊伍位置正確率 **90～100%** | 小 |
| **卡外承載槽** | 卡放在與容量列、技能格共用導軌的**霧面槽板**；用卡外接觸陰影與槽底交代位置，**不在 `.face-*` 裡加框或黑條** | 卡與槽內緣間距 8～16px；**卡被裁切 0%**；完整卡占詳情區 35～50% | 中 |
| **只在交界增加材質** | 槽板帶刮痕與邊緣明暗；一般文字與按鈕保持乾淨，**不把 `foil-stack` 複製到全站** | 有紋理表面占非卡片 UI **12～22%**；紋理開關在空白樣區的灰階差 **6～14／255**；文字對比 4.5～12:1 | 中 |
| **節制外部動態** | 完整卡保留材質互動，**代理圖靜止**；選取用槽標改變 | 接受材質互動的詳情卡 **1 張**；自動掃箔與導航觸發揭卡 **0 次** | 小 |
| ~~承載槽跟隨反光~~ | 靜態承載不夠才做。卡外窄反光帶讀同一游標輸入 | 主反光與槽邊反光方向夾角 0～20°；反光占詳情區 2～5% | 大（**首版不做**）|

> 若必須讓所有面板發光、加彩虹與召喚環才融入，**已經失去 C 的方向。**

### 並排圖怎麼拍（這條線的規矩：開 vs 關，並排沒差＝沒做到）

先固定分母：**詳情區 D**（預先標定，開關圖不得縮小它湊比例）、**卡片 K**（中立姿態投影，不計槽、陰影、外光）、**非卡片 UI**（面板與控制的面積聯集，不含地景卡面空白，巢狀不重複）、**接合區 R**（卡外側 8～24px 的槽板，排除文字）。兩張圖用**完全相同的遮罩**。

拍攝：1440×900／1024×768／390×844 三個尺寸各拍（**手機圖不准縮成縮圖判斷**）；同隊伍、同卡、同游標位置、同動畫時刻；涵蓋各稀有度與 `depth／flat／framed`、亮暗卡都要；**左＝關**（保留完整卡與功能，只關掉承載／接合材質／共同選取標記，空間仍保留），**右＝開**；另交各項獨立開關圖；靜止／游標偏左上／偏右下三次取樣，**要等真的重繪**。**卡的大小、亮度、飽和度、文字、箔面參數一律不准為了右圖好看而動。**

| 要證明什麼 | 比什麼 | 通過區間 |
|---|---|---|
| 沒靠藏卡解決 | K／D | 35～50% |
| 仍是第三套語言 | 新輪廓所屬的非卡片 UI 面積 | 65～85% |
| 接合看得見 | R 內灰階差達 8～24／255 的像素占比 | **20～45%**；超過該帶寬的像素 0～5%（**防止靠爆亮過關**）|
| 沒改卡救介面 | 對齊後卡內核心區的開關差異 | **0%** |
| 形成共同操作關係 | 不顯示標籤，請玩家圈出「這張卡的隊伍位置與替換操作」| 正確率 90～100% |
| 並排差異有意義 | 玩家指出哪張承載／選取關係較清楚並圈出依據 | 選「開」且依據有效 80～100% |
| 絕對品質成立 | 單看「開」圖，判斷卡是編隊物件或獨立嵌入展示 | 編隊物件 85～100%；獨立嵌入 0～15% |

**最後兩項要玩家判讀，不能用像素差替代。** 並排看不出差異、或只看得出多了一圈裝飾，都不算完成。

## 三、兩個一定要記住的實作陷阱 ★astra 從原始碼挖出來的

1. **王關 3 分鐘冷卻不能用 `activeNow()`。**
   那個時鐘是為「演出暫停」寫的，`pauseTimers()` 會在分頁隱藏時凍住它——
   **玩家切到別的分頁，冷卻就停了。** 冷卻要用**獨立的到期時間戳**，介面只負責顯示剩餘。
2. **`dealDuration:620`／`stagger`／`strengthen()`／揭卡分層全部留在抽卡。**
   2.0 的新效果一律 CSS／DOM／SVG，**不要藉機把 Canvas／WebGL 搬成全站效果**。

## 四、轉場改了：不是「先見土地與道路」，是「先見熟悉的地標」

astra 自己推翻上一輪：**陌生土地只能證明換場景，不能解釋為什麼來到這裡。**

新的順序：**離開城市 → 回到熟悉卻被毀的後院 → 看見重新走過舊地點的路 → 介面就位**
（⚠ 不能把城市直接形變成後院，兩者不是同一位置；要在遮幕下切換）

| 階段 | 時間 | 門檻 |
|---|---|---|
| 收起舊控制（城市保留）| 140～180ms | 視窗位移 8～12px |
| 遮幕（舊舞台不放大，`#zoomer` 外接手）| 160～200ms | 覆蓋率 100%、alpha 1 |
| 幕後換根容器 | 40～80ms | 舊 UI 穿透 **0%** |
| **揭出熟悉地標**（先出後院構圖，不先出路線與面板）| 220～280ms | **關鍵地標可見率 90～100%** |
| **留出辨認畫面**（停止鏡頭運動）| 320～440ms | 非必要 UI 覆蓋 0～5% |
| 路線與操作就位（工作盤自邊緣進場，避開地標）| 180～240ms | 位移 6～10px |

首次入場總長 **1.06～1.42 秒**（上一輪的 0.70～0.92 秒**留給回訪**，不重播辨認停頓）。
並排驗收：「土地道路先出」vs「地標先出」，後者的玩家新舊後院配對正確率須 **85～100%**。
**認不得的話要改地景識別與構圖，不能只延長黑幕。**

## 五、UI 跟廢墟地景怎麼共處：對比／融合不是二選一

分三件事各自處理：**操作輪廓對比**（知道哪裡能點）、**承載材質有限融合**（霧面刮痕氧化色呼應環境，但不讓整張 UI 像碎石）、**地景識別靠構圖與物件保留**（**這件事不能交給色票**）。

投報率最高的一項是**先避讓**：面板靠邊、路線繞過識別核心，不用先加材質。
門檻：指定地標輪廓被 UI 遮住 **0～10%**；**識別核心被不透明面板遮住 0%**。

| 畫面 | 地景可見面積 | UI 覆蓋地景 | 已標定識別物可見 |
|---|---:|---:|---:|
| 首次地標揭示 | 80～95% | 0～5% | 18～30% |
| 地圖常態 | 60～75% | 10～20% | 15～25% |
| 一般戰 | 55～70% | 15～25% | 12～22% |
| 王戰 | 50～65% | 15～25% | 10～18% |

`clicker-scene.js` 已經有可用的構圖線索：**後院樹在左、廚房層架與後櫃有相對位置、
便利商店前後貨架錯開、夜市有攤架與燈籠、冰箱又是另一組配置。**

並排驗收：同一新地景的 UI 關／UI 開，再放對應的 1.0 原場景。
UI 開啟後場景配對正確率仍須 85～100%、比 UI 關下降 0～10 個百分點、地標輪廓可見率 90～100%。
⚠ **用名稱提示才認得、遮掉名稱就配錯，不算通過。**

⚠ **王②的粗白邊是護盾機制，不要為了材質融合把它磨掉。**
王③的節拍標記與王④的部位標記**只在王關工作**，一般關不鋪同類 UI。

| **③ 新介面吃掉舊世界的辨識** | UI 關的地景配對先達 85～100%；開啟後仍 85～100%、下降 0～10 個百分點；地標可見率 90～100% | **若 UI 關也失敗 → 該重畫地景，不能歸咎 C** |

⚠ **退回 B 不代表改 `src/`，也不代表把舊 PNG 壓暗就算交付。**
B 必須用同一張卡、同一地景、同一資訊量對照，一樣要過卡片關聯與地景辨識門檻。
**B 也失敗的話，要修的是承載或內容，不是宣稱換回熟悉風格就解決了。**

### 真身素材這條要特別記住

使用者原話：

> 2 但用濾鏡來呈現 盡量不要改圖
> 前景畫面特效 讓他更立體 看起來會呼吸

所以真・滅世珍獸的作法被限定成：

```
底圖   ＝ clicker-boss7-mieshi.png（632×360），不重畫、不裁層
呈現   ＝ CSS 濾鏡（色調／對比／飽和／色相位移），不改像素
立體   ＝ 前景特效層做視差與景深，不是把圖切開
呼吸   ＝ 極慢的整體節律（縮放／亮度／位移），要像活的不是像動畫
```

⚠ 這正好避開 1.0 註解記錄的三次裁層失敗（鐵塔與天空同組暖色分不開、鏡射拼寬整片對稱），
也符合 astra 說的「只有完整場景插畫就用遮罩揭露，**不硬造可活動肢體**」。

⚠ **「會呼吸」要有可量測的上下限，不然做出來不是沒感覺就是像在抖。**
提議（實測後定死）：週期 **4～7 秒**；整體縮放振幅 **0.6～1.4%**；
亮度振幅 **2～5%**；**UI 位移 0**。並排圖交「呼吸開 vs 關」，
沒差＝沒做到；抖到看得出是動畫＝過頭。
