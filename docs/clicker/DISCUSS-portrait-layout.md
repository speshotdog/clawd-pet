# 討論：直式手機版面要重做（給 Astra）

**這一份是討論，不是派工。** 請你先讀完、思考，然後把你的看法與提案寫進
`docs/clicker/DISCUSS-portrait-layout-astra.md`。**不要改任何程式碼。**

## 背景

珍母點點原本是釘死的 960×640 橫式。2026-09-08 加了一套直式手機版面
（`src/clicker.css` 最後面的 `@media (max-aspect-ratio: 3/4)`），
作法是「只縮放 `#stage` 本身」——舞台內部維持 608×360 的座標系，
所以場景圖層、王的 `--boss-cx`、粒子、技能槽全部跟著等比縮，內容一行都沒改。
這個作法本身是對的，**不要推翻它**。

使用者在真機上看過之後說：「字體有些沒置中，也些空間沒有合理被分配」，要求重做版面。

## 實機量到的數字（390 × 844，`_art/out/r33-portrait-real.png`）

目前由上到下：

其他量到的溢出：

- 舞台裡有個 `IMG` 在 x=-6（左緣出界 6px）

## 我目前的判斷（請挑戰我）

1. **錢包**：`.wallet` 在基準樣式裡有 `margin-left:auto`，直式我寫了 `margin-left:0` 但顯然沒生效，
   要查是被什麼蓋掉。更根本的是：46px 高的一列要塞「幣數 + 每次 + 每秒 + 音量鈕」四樣東西，
   而幣數在後期會長到「1.00垓」這種寬度。我傾向**拆成兩行或把每次／每秒縮小**，
   幣數是玩家最常看的，應該最大、最左。
2. **空間分配**：現在 844 高裡，舞台只佔 221（26%），夥伴列卻佔 299（35%）。
   夥伴列是「不看也能玩」的東西。我傾向**夥伴列固定 92 高**，把省下來的 200 給舞台
   （舞台是主畫面，也是拆包要點的地方）。但舞台放大之後 608×360 的比例會讓它更高，
   要確認技能槽仍在拇指構得到的範圍。
3. **底部分頁**：五顆的內容結構不一致（三顆有圖示、兩顆沒有）。要嘛全部補圖示，
   要嘛全部只用文字。我傾向**全部只用文字＋放大字級**，因為 71px 寬塞圖示＋文字會很擠。

## 請你回答這四題

1. **上面三個判斷你同不同意？哪裡是錯的？** 尤其第 2 點：把空間從夥伴列搬到舞台，
   會不會讓技能槽掉出拇指區？（舞台底部就是技能槽的位置，`#slots` 在 `#stage` 內
   `left:28px; bottom:20px`，跟著舞台一起縮放）
2. **844 高要怎麼分配才合理？** 請給一張表：每一段幾 px、為什麼。
   已知固定成本：安全區上下約 47 + 34、五個分頁 56、段間留白約 7×5。
3. **錢包列那四樣東西怎麼排？** 幣數在後期是「1.00垓」這種長度，
   每次／每秒也會到「132.5億」。46px 一行塞不塞得下？還是要 60px 兩行？
4. **有沒有我完全沒想到的問題？** 你可以直接看 `src/clicker.css` 最後面那段
   `@media (max-aspect-ratio: 3/4)` 與 `src/clicker.html`。

## 限制（提案時要遵守）

- 橫式那套 960×640 **一行都不能動**（桌機與 exe 在用）。
- 舞台內部的 608×360 座標系不能動。
- 技能槽最多 **4 格**（印記商店的 slot4）：4×64 + 3×16 = 304，在 608 的舞台裡放得下。
- 面板（名冊／商店／換桌布…）在直式是「從底部推上來」，這個已經做好了，不用改。
- 驗收要跑得過 `PYTHONIOENCODING=utf-8 python tools/test/clicker-round31.py`。
