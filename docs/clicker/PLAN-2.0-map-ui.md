# 2.0 末世地圖 UI：討論結論與待挑選項

來源：`DISCUSS-2.0-map-ui.md`（我出的題）＋ `ANSWER-astra-2.0-map-ui.md`（gpt-6-astra 原文）。
**這份是給你挑的，還沒有實作。** 每一項標了「我建議」與「要你決定」。

astra 有真的讀原始碼——它糾正了我兩處事實：
① `ceremony.css` 的六層背景其實只有三層在亮（`.stage-substrate`、`.stage-sheen` 透明度是 0），
所以「深色儀式感」的特徵是**黑底＋幾何＋留白**，不是滿畫面光效；
② 六角切角按鈕只套在 `.pull-actions button`，不是全站按鈕。
這兩點會影響「2.0 要不要延續抽卡語言」的成本估算。

## 決策一：2.0 的視覺語言走哪一套 ★要你決定

| 選項 | 第一秒的感覺 | 成本 | 風險 |
|---|---|---|---|
| **A. 抽卡語言的延伸**（astra 推薦，我同意）| 「從『抽到力量』走進『使用力量』的世界」——卡是熟的，環境是陌生的 | 中。深色底、Noto Sans TC、`#eadfc4`、切角輪廓可直接吃；地圖／節點／關卡景深要新做 | 最低。精裝卡本來就長在這套語言裡 |
| **B. 1.0 牛皮紙的黑化版** | 同一張熟悉的桌面變危險了 | 中。`#game`／`.topbar`／`#shop`／`#team` 的固定座標仍要全部重排，還要新做暗色紙材 | **圓體＋咖啡描邊會把精裝卡襯成外來物** |
| **C. 第三套全新語言**（例：災後軍事終端）| 像另一款遊戲 | 大。字級、圖示、面板、按鈕、地圖、轉場全新做 | **最高。新介面若偏平面，箔面卡會像嵌進去的廣告** |

**A 的具體樣子**：延伸的是材質／字體／控制元件／深色留白；
但**地圖不用召喚陣當背景、戰鬥不重播揭卡演出**——把「儀式桌面」換成「末世行軍場景」。

**驗收「這確實是新設計不是換色票」**（灰階下也要看得出結構改變）：
地圖場景與路線占畫面 **55～70%**；主操作中心相對 1.0 同類畫面位移 **20～40% 畫面對角線**。

**B 或 C 什麼時候反而對**：B——你想保住原桌面操作習慣、強調「同一個寵物世界的恐怖續篇」；
C——2.0 以後要獨立成產品，而且你已經有足量的新場景與角色美術。

## 決策二：2.0 要不要沿用抽卡的畫面狀態機 ★我建議照做，你可以否決

**建議：模式照抄，控制器另起一套。**

理由是實作事實：`ceremony.js` 的 `setScreen()` 寫死只收 `entry／ceremony／results`，
而且連動 `focus-held` 與 `updatePages()`；`updateFinish()` 還要檢查卡片完成、動畫、計時器、
rAF、聲音**全部**結束。地圖塞進去會錯誤繼承抽卡的完成條件。

要照抄的是它的四個契約（這幾個是這條線用血換來的）：
`generation` 先失效再取消舊工作、`wait()` 取消後要結束等待、
`activeNow()`／`pauseTimers()`／`pauseRafs()` 的可見性處理、背景生命週期與有限演出分開。

驗收：任意換頁或返回後，舊畫面回呼改動新畫面的次數 **0**；每次切換後可操作主畫面 **1 個**。
（只隱藏 DOM 不算取消完成。）

## 決策二之二：1.0 → 2.0 的轉場 ★我建議照做

**核心問題是座標系**：1.0 是 `#zoomer` 縮放的固定 960×640，抽卡是 `100vw/100dvh` 滿版。
astra 明確反對「把 `#zoomer` 一路拉成滿版」——那會同時放大字、邊框與 PNG，最後還是要換排版。

**作法：滿版遮幕跨座標系。** 遮幕由獨立於 `#zoomer` 的外層承接，舊舞台保持原縮放；
**遮幕完全不透明之後**才切成新的滿版根容器。

| 順序 | 看得到什麼 | 門檻 |
|---|---|---|
| 收起舊控制 | 商店／隊伍先退場，**城市暫留**（讓玩家知道自己從哪離開）| 140～180ms；視窗位移 8～12px |
| 遮住座標切換 | 近黑遮幕蓋滿整個視窗（含舊舞台外側）| 180～220ms；覆蓋率 100%；終點 alpha 1 |
| 切換根容器 | 幕後換成滿版地圖 | 完全遮蔽 60～100ms；舊 UI 穿透誤觸 **0 次** |
| 先見土地與道路 | 遮幕退去，**先出現廢墟地形與往遠方的路** | 240～300ms；場景由下方 12～20px 回位 |
| 再見現在與操作 | 當前節點、關卡名、編隊入口**最後**出現 | 160～220ms；位移 6～10px；場景出現後 80～120ms 才開始 |

全長 **0.70～0.92 秒**（不含素材等待）。順序的意思是「離開桌面 → 換世界 → 看清目的地 → 開始操作」。

⚠ 兩個容易漏的：素材要在揭幕前備妥，**準備失敗要顯示可返回的錯誤狀態，不能停在無提示黑幕**；
舊 UI 若用原舞台元素做動畫，位移要**除以 `#zoomer` 的實際縮放值**才等於表上的視窗位移。
減少動態模式：120～180ms 淡換、位移 0。

## 決策三：地圖怎麼畫 ★要你決定「垂直捲動」是不是你要的

**astra 提案：垂直捲動、單一路線、局部左右偏移**（偏移只是地景構圖，不能看起來像岔路）。
桌面右側放關卡摘要，手機放底部。

| 元素 | 長相 | 門檻（上下限成對）|
|---|---|---|
| 普通節點 | 切角地標牌，站序＋地景符號（不是每站一顆光球）| 本體 48～60px；相鄰縱距 104～144px、橫偏 24～56px；**靜止位移 0**；輪廓對比 3～5:1 |
| 路線 | 單條折線，已走實線／未走斷線 | 線寬 2～3px；已走 alpha .65～.80、未走 .22～.34 |
| 當前位置 | 切角括框＋「目前」＋實心方向標 | 括框距 6～10px；對比 5～7:1；切換 160～220ms |
| 已通關 | **保留站名**＋勾號（不整顆變灰消失）| 勾號 14～18px；標籤對比 4.5～7:1 |
| 未解鎖 | 空心節點＋鎖＋前置站名（不顯示可挑戰按鈕）| 圖形 alpha .30～.42；標籤對比 4.5～7:1 |
| BOSS 節點 | **寬幅城門剪影，路線從門中央穿過**（不靠紅色辨識）| 88～112 × 60～76px；外形對比 4～6:1 |
| 推進一格 | 舊節點落勾 → 連線向前填滿 → 括框移到新站 | 120～160ms → 240～320ms → 160～220ms |

鏡頭規則：新節點已在視野內就**不捲動**；被遮住才移動，單次 12～28% 視窗高、280～380ms，
**不跳到正中央**（會遮斷上下文）。

## 決策四：編隊怎麼放 20 張卡 ★要你決定「總覽用代理圖」這件事

astra 直接改了題目：不該問「20 張怎麼塞進一個畫面」，該問
**「玩家看得到隊伍規模、能定位任一張、能理解限制」**。

### 4-1 四條累加上限的畫面呈現（規模小、我建議先做這個）

固定顯示四列，**直接把集合寫出來**，不要寫成四種獨立配額：

```
神話                  n / 2
神話＋傳說            n / 6
神話＋傳說＋史詩       n / 12
全隊                  n / 20
```

拖入超額時：卡片返回起點 180～240ms；在那一列旁寫
**「神話＋傳說合計已達 6，加入後將為 7」**；超額列邊框亮 240～360ms、線寬 2～3px；
**文字持續到下一次操作，不只閃一下**。多條同時違規要全部標出。

⚠ astra 指出我題目裡「第 7 張傳說」只是特例——**已有神話時會更早撞到第二條**，
驗收必須包含混合隊伍，不能只測純傳說。

### 4-2 版型：不要擴充 `CeremonyTable.layout` ★我同意

它不是拒絕 20 張，是會算出**四排**卻仍用 `(Math.floor(i/5)-.5)` 定位（後兩排會往下溢出）；
桌面卡寬還有 170／190px 下限，縮不下來；手機的 `.page-away` 是為「逐張欣賞」寫的，
不適合比較隊伍。**另寫一個編隊專用版型模組**，共用卡片身分與 `HoloCardFace.refit()`／`unobserve()` 契約。
`dealDuration:620`／`stagger` 留在抽卡，編隊不要逐張發牌。

| 情境 | 配置 |
|---|---|
| 寬螢幕 | 10 欄 × 2 排，卡寬 88～104px，間距 8～12px（陣列約 952～1148 × 254～303px）|
| 中型桌面 | 5 欄 × 4 排，卡寬 88～104px；不夠時卡區獨立捲動，**容量列與技能列保持可見** |
| 手機 | 4 欄，卡寬 68～80px；不夠時降欄數，**不再縮小** |
| 詳情 | 選中後展示**未修改的完整卡面**，寬 240～304px |

驗收：滿隊項目數 20／20；任一卡的識別區被相鄰卡遮住 **0%**。

### 4-3 總覽用「代理圖」、詳情用完整卡面 ★要你決定

代理圖 = 保留 **5:7 外形、角色主要輪廓、稀有度符號、外部姓名**。
它是**另一個 UI 元件**，不是把凍結卡面的字級或 Z 改小（`card_face.js` 不動）。

不採純頭像的理由：會截掉兔子的**槌**、龍的**角**這種識別物。

驗收（這條是重點）：**隱去姓名後配對回原卡的正確率 90～100%，耗時 2～4 秒**；
角色主要輪廓占代理圖面積 45～70%；姓名字級 12～14px、對比 4.5～7:1。
⚠ astra 自己標注：**68px 不是已證實的辨識下限，需要實機量。**
達不到就加大或減欄，**不能靠姓名替糊圖過關**。

### 4-4 技能格 ★取決於你回答「技能從哪來」

四格固定在隊伍區下方，高 56～72px、間距 8～12px。兩種都先畫好了：

- **技能來自隊伍卡**：技能格顯示來源卡小圖，選中時來源卡與技能格用**同一種括框**；
  移除來源卡必須明示技能缺額，**不能靜默換人**。
- **技能是獨立池**：標示「獨立技能」、有自己的挑選入口，**不畫連線**（連線會暗示必須由隊伍供應）。

⚠ 「不超過 1神話+1傳說+1史詩+1精良 的戰力」這條**不能只靠稀有度數量推算**，
取決於技能戰力定義；**未定之前不要畫百分比條**（那是先替未來機制下決定）。

## 決策五：戰鬥與 BOSS 的版面 ★機制未定，這裡只談畫面

### 一般戰
交鋒場景占 55～65%；頂部資訊 8～12%；下方隊伍／技能 20～28%。
事件卡片回饋 180～260ms、位移 8～14px，**不播揭卡或稀有度爆光**。
⚠ 場上只顯示 1～3 張卡是「當次相關」，**不能讓玩家誤讀成參戰名額只有這麼多**。

### BOSS 戰（改構圖，不是一般戰加大血條）
中央縱深構圖：上識別區／中怪物與專屬地景／下隊伍。BOSS 場景占 65～75%；
**一般戰與 BOSS 戰的主要焦點位置要差 15～25% 畫面寬**（這就是「不同一套」的可量測定義）。
入場 400～600ms、背景位移 16～28px；**鏡頭動，資訊列不晃**。
不預設部位破壞／多階段血條／倒數／弱點游標——那些不是版面決策。

### 四個 BOSS 素材的用法
| 素材 | 用法 | 尺寸 |
|---|---|---|
| `01.gif`（180px 狼犬）| **用場景尺度襯托小角色**，放遠景平台中央；不放大不模糊 | 盒邊長 144～180px（0.8～1.0 倍原尺度）|
| `ej93j4.gif`（貼紙羊）| **承認它是貼紙**，給實體底座；不用光暈吞白邊 | 240～320px；外輪廓保留 98～100% |
| `image.gif`（扛槌兔）| 去背後**保留兔＋槌＋裂地當小舞台**，不能只留頭 | 240～320px |
| `rise.png`（靜態雞頭怪）| **動的是背景霧與底座陰影**，不假裝有走路動畫 | 高 220～280px；角色形變 0%；霧移 8～16px／4～6 秒 |

去背驗收（照這條線的規矩，**不用逐像素差**）：主體遮罩保留 98～100%、輪廓 IoU .97～1.00、
殘留白區占原背景 0～0.5%、各幀波動 0～2%（扣掉本來的形變）。
**GIF 要逐幀驗，不能只驗第一幀**；深色與中灰底都要看，白毛／槌柄／細角不能被當背景刪掉。

### 真・滅世珍獸 ★要你決定素材路線
`scenes.city` 的原始碼註解記錄了裁層三次失敗（鐵塔與天空同組暖色分不開、鏡射拼寬整片對稱），
所以**不要再靠自動裁原圖拼真身**。

astra 的方向，我覺得值得採用：
**「城市輪廓其實就是伏臥巨獸的背脊；2.0 街道裂開，城市尺度才顯示出牠的形體。」**

- 延續 `mat:'#4A3A2A'`／`sky:'#8A6B44'` 的暖色城市記憶
- 新背景重畫相似城市輪廓與前景暗樓，把**地標形狀轉成背脊／冠部／外殼**
- **不要沿用「整張圖全亮一次」**；改用地平線錯位、城縫亮起、巨大陰影移動來揭示尺度

驗收：從原城市指定 2～3 個地標，在新場景輪廓保留率 85～100%（這就是「同一隻的真身」的證據）；
真身／城市占主場景寬 65～85%；開場揭示 1.2～1.6 秒、前後景相對位移 12～24px；
裂縫亮帶占 3～7%、峰值 alpha .45～.65；**衝擊只移背景 3～5px，UI 位移 0**。

分支：**拿到獨立透明真身素材** → 讓牠從城市之後起身；
**只有完整場景插畫** → 城市變形＋遮罩揭露，**不硬造可活動肢體**。

## 決策六：明確不做的事（astra 列的，我全部同意）

體力／每日任務、虛構掉落預覽與關卡星等、戰鬥形式未定就先放加速鈕、
有分岔感的路線圖、一般操作反覆播抽卡級特效、滿版常駐光暈、
20 張卡全部持續傾斜掃箔（比較隊伍需要**穩定位置**）、
技能先補冷卻／能量／戰力百分比條、把 1.0 CSS 全域改暗、把抽卡三態機擴成全遊戲控制器、
用模糊／全亮／巨大白邊遮掩素材問題、新增 npm 或外連素材。

其中兩條特別重要，因為對應這條線踩過的坑：
- **滿版光暈**——「為了過亮度門檻加光暈，把愛心做成光斑」。門檻是核心圖形輪廓可見率 95～100%、局部光效覆蓋 3～7%。
- **虛構計量元件**——畫面會先替還沒設計的機制下決定，之後改不動。

## 派工順序（astra 建議，我同意）

```
地圖與關卡狀態 → 編隊可讀性與限制回饋 → 跨世界轉場 → 一般戰與 BOSS 構圖 → 真身資產與專屬特效
```

跟你說的「先做關卡 → 再提機制」一致。戰鬥操作、失敗代價、技能戰力定義等關卡骨架成立後再接。

**第一輪真正要驗收的只有四句話**：
看得出已進入新世界／找得到下一站／認得出隊伍成員／知道為什麼編隊被擋。
