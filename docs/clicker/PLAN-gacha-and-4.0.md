## 第二段：把研究線收進遊戲（這是真正的里程碑）

順序有依賴關係，不要跳。

### 2-1. 卡名字型 —— **根因已經找到並驗證過了，可以直接做**

`ISSUES-2026-09-09-night.md` 第七節說「Noto Sans TC 內嵌從來沒生效過」，
原因不是字型檔壞掉，是 `build_round4_fonts.py` 的一個 API 誤用：

```python
opts = subset.Options(); opts.text = chars      # ← 這行沒有作用
subset.Subsetter(opts).subset(font)             # ← 於是子集是「空的」
```

`fontTools.subset.Options.text` **只有命令列的 `pyftsubset` 會讀**，
Python API 必須另外呼叫 `subsetter.populate(text=chars)`。
沒呼叫的話 Subsetter 拿到空的字符集，輸出一個沒有 `cmap` 的殼——
所以是 996 bytes，而且瀏覽器載入直接 throw。

補上 `populate()` 後實測：

```
FIXED size: 168,472 bytes    glyphs: 778    cmap: 512
```

（本機已驗過，來源 `C:\Windows\Fonts\NotoSansTC-VF.ttf` 存在、11.9 MB。）

**要做的**：
1. `build_round4_fonts.py` 補 `populate()`，重建兩支 woff2，重新內嵌。
2. **字集要收窄**：現在是拿整份 `demo.html` 的所有非 ASCII 去做子集（514 字 → 168 KB）。
   卡面實際只需要「卡名 ＋ 稀有度 ＋ 型別」那幾十個字，
   從 `pool_data.py` 抽真正會用到的字元集，能壓到十幾 KB。
   這同時吃掉 `check_new_cards_round32.py` 那條「單檔超出體積預算 81 KB」的一部分。
3. 稀有度那行寫死的 `font:9px monospace` 一起換掉——中英兩種字型是這一行造成的。
4. **驗收要真的驗到字**：不能只驗 `document.fonts.check()`，
   要逐字比對 `measureText` 寬度與 fallback 不同，或直接像素比對。
   現在的驗收之所以沒抓到，就是因為它沒有驗「有沒有真的用上」。

### 2-2. 三支紅的驗收各自結案

`check_new_cards_round32.py` 的三項：

- **珍珍 flat 不符「純裁切」契約**：這是第 1 項裁決的直接後果，
  裁決確定後把契約改成「flat 卡允許透明留邊」並寫下理由。
- **單檔超出體積預算 81,268 bytes**：三張 depth 各多一層背景圖。
  先做 2-1 的字型收窄，再看差多少；還是超的話就調預算並寫下新數字的依據
  （**不要靜靜地調**，預算是為了防止頁面失控，不是裝飾）。
- **CRLF/LF 快照差異**：`src/clicker.html`、`src/gacha-mode-deluxe.js`、`src/gacha.html`
  的 `git diff` 是空的，純粹是行尾。凍結快照改成正規化行尾後再比，這條就永遠不會再假紅。
