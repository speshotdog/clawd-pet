# 揭曉演出改版 v3（第二十八輪設計）

日期：2026-09-09  
範圍：`_art/holo-test/build_deluxe_b.py` 的抽卡演出與外層 UI。  
狀態：**分析提案；本次未修改任何檔案、未執行建置或驗收。** 第二十七輪仍在另一個 session 進行，以下以其任務 0、A1–A5 完成並驗收後的版本作為實作起點。

## 一、設計裁決與研究批判

**推薦「星軌召喚封套」：流光投入召喚陣 → 封印顯色 → 撕封發牌 → 卡後蓄光 → 正面接光 → 回槽收下。**

視覺主張是深藍夜空、銀色封套、具有厚度與方向的光。借用日系抽卡的敘事語法，建立自己的星軌圖案與封印，不拼貼四款遊戲的識別素材。

畫面分工：

- **入口**：卡池、券數、抽卡操作。
- **演出**：一個封套或一張焦點卡；只保留跳過。
- **結果**：完整卡列與收下。

三個關鍵動作是「投遞落點」「封印破裂」「卡片接光」。卡面箔光是第三拍的回應，不承擔整場戲。

### 接受的結論

| 研究結論 | v3 採用方式 |
|---|---|
| 光應有明確來源，材質要接住外部光 | 保留 v2「卡後蓄光 → 材質接光」。卡外光源與卡片共用座標，不再固定於 `#orbit` 中央 |
| 靜止材質不應持續自動閃動 | 演出期間使用有限時間軸；完成後交還 `paintFoil()`，無輸入即停止更新 |
| 不應為每張卡製作影片 | 影片只製作共用舞台事件；角色、名字、卡框仍由 `HoloCardFace` 畫出 |
| UI 應保護獎品的視覺地位 | 常駐操作區安靜；抽卡開始後，側欄與底部操作退出視覺焦點 |
| 保留降級與取消路徑 | CSS 是完整可玩的基底；WebGL、影片失敗不影響卡片身份、數量或收下 |

### 拒絕或修正的結論

**1. 不接受「先改善角速度箔光，就能解掉一半抱怨」。**

這是未驗證的設計推論。現有 `revealOne()` 已有神話 80 顆粒子與多次衝擊波，問題仍可能是缺乏預期、焦點重疊、光源錯位與聲畫不同拍。優先序應是：

**完成狀態 → 演出節拍 → 光源定位 → 材質回應 → 更昂貴的渲染。**

此外，`--phase` 目前是光位輸入的映射，不是卡片真實旋轉角。其差分最多稱為「掃光速度」，不能直接當物理角速度。若日後加入 `--fx-energy`，由演出光路速度控制卡外效果，不新增卡面材質規則。

**2. 不接受「CSS 調 contrast／blur 等價於 roughness／metalness」。**

這只能近似明暗與高光形狀，沒有相同的反射行為。適合原型，但不能據此宣稱得到物理箔材質，也不能以此突破卡面凍結。

**3. 不接受「維持 CSS 卡面，three.js 後製路線就死了」。**

可以讓 WebGL 畫召喚陣、光柱、封套與粒子，CSS 卡面疊在其上。限制是後製只能作用於它自己的畫布，不能自然扭曲上層 DOM 卡片。因此 v3 的衝擊波只扭曲背景與光，不扭曲卡名。

**4. 不接受「Blender 只值得做神話卡翻面」。**

最有價值的是**所有抽次共用的封套折面、撕裂邊與光學素材**。它们有重複使用率，也不用與每張 CSS 卡面對齊。神話可再加共用空間破裂短片。

**5. 對 UI 的結論應由「技術不能」改成「哪些位置值得」。**

示範頁的啞光控制面板能支持克制，不能證明箔面不適合 UI。研究本身也允許面板殘影與高階徽章，並非真的只允許光位。v3 允許具有明確材質語意的小範圍箔面，規則見第五節。

**6. 修正三個會直接影響製作的細節。**

- 1080×1512、720×1008 都是 **5:7**，不是直式 3:2。
- 現讀 `HoloCardFace.paint(card,r,0,0,{tilt:false})` 的中立 `--phase` 是 **120deg**。交接應呼叫中立 API，不能寫死研究中的 `0deg`。
- 現有 `pull()` 只是建立 `Image` 並設 `src`，**沒有 await `decode()`**；註解不能當作已完成解碼的證據。

研究中的影片大小、工時與「CSS 可以達到八成」均只當估算，不作驗收事實。

## 三、稀有度預告與跳過規則

### 五階視覺語法

顏色沿用現有 `SURGE`；形狀與節奏提供第二種辨識，不只換色。

| 階級 | 預告語法 | 單卡節拍 ms：蓄力／翻面／讀卡／回槽 | 總長 | 揭曉特徵 |
|---|---|---:|---:|---|
| common | 灰銀 `#9fb0c8`、單細環、單刻痕 | 100／320／120／0 | **540** | 原槽位翻開，短柔光與少量灰塵 |
| rare | 冰藍 `#6fd8ff`、菱形、雙短刻痕 | 140／360／180／0 | **680** | 藍色短光束、單次外擴環，不震屏 |
| epic | 紫 `#c39dff`、六角封印、三段刻痕 | 400／480／380／260 | **1520** | 取得中央焦點，紫色光柱與双環 |
| legendary | 金 `#ffd45c`、雙環冠印 | 1080／580／280／360 | **2300** | 寬窄射線、金色外緣火星、單次衝擊 |
| mythic | 粉 `#ff7ad0` 起勢，青／金分色裂隙、破環星印 | 1200／580／620／400 | **2800** | 翻面前多 120ms 收束停頓；空間裂隙、一次分色爆發、較長讀卡 |

規則如下：

1. **整包預告只承諾最高階，不承諾張數或位置。** 同樣的最高階，預告尺寸、亮度與時長相同。
2. 預設不做假金、假彩虹或低階升階欺騙。抽到什麼，在 `draw(n)` 時已確定；演出不改 `RATE`，不新增保底。
3. 第一拍使用稀有度色；正面初見後，外圍餘燼才可混入 `pal.glow/accent`。缺 palette 時用 `SURGE`。
4. 普通每 **180ms**、精良每 **220ms** 可錯峰啟動。遇史詩以上，先等正在翻的低階卡完成，再取得唯一焦點。
5. 史詩以上依序 await 完整揭曉與回槽；高階持有焦點時不啟動下一張。連續神話不能互相搶鏡。
6. 揭曉後維持 `--rx/--ry=0`、圖內位移為零。外層翻面不等於解凍內部卡片姿態。

以十張普通為例，完整演出約 **5120ms**；九張普通後接傳說約 **7240ms**。極端全神話自然更長，讓跳過解決重看成本，不暗中縮減正常高階演出。

### A5 是狀態契約，不能被新時間軸覆蓋

保留第二十七輪實作者選定的狀態名稱；語意至少必須區分：

`未開始 → 揭曉中 → 已完成`

`revealed=true` 若仍代表「開始過」，就不能再用它決定收下。

| 現有函式 | v3 責任 |
|---|---|
| `pull(n)` | 固定結果、建立當次生命週期、準備全部槽位資料、執行共用前奏 |
| `cascade()` | 依階級排程；高階互斥；在 `finally` **無條件**清除排程旗標並重算 UI |
| `revealOne(s,fast)` | 同一槽位重入時返回同一工作 Promise；完成翻面、回槽與 refit 才標完成 |
| `skipAll()` | 同時處理未開始及進行中的卡，將全部收斂到同一正面終態 |
| `finishReveal()` | 只重新推導完成狀態與文案，不強制宣告全部完成 |
| `updateFinish()` | 收下須滿足：所有卡完成、cascade 已退出、無未完成工作、無會再寫入的演出回呼 |

**跳過的玩家語意：一次操作，立刻前往完整結果。**

- `#revealall` 改為明確的「跳過演出」，從前奏開始就可用；不能沿用 `!slots.length` 導致前奏無法跳過。
- 保留點擊演出背景跳過；略過按钮、連結與其他控制項，避免事件冒泡重複執行。
- 跳過後取消本抽次前奏、排程等待、WAAPI、rAF、延遲 `shock/burst`、影片及音效。
- 已建立的 face 重用；尚未建立的 face 建立一次。所有卡恢復原槽位、正面可見、卡背隱藏、材質中立、完成 refit。
- 素材已就緒時，結果以 **180ms** 淡入；所有工作清理完後 **100ms 內**提供收下。素材未就緒則顯示準備狀態，不能交付空白卡。
- 每次抽卡具有 run ID；reset／收下使舊 ID 失效。每個 `await` 後及延遲回呼開始前都檢查歸屬，舊任務不能清掉新抽次的 `cascading`。
- `.done` 不能提前讓 hover scale 與回槽動畫互相覆蓋。

`prefers-reduced-motion` 是獨立分支：跳過飛行、撕裂、震動與大閃光，以 **180ms** 淡入結果，保留稀有度色、形狀、文字與相同完成契約。不能只將現有 `wait()` 截短、讓 WAAPI 繼續跑原長度。

## 四、技術選型與體積預算

**決定：CSS 卡面＋單一 three.js 舞台；Blender 負責共用素材。Pixi 不加入本方案。**

Pixi 適合純 2D 圖集方案，但此案的重點是透視召喚陣、封套折面與空間光。選定 three.js 後再加入 Pixi，只會多一套渲染與清理流程。

| 階段 | 正式方向 | 原因與限制 |
|---|---|---|
| 按鍵、UI 退出、發牌、回槽 | CSS／WAAPI | DOM 與點擊區一致，終態容易驗證 |
| 召喚陣、流光、光柱、射線 | 29 輪起 three.js | 一個 canvas，共用相機與光源；卡片仍是 DOM |
| 撕封 | Blender 靜態素材＋three.js 簡單分片幾何 | 不做即時布料模擬；用可控折面与撕裂輪廓 |
| 卡背與正面交接 | CSS 外層翻面 | 保留凍結卡面，不製作 WebGL 卡面替身 |
| 材質接光 | `paintFoil()` | 時間軸持有期間只有一個 writer；完成後交還 pointer |
| 神話空間破裂 | 30 輪共用 Blender 短片 | 只在卡後播放，不含角色、卡名、卡框 |
| 音效 | WebAudio 合成 | 充能、紙裂、衝擊、和弦；以揭曉 marker 同步 |

現有 `shock()`、`burst()`、`rayBurst()` 應接受當次 scope 與定位 anchor。整包事件可以位於中央；單卡事件不得再默認 `#orbit` 中心。舊 `.rays` 不能只「補一次呼叫」就算完成定位改造。

### 尺寸預算

以下採十進位 MB；是**交付上限，不是套件實測大小**。4.7MB 為題目提供基線，第二十七輪結束後須重新量測。

| 輪次 | 新增程式上限，未 gzip | 新增二進位素材上限，內嵌前 | standalone 總檔上限 |
|---|---:|---:|---:|
| 28 | 0.08MB | 0.32MB | **5.3MB** |
| 29 | 再加 0.90MB，含選定 three.js bundle | 再加 0.22MB | **6.5MB** |
| 30 | 再加 0.08MB | 再加 1.66MB | **9.0MB** |

二進位轉 Base64 約增加三分之一；不能拿 gzip 傳輸大小冒充本地 HTML 檔案大小。新版共用圖取代舊素材時，避免兩份一起內嵌。

- 開發版使用相對資源；standalone 由建置時打包成無外部 import 的程式與資源。
- 新素材進入單一 resolver／asset manifest，不再增加字面字串替換。
- 不使用 CDN 才能觀看演出。
- PNG 序列、`.blend`、高解析母稿不塞入 HTML。

### 影片與 WebGL 的失敗路徑

神話影片採**不透明背景短片**，避免把透明影片支援當必要條件。卡面永遠疊在影片上方，最後淡去的是背景，毋須逐卡末幀對齊。

`video.play()` 可能拒絕，必須捕捉並轉為 CSS／WebGL 分支；影片不能掌握卡片完成狀態。[MDN：play()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)

需要追踪影片實際呈現幀時使用 `requestVideoFrameCallback()`，但不把它當成精準聲畫同步的保證；測試另記錄實際 marker。[MDN：影片幀回呼](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)

WebGL 初始化失敗或 context lost 時切回 CSS，沿用同一結果與時間軸狀態。可用 `WEBGL_lose_context` 注入此故障驗證。[MDN：context loss 測試介面](https://developer.mozilla.org/en-US/docs/Web/API/WEBGL_lose_context)

## 五、箔面套用 UI：具體允許／禁止清單

**裁決：可以，但依「材質語意、面積、觸發時間」分配；不是只准移動光位。**

下列均為卡外 UI，不變更凍結卡片內的名字、稀有度字效與寶石。

| UI／建議類別 | 允許 | 禁止 |
|---|---|---|
