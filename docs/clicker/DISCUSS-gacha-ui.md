# 討論題：抽卡介面怎麼樣才「像一款遊戲的抽卡」

**這是討論，不是派工。不要改任何檔案、不要建置、不要寫程式。**
請直接回答下面的問題，輸出一份分析。

使用者原話：

> 抽卡系統的介面我認為要更優化。幫我跟 GPT-6 討論，怎麼樣可以更像遊戲抽卡？
> 少在哪？銜接的動畫、入場的表現方式嗎？
> **目前翻卡的特效我已經很滿意了，要強化的是 UI 跟動畫部分。**

所以：**揭卡／翻卡的特效本身不在討論範圍**（那部分已經滿意）。
要談的是它前後左右的東西——介面長相、進場、轉場、銜接、待機、收尾。

---

## 一、現在的流程與時序（實際跑出來的，不是規格書）

1. **入口畫面**：黑底，中央一個精裝卡包，卡包下方橫排三顆按鈕
   「單抽 ◇1」「五連 ◇5」「十連 ◇10」，右上角顯示券數。
   按鈕是細線框的長方形，沒有底色、沒有圖示、沒有按下回饋以外的動態。
   背景是黑底細白線的召喚陣 SVG（`ceremony-background.svg`），有極慢的循環。
2. 按下抽卡 → **卡包退場 220ms → 推近 380ms** → **無限等待點擊卡包**
   （不是自動開，這是定案的契約）
3. 點擊 → 撕封拆包 → 揭卡演出（**這段已經滿意，不要改**）
   - 不預告只適用 common／rare／epic
   - legendary／mythic 明確預告，蓄力 900／1300ms，閱讀 1400／1900ms
   - 四層分層：其他卡 → 背光／射線 → 演出卡 → 衝擊波
4. **結果**：五張一排（245px 不重疊）／十張雙排，手機是有間距的單卡瀏覽
5. **收下 220ms** → 回到入口

其他已經在的東西：卡面箔面反光跟游標、卡片可拖轉、hover 微放大、
點空白＝全部跳過、演出蓋滿視窗、首次靜音、背景六層。
卡包本身這一輪正在加：hover 放大、呼吸懸浮、外圍循環光暈。

## 二、不准動的東西（提案碰到這些就直接不用提）

- 揭卡演出本身的特效、時序、分層契約
- 「不預告品質」：`face-visible` 之前不同稀有度必須逐像素零差
- 「無限等待點擊卡包」不得改成自動逾時
- 正式版 RATE 與初始 30 券
- `src/`、`card_face.js` 的凍結工法（卡面幾何、Z、字級）
- 不引入 npm 相依。產物必須是**單檔自包含的 HTML**（圖與腳本全內嵌）。
  WebGL 只在神話折射那一項被授權評估過，其餘一律 CSS／DOM／SVG。

## 三、請回答這四題

### Q1. 跟真正的手遊抽卡比，這套「少在哪」？

請**具體列出缺的東西**，不要講抽象的「缺乏沉浸感」。
每一項寫清楚：缺什麼 → 玩家實際會感覺到什麼 → 為什麼那會讓人覺得「這不是遊戲」。
如果你認為某些常見手法（例如保底提示、十連跳過、卡池切換頁籤）
**不適合**這個專案，也請講，並說理由。

### Q2. 入場的表現方式

從「玩家看到抽卡畫面的第一秒」到「按下抽卡」這一段，現在幾乎是靜態的。
請提出**具體**的入場設計：元素以什麼順序出現、各自的時間與位移、
先後關係是什麼、為什麼是這個順序。

### Q3. 銜接的動畫

現在每個階段之間是「退場 → 推近 → 等待 → 拆封 → 揭卡 → 結果 → 收下」，
這些接點目前多半是硬切或單純的淡入淡出。
請指出**哪幾個接點最傷**（依「玩家最容易注意到」排序），並各給一個具體的接法。

### Q4. UI 本身

入口的三顆按鈕、券數顯示、結果頁的版面——
請針對**看得見的介面元素**提出改法。包含層級、對比、留白、圖示、狀態回饋
（hover／按下／不足券／進行中）。

## 四、回答的格式要求

- **依「投資報酬率」排序**：先講「改動小但感受差很多」的，再講大工程。
  每一項標上大約的實作規模（小／中／大）。
- 每一項要能被翻成**可量測的驗收條件**（時間、位移、對比、覆蓋率之類）。
  這個專案的教訓是「只寫上限的門檻＝做出看不見的東西」，
  所以你提的數值請**同時給下限與上限**，不要只給「不超過多少」。
- 不確定的地方請說「這需要實機量」，**不要編數字**。
  你不會跑實機，所有 fps／時間類的宣稱都會由我這邊重新量。
- 如果你認為我這份題目本身問錯了方向，請直接說，並說你會問什麼。

**再說一次：不要改檔案、不要建置、不要寫程式碼實作。輸出分析就好。**
（示意用的 CSS 片段可以，但不要寫進任何檔案。）
