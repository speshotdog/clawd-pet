## 五、⚠ 不能講的、還沒解決的

### 1. 像素層級一致性**不成立**，而且量測工具自己不穩定

`check_shot_determinism.py` 實測：**同一個入口、同一支腳本連跑三次，
結果會在兩種狀態之間跳**——

```
demo            run0 vs run1  mean 0.00
                run0 vs run2  mean 29.69   >100 的像素 10.6%
pool-standalone run0 vs run1  mean 33.59   >100 的像素 12.4%
                run0 vs run2  mean 0.00
```

**所以入口之間的像素差在修好這個之前不是有效訊號**——量測雜訊蓋過了要找的差異。
載重的證據是 `check_card_assets.py` 的層比對（那個是決定性的，跑兩次結果一致）。

已排除的原因：**不是箔面相位**。`diag_foil_phase.py` 證明
`--phase`／`--fx`／`--fy`／`--gx`／`--gy`／`--sx`／`--sy`／`--tilt`／`--foil`
在「paint(0,0) 後 / 雙 rAF 後 / 截圖前」三個時點**零漂移**，
而且整段只有量測端自己那一次 `paint` 呼叫（編隊是兩次）。

**下一步建議**：兩種狀態的二元跳動，優先查圖片 decode 時序
（`img.decode()` 的例外目前被 `catch` 吞掉）與 lazy 解碼；
先讓 `check_shot_determinism.py` 過（門檻 mean < 1.0），再談入口之間的像素比對。

## 八、這一輪值得記住的坑

1. **`pull()` 不等於揭卡。** 只 pull 會停在卡包與「準備卡片…」，卡片雖然進了 DOM
   但不是揭開狀態。要走完 `openPack → skipAll → ready()` 並斷言 `state().screen==='results'`。
2. **`select(id)` 不會開手機詳情**，要 `select(id, true)`。
3. **選取放大是 CSS 的 `scale` 屬性不是 `transform`**（`team20.css:142`），
   關 `transform` 關不掉；`rotate`／`translate` 同一組也要一起關。
4. **demo 的正式卡 DOM id 是 `pool-<id>`**（`demo.html:669`），
   拿它直接比卡池 ID 會把整頁正式卡當成實驗樣本排除掉。
5. **預期清單一定要從原始碼讀。** 從待驗 JSON 讀的話，
   只要把 JSON 裡的 `expectedPoolIds` 一起改小，刪掉的卡就再也驗不出來。
6. **`getComputedStyle` 回傳 `auto`／百分比 = 那個元素在沒佈局的子樹裡**
   （手機詳情浮層還沒開就量到的話）。
7. **Python 的 `json` 會接受 `NaN`／`Infinity`**，量測值要自己擋非有限數。
8. **`git show` 是 LF、工作目錄是 CRLF**，雜湊要分開標，不能統稱。
