## A. 粒子：數量與覆蓋率拉上來

| 項目 | 現況 | 本輪目標 |
|---|---:|---|
| 圓點數量 | 20 | **45～60 顆** |
| 圓點直徑 | 3.2～5.3px | **4～9px**（大小要有落差，不要全部一樣） |
| 愛心數量 | 5 | **8～12 顆** |
| 愛心直徑 | 12.7px | **14～20px** |
| **愛心透明度** | 0.23～0.29 | **0.45～0.65**（這是下限，不准再做成隱形） |
| 圓點透明度 | 0.81～0.85 | 維持 |

### 門檻（上下限成對）

| 條件 | 下限 | 上限 |
|---|---|---|
| **粒子層覆蓋率**（粒子開／關差圖中差 >6 灰階的像素佔卡面比例） | **≥ 1.2%** | ≤ 3.0% |
| **整卡平均增亮** | **≥ 0.30%** | ≤ 1.2% |
| 圖窗 2 秒差異像素 | **≥ 1.0%** | ≤ 4.0% |
| **粒子的移動要看得見**：2 秒內每顆的位移 | **≥ 卡高的 3%（≈16px）** | ≤ 卡高的 12% |
| 單顆峰值相對鄰近背景 | ≥ 25 灰階 | — |
| 愛心 IoU（形狀） | ≥ 0.80 | — |
| 愛心垂直範圍 | 卡高 60%～80% | 同左 |
| 文字框差異像素 | — | **≤ 0.02%** |
| 卡名／稀有度／寶石對比 | 見〇之三 | — |

**覆蓋率是本輪最重要的一條。** 現在是 0.16%，目標 1.2%～3.0%，也就是要提高 8～19 倍。
達成方式優先靠**數量與尺寸**，不要靠把粒子調得更亮——調亮會讓淡彩變糊，而且
`screen` 在亮底上本來就沒有空間（第三十六輪已實測）。

## B. 回彈：要有彈性，不是滑動

現在過衝是 **0.000%**，所以放開之後只是平順地滑回去，感覺不到「彈」。

| 條件 | 下限 | 上限 |
|---|---|---|
| 回正過衝（反向越過 0 的幅度，佔目標角度） | **≥ 8%** | ≤ 20% |
| 過衝次數 | 1 次 | ≤ 2 次 |
| 回正到兩軸 <0.1° 的總時間 | 550ms | 800ms |
| 跟隨到目標角度 90% | — | ≤120ms（不變）|
| **逐格投影超緣** | — | **≤1.5px（含過衝的每一格）** |
| reduced-motion | 立即回正、無動畫 | 同左 |
| rAF | 0 | 0 |

⚠ **過衝與「不得浮出卡緣」會互相拉扯**——這正是要逐格量的原因。
過衝做不到 8% 又同時守住 1.5px 的話，**先回報數字，不要偷偷放掉其中一邊**。
可行的解法是把過衝放在旋轉角度上、同時把 `--za`／`--zp` 之類的 Z 位移排除在彈跳之外。

## D. 修掉第三十七輪的假紅（重繪屏障）

`check_gift_card.py` 第 486 行用
`a.currentTime = -delay + duration*1.5` 把愛心停在週期中點——**做法是對的**，
但設完 `currentTime` **沒有等一個重繪就直接截圖**，合成器還沒把新位置畫上去，
截到的是上一格，遮罩位置對不上。我獨立連跑五次掛了一次：

```
AssertionError: ['heart silhouette IoU >=0.80',
  [0.9099756690997567, 0.01060834447256904, 0.8470319634703196, 0.8565022421524664, 0.9203980099502488]]
                       ^^^^^^^^^^^^^^^^^^^ 只有這一顆掉到近乎零＝畫在別的位置，不是形狀不像
```

其他四顆與五次記錄的 JSON 完全一致，所以不是形狀問題。

**修法**：設完 `currentTime` 之後等雙重 `requestAnimationFrame`（或明確等一個 commit）
再截圖。**門檻一個字都不改。** 同一個模式在 `capture_motion()` 那邊也檢查一次，
凡是「設定狀態後立刻截圖」的地方都要有重繪屏障。

驗收：連跑 **5 次** `check_gift_card.py`，5 次都要 exit 0，退出碼全列進報告。
