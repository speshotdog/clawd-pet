## 一、今天的派工工法（這一段是流程，不是程式）

這是今天真正跑順的做法，下次照這個走：

1. **使用者只講現象，不講實作。** 例：「傳說的四散光芒圖層不能比卡面高」。
2. **Claude 先進 repo 把現象定位到行**，把「症狀 → 現況程式位置 → 可能成因（列 2–3 個假設）」寫進簡報，並**明文要求「先量再改，不要照我的猜測動手」**。今天兩次證明這條有用：
   - 第三十一輪 A 題：我猜的三個成因裡命中第一個（`completeSlot()` 移除 `is-revealing` 後 slot 從 z-index 10 掉回 2，上層 canvas 是 4 就翻到卡前面）。
   - 第三十一輪 B 題：我建議的「anchor 推到 +Z」被實測否決（會與旋轉中的 flip 相交出現直切缺口），改用外層 slot 攤平。**簡報要允許實作者否決我的建議，只要他拿得出量測。**
3. **每個要求都要附可量的門檻**，不要寫「更亮一點」。今天的例子：環線寬 24–28px、卡背亮度 +45%／+60% 且標準差不得低於起始的 40%、卡包最亮 5% 像素壓到 70–80% 且對比下降 ≤ 10%。
4. **反向斷言跟正向一樣重要。** 第三十三輪要求「射線**必須**有蓋到鄰卡」，否則實作者會把它修成「全部都不准蓋」——那正是第三十一輪留下的過度修正。
5. **凍結規則要解除時，寫明是使用者裁決。** 第三十二／三十三輪解除了「不預告」（傳說神話翻牌前要看得出來），驗收改寫成「普通／精良／史詩之間仍零差、傳說神話必須有差異」，**不是刪測試**。
6. **驗收要自己重跑。** 今天第三十一輪五支驗收我全部獨立重跑一次，確認 exit 0 才向使用者回報。代理的報告不能當結論。
7. **`.cmd` 派工檔一律純 ASCII。** 今天第三十二輪第一次啟動失敗，原因是我把中文路徑寫進 `codex exec` 的參數，Big5 解碼把 `clawd-pet-holo` 拆成 `claw` + `d-pet-holo`。中文一律只出現在 `.md` 簡報裡。
8. 派工檔 `docs/clicker/run-round*.cmd` 與 `codex-round*.log` 依 `.gitignore` **不進版控**，簡報與報告才進。

## 二、演出層的分層規則（今天改了兩次，這是最終版）

這一段是今天最容易再踩的地方。`preserve-3d` 的規則見 LESSONS 第一節；下面是**畫面層級**的規則。

### 2-1. 第三十一輪的版本（已被三十三輪取代一半）

- 上層 canvas 從 `z-index:4` 降到 `1`，讓射線永遠在卡後面。
- 外環改成：外層 `.slot` 設 `transform-style:flat`，`.reveal-anchor` 在 Z=0 的前方平面，`.reveal-shell` 內部維持 `preserve-3d`。實測補償倍率 1.000。
- **留下的洞**：`--b` 驗收只在**單張卡**的情境量環的直徑與線寬，沒有量「環經過鄰卡時還在不在」。所以十連時環被鄰卡切斷，綠燈照樣放行。

### 2-2. 第三十三輪的最終分層（使用者裁決）

| 由下而上 | 內容 | 規則 |
|---|---|---|
| 1 | 其他卡（非演出中的 slot） | **會被射線蓋到，這是對的** |
| 2 | 背光層：`rays()`／底光／`flash()` | **只有「演出中那張卡的卡面 rect」不得被覆蓋** |
| 3 | 演出中的那張卡 | 主角，壓在 1 與 2 之上，不得被任何鄰卡遮到 |
| 4 | 衝擊波環（canvas `ring()` 與 CSS `.rarity-fx`） | **壓過畫面上每一張卡** |

**第三十一輪那條「射線不得覆蓋任何卡面」已作廢**，收窄成只保護演出中那張卡。改動時要同時跑正向與反向兩支斷言。

## 三、新卡進精裝卡池的工法（第三十二輪定案）

素材來源：`C:\Users\ASUS User VII\Desktop\新卡\4.0`，**檔名就是規格**（`<卡名> <稀有度>.<副檔名>`），
稀有度對照 `精良=rare`／`史詩=epic`／`傳說=legendary`／`神話=mythic`。**卡名一律照檔名，不要翻譯或改字。**

1. **先分類，不要當成同一種處理**：已去背 PNG／白底單角色／滿版整幅畫，三類的處理完全不同。
2. **framed（去背角色）**：照 `角色製作工法.md` 第 1 節四步驟——洪水填充只移除**與邊緣相連**的近白像素（門檻 235）→ 連通元件只留最大塊 → defringe（邊界且 `min(r,g,b)>165`）跑 5 輪。JPG 來源因為壓縮雜訊要跑 7 輪、門檻降到 150。
   - **身上有大面積白色的角色最容易被挖破**，要逐張目視確認並回報數字。
   - 輸出 RGBA、緊裁、**高度統一 580**（對齊既有 `art/card-*.png`）。
3. **flat（滿版場景）**：**不去背**，裁成 5:7 後重採樣到 600×840。只裁不重畫，主體不得被切到。
4. **不做 depth**：depth 要拆 subject／background 兩層＋掛 subject-mask，是另一件事。
5. **卡池資料只加在 `pool_data.py`**：照 `SCENE_CARDS` 的先例新增 `EXTRA_CARDS`，註解寫明「只在精裝研究線生效、未進遊戲」。**不改 `src/gacha-pool.js`**，`RATE` 不動。
6. **`kind` 是資料**，不准在任何 builder 裡寫死（`pool_data.py` 檔頭記著那次事故）。
7. 跑 `build_card_scenes.py` 重算 `art/palette.json`；`embed_masks.py` 要能從 `art/` 取新卡 alpha 產箔面遮罩，**路徑解析收斂成一個函式，不要再貼一份名單**。
8. 建置順序：`build_card_scenes.py` → `embed_masks.py` → `build_cards_remade.py` → `build_cards_remade_standalone.py` → `build_deluxe_b.py` → `build_deluxe_b_standalone.py`。
9. **`4.0\怪物\`（3 個 gif ＋ `rise.png`）本輪未收**，那是動畫素材不是卡圖，待裁決。
