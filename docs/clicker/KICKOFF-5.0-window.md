## 任務二：變種卡（先研究，不要急著做）

使用者的話：

> 昨天加了一張特殊卡，我想把一些卡做變種，有更炫麗的特效與外框，
> 之後會有方式入手，收藏價值用。

「昨天那張特殊卡」＝**魔花少女**（禮物卡，新階級 `special`，粉紅卡框粉紅字，
在 `clawd-pet-gift` 那條線）。

要先想清楚的：

- **變種是「同一張卡的另一個版本」還是「另一張卡」？**
  影響卡池、圖鑑計數、以及編隊時算不算同一張。
- **炫麗到什麼程度不會打架？** 現有神話已經有蓄力 1300ms ＋ 預告 ＋ 衝擊波。
  變種要更炫，但**不能違反「不預告品質」**（`face-visible` 前逐像素零差的契約只適用
  common／rare／epic；legendary／mythic 本來就明確預告）。
- **入手方式**會影響稀有度感受，但那是另一個系統，**這一輪只出視覺規格，不要做掉落**。

⚠ **不要一次做十張變種。** 先做一張當樣品給使用者看，門檻上下限成對，交「原版 vs 變種」並排圖。

## 這條線的紀律（每一條都對應一次事故）

1. **視覺門檻上下限成對**，並交「開 vs 關」並排圖；並排圖沒差＝沒做到。
2. **fps／時間類結論至少三次取平均**，跨機器的絕對值不能比。
3. **決定性取樣**：Web Animations API 暫停 ＋ 設 `currentTime` ＋ 雙重 rAF 重繪屏障。
4. **派工給 codex 的 `.cmd` 一律純 ASCII**——裡面有中文會讓 cmd.exe 用 CP950 拆錯行，
   整支死在 `'exec' 不是內部或外部命令`，看起來像環境壞掉。中文寫在 `.md` 簡報裡讓它自己讀。
5. **一次只跑一支 codex**，要接續就等前一支的行程真的結束
   （`tokens used` 那行印出來之後還有一百多行，不能拿它當結束判斷）。
6. codex 的驗收全綠也要自己截圖；它的 commit 一定被 sandbox 擋，由你複驗後再 commit。
