## A. 召喚陣的線條要有光暈

**症狀**：`ceremony-background.svg` 的召喚陣是純細白線（`stroke="#fff" stroke-width="1"`，
群組 opacity `.24`／`.28`／`.1`），在 `#010203` 的純黑底上顯得乾、扁，沒有「在發光」的感覺。

**現況位置**：

- 幾何：`_art/holo-test/ceremony-background.svg`（第三十一輪自寫，無第三方素材）
- 圖層與動畫：`_art/holo-test/ceremony.css`
  - `.stage-geometry{opacity:.85;animation:sigil-breathe 28s ...}`（第 11 行）
  - `.focus-held .stage-geometry{opacity:.22;animation:none}`（第 18 行）
  - 各元件的循環動畫在第 123–140 行（`orbit-turn`／`orbit-dash`／`orbit-sway`／
    `star-pulse`／`axis-flow`／`floor-wave`／`water-flow`）

**做法**（兩條路，**先量再選**，不要直接照我的猜測動手）：

1. SVG `filter`（`feGaussianBlur` + `feMerge`）或 CSS `drop-shadow()`，一次套在幾何層上。
   視覺最像光，但**濾鏡會在每一格重算**，而這一層整層都在動。
2. 同一條路徑畫兩層：底層粗、低透明度（必要時輕微模糊），上層維持現在的細實線。
   便宜很多，但要處理「怎麼在不複製整份 SVG 的前提下做出底層」。

**兩條都要實測掉幀再決定**，報告要寫出你量到的數字與你選了哪一條、為什麼。

**門檻**（避免做過頭；這是「線條在發亮」，不是「背景整片變亮」）：

1. 背景整體平均亮度增幅 **≤ 15%**（在同一個狀態、同一顆種子下，改前改後各截一張全畫面比較）。
2. **線條本身要變亮**：取線條所在的像素（用改前的幾何當遮罩），平均亮度增幅 **≥ 40%**，
   而且線寬（亮度高於底色 + 10 的水平連續像素數）要變寬 **≥ 1.5×**。
   ——這是反向斷言：只讓整體變亮但線沒變亮，或線變亮但看不出外溢，都算沒做到。
3. **卡片區域的對比不得下降**：揭曉中那張卡的 `.hcard` rect 內，標準差不得低於改前的 **98%**。
4. `.focus-held` 降階時**光暈要跟著收**：`.focus-held` 狀態下背景平均亮度不得高於改前同狀態的 **105%**。
5. **不准掉幀**：1440×900、十連揭曉全程，`requestAnimationFrame` 間隔的 p95 不得超過 **20ms**
   （改前先量一次當基準，改後不得比基準差超過 2ms）。做不到就走做法 2。
6. `prefers-reduced-motion: reduce` 時光暈可以留（它是靜態外觀），但**不准新增動畫**。

**不准**：引入第三方素材或字型、新增常駐 `requestAnimationFrame`、改動 `HANDOFF` 第二節那張分層表。

## B. 1024×640 的留白規則改成比例

**現況**（`_art/holo-test/ceremony-layout.js`，第三十三輪版）：

```js
cw  = Math.max(190, Math.min(n>5?198:208, (width-40)/5.14, (height-140)/(n>5?3.0:1.7)))
gap = Math.max(8, Math.min(cw*.14, (width-40-5*cw)/4))
```

1024 寬時 `(1024-40)/5.14 = 191.4`，五張 957px ＋ 四個 8px 間隙 ＝ 989px，左右各只剩 **17.5px**，
達不到第三十三輪訂的「左右各 ≥ 99.56px」。第三十三輪 I 題那四項失敗就是這樣來的——
**是我把規格訂成不可能**（190×5 + 8×4 + 199 = 1181 > 1024），不是實作偷工。

**使用者裁決**：留白從絕對值改成**比例**。

| 規則 | 新值 |
|---|---|
| 左右留白 | 各 **≥ 6% 視窗寬**（1440 → 86.4px、1024 → 61.4px、390 手機沿用現行單卡瀏覽） |
| 桌面卡寬下限 | 一般 190px；**1024 寬（含以下、>600 以上）放寬到 170px** |
| 上下留白 | 十連上下各 ≥ 70px 不變 |
| 卡片間距 | 任兩張 rect 交集必須為 0，而且看得出間隙（≥ 8px），不變 |

**1440 的體驗必須完全不變**——這是硬要求。改完要拿 1440×900 的版面數字（cw、gap、
左右留白、上下留白、每張卡的 x/y）跟改前逐項比對，**任一項不同就算回歸**。

`focusWidth()` 是字級 refit、`fx()` 寬度、flakes 偏移的共同基準，改完要整批重驗，
不要只改 layout 就收工（第三十三輪 I 題第 4 點）。

**驗收尺寸**：1440×900、1024×640、390×844 三個都要，五連與十連都要。

## C. 史詩階的揭曉光效比普通還弱

**現況數字**（第三十三輪報告，黑底舞台，卡外亮度峰值）：普通 **49**／精良 **49**／史詩 **42**，
且史詩的「亮度 > 底色 + 40」持續時間是 **0ms**。第三十輪在深藍底時就是這個相對關係
（普通 66／史詩 60），**不是本輪回歸**，但「史詩比普通還暗」在體感上是錯的。

**要求**：亮度峰值與持續時間都必須**隨稀有度單調不遞減**：

```
common ≤ rare ≤ epic ≤ legendary ≤ mythic
```

- 史詩的峰值至少要比精良高 **10%**，「亮度 > 底色 + 40」的持續時間 **≥ 200ms**。
- **普通／精良之間仍必須零差**（第三十二／三十三輪解除的是「傳說神話不預告」，
  普通到史詩之間的零差沒有被解除——不要為了做出單調而把普通調暗）。
- 傳說與神話**不得被拉低**：兩者的峰值與持續時間不得低於改前。

先量清楚**為什麼**史詩比較暗（是 palette、是 `ZLIFT`、是特效階梯的參數、還是史詩沒有走到某段），
報告要寫出成因再寫修法。**不要只是把史詩的數字調大**。
