# 複檢結果：隊伍預設與卡面特效

**結論：3 項必修、1 項建議。**

## 必修

### 1. 1.0 套用預設時，無法交換已佔用的技能槽

- **位置：** `src/clicker-team.js:340`、`src/clicker-team.js:341`
- **重現：** 目前技能槽為 `[A, B, null]`，套用同隊伍、技能槽為 `[B, A, null]` 的預設。
- **結果：** 清槽迴圈只判斷目標卡是否在隊伍，保留兩個舊槽；後續兩次 `E.equip` 都拋出「角色已在其他槽位」。實際執行結果仍為 `[A, B, null]`，且 `missing = 2`，錯誤提示成卡片不在卡冊或派遣中。
- **建議修法：** 先計算過濾後的完整目標技能槽，清空所有與目標不同的已佔用槽，再逐格裝備。不要將所有裝備例外都歸類為缺卡。補上交換兩槽及三槽循環換位測試。

### 2. 末世技能篩選會殘留到 1.0，導致候選全部消失

- **位置：** `src/clicker-team.js:304`、`src/clicker-team.js:377`
- **重現：** 在末世挑選器選「破防」，關閉後於同一頁切回 1.0，再開啟新增成員或技能挑選器。
- **推理：** `roleFilter` 保留為 `breach`；1.0 只隱藏篩選列，候選仍套用該條件。1.0 的 `roleOf()` 回傳 `click`、`team` 等 `kind`，沒有 `breach`，所以候選全被排除，且無法操作已隱藏的「全部」按鈕解除。
- **建議修法：** 候選篩選加上 `apoc()` 條件，確保只作用於末世。補上不重新載入頁面的跨世界測試。

### 3. `teamPresets` 缺少驗證，壞存檔可使編隊畫面拋錯

- **位置：** `src/clicker-team.js:316`、`src/clicker-team.js:353`；驗證入口 `src/clicker-save.js:28`
- **重現：** 對合法存檔設定 `teamPresets: [{}]`，經匯出、解碼及 `S.validate()` 後，該資料仍原樣保留。
- **結果：** `renderPresets()` 存取 `p.roster.length` 時拋出 `Cannot read properties of undefined (reading 'length')`，中斷編隊渲染。已以 Node 最小案例確認。
- **建議修法：** 在存檔驗證階段正規化 `teamPresets`：固定最多三組、檢查物件與陣列形狀、限制名稱長度、整理卡片 ID 與技能槽；壞組別轉為 `null`，舊存檔缺欄位補空組。補上匯入壞資料測試。

## 建議

### 4. 效果圓環分母未反映實際施放時長與來源

- **位置：** `src/clicker-apoc-ui.js:760` 至 `src/clicker-apoc-ui.js:765`
- **重現：** 精良破防基礎時長為 7 秒，無加成時王關抵抗後為 4.2 秒；剛施放的 `effectLeft()` 已回傳 `frac: 0.6`。已直接執行確認。
- **影響：** 秒數文字正確，但圓環剛開始就只有六成。同型不同稀有度共用效果時，各槽還會以自己的規則時長／次數計算，產生不同進度。
- **建議修法：** 記錄目前效果的實際總時長或初始次數，讓同型各槽共用分母。
