# 精裝專屬整頁抽卡設計：撕封、落印、揭卡

日期：2026-09-08。狀態：設計提案，未實作、未試播。尺寸、節拍與音色參數供下一輪製作及實機調整；價格、抽率、換券比值、重複卡處理不在本文件定案。

## 1. 先定義「沒有 AI 味」

本文件所說的「AI 味」，不是判斷素材由誰生成，而是指**把任何角色換進去都成立、效果沒有動作原因、每一秒都在爭注意力的通用演出**。典型症狀是：卡片還沒做什麼，中央已經白光爆開；粒子從同一圓心飛散，與撕口、碰撞位置無關；所有稀有度只是同一套動畫換色加量；名字和人物正在被光效遮住，畫面仍繼續加亮。

「最炫」在此定義為：有大幅度的構圖變化、可辨識的動作輪廓、一次確實落下的重擊，以及足夠大的卡面讓玩家看清自己得到什麼。不是把全部效果壓小，也不是靠曝光過量表示價值。

### 1.1 可以檢查的設計標準

| 判斷面向 | 本案解法 | 不合格的具體情形 |
|---|---|---|
| 遊戲自身的語言 | 深藍紙底、奶油色切邊、粗黑筆觸；卡背的爪／骨／星／心成為封條壓紋與碎紙形狀 | 換成任意科幻遊戲標誌，整段仍毫無差別 |
| 動作有因果 | 撕口帶出紙屑；翻面帶動色塊；落印帶出短墨痕。效果都從接觸點開始 | 所有粒子固定從畫面圓心產生，與卡的位置無關 |
| 有主次 | 每拍只有一個最大運動物件；姓名出現後，其背後色塊停止，卡正面回正 | 同時轉背景、震視窗、白閃、放射、變色，找不到卡名 |
| 稀有度有不同動詞 | 普通「揭」、精良「扣」、史詩「掃」、傳說「壓」、神話「撕開整張襯紙」 | 神話只是普通版的粒子數乘十 |
| 時間有設計 | 快撕、短停、落印、長讀；高潮前留 120–180ms 安靜區 | 等速移動、每張同樣一聲爆炸、全程音樂式鋪滿 |
| 手繪感有邊界 | 筆觸與紙邊用固定形狀，2–3 張形變姿態，局部不對稱；文字排版保持精確 | 用每幀亂數讓輪廓抖動，或把排版歪斜當成手繪 |

移除角色圖後，仍應能從熱狗獎章、奶油雙線與四角圖示辨認這個卡背世界。恢復角色圖後，第一眼應看角色，第二眼看卡名，第三眼才欣賞箔紋。這是本案對「沒有 AI 味」的驗收定義。

### 1.2 視覺語彙與使用時機

主場景是一張鋪滿畫面的深藍收藏襯紙。斜放的封套以奶油粗邊收口，中央沿用熱狗獎章。保留卡片精裝框、寶石、景深與箔面份量；舞台不用寫實玻璃罩、持續霧光或太空軌道。奶油色是靜態紙色，不做全畫面亮暗脈衝。

| 拍點 | 圖形、方向與重量 |
|---|---|
| 入口 | 封套偏右上傾 6°，下方壓住一角襯紙；只有靜態接觸陰影，沒有懸浮循環 |
| 撕封 | 從左上撕到右下，一條鋸齒奶油紙邊；6 片大小不同的扁平碎紙沿撕向飛出，再下墜，黑邊與卡圖一致 |
| 待揭 | 大卡背正面對玩家。四角圖示與中央獎章保留；不旋轉背景，不用呼吸白光催點 |
| 普通／精良 | 卡背側轉、正面落定；精良多一個右下角的短扣合墨痕，不爆光 |
| 史詩 | 卡後由左下往右上掃過一道有毛邊的稀有度色塊，220ms 完成；卡名區無覆蓋 |
| 傳說 | 左上角粗邊印章砸下，襯紙壓縮 4px、回彈一次；金色短刷痕沿卡框通過，320ms 結束 |
| 神話 | 卡後整張深藍襯紙沿斜縫裂成兩大片，向兩側讓出舞台；三層粉／奶油／薄荷色紙邊錯開 60ms 展開，最後卡框和名字保留既定彩虹，背景停住 |
| 結果與收下 | 結果卡整齊正面陳列；收下時全批成為一疊，滑入帶熱狗獎章的封套，封口一次，不逐張放煙火 |

神話的大場面來自「整個背景被角色推開」：兩側紙片可各佔舞台寬度 35%，卡本身保持大而清楚。不是因效能把大演出改成角落小章。紙邊、印章與筆觸是後續自製的圖形需求，本輪不製作素材、不引入素材包。

## 2. 已讀現況與邊界

依據：[派工簡報](BRIEF-deluxe-gacha-redesign.md)、[可試抽原型](../../_art/holo-test/deluxe-gacha-b.html)、[原型產生器](../../_art/holo-test/build_deluxe_b.py)、[HANDOFF 六之二／六之三](HANDOFF-holo-cards.md)、[既有設計第 5 節](DESIGN-deluxe-gacha.md)、[WebAudio 音效](../../src/gacha-audio.js)。原型以原始碼閱讀，沒有執行。

實際查看 `card-foxfriend.png`、`card-yangtuo.png`、`card-wanwumythic.png`、`card-zhenjpg.png` 與 `gacha-cardback.jpg`：角色線條粗糙而明確，主體有不對稱配件；卡背是深藍、奶油雙框、黑線熱狗與四色角標。這是視覺抽樣，不宣稱逐張圖已驗收。

### 2.1 原型中看得到的問題

- `.win` 是可拖曳的 3:2 浮窗，頂列 8.6%、底列 14%，另有 16% 側欄，舞台再吃 padding。改整頁必須連這些空間分配一起改，單純放大外框不夠。
- `layout()` 單抽／五連／十連卡寬上限是 230／150／118px。卡名按 `24/290` 計算，118px 卡寬只剩約 9.8px；滑鼠 hover 放大 1.13 倍不是手機閱讀方案。
- `makeFace()` 有兩條文字路徑：文字放在 `.face-plate` 內，或放在同層 `.face-text`。後者不會自動繼承前者的內距；只補框的 padding 不能保證名字安全。另有多輪 CSS 覆寫，不能僅憑較早一條置中規則判定最終正確。
- `.art-media` 的 grid 居中仍在排圖片矩形，沒有消除 PNG 透明留白。人物區已避開下方文字框，這個方向保留，再換成主體座標。
- 原型在開包充能就取整包最高稀有度染色；逐張又有 `tease` 亮度循環、每張 `flash()`，史詩以上追加 `rayBurst()`。因此光效重複也過早洩露整包上限。
- 產生器從 CATALOG 讀一般卡圖資料，四張場景展示資料另列；它沿用 demo 的卡面 CSS／mask。正式卡名與稀有度仍應取正式 catalog，不從檔名推，也不把場景展示陣列當新卡池規則。
- 原型 `RATE`、扣券與十連強制傳說都是試抽邏輯。HANDOFF 已記錄精裝池「沒有保底」；本案不搬入原型的「十連必出傳說」。未定的價格與抽率仍未定。

### 2.2 本案與已定案的關係

這是**精裝獨立卡池的專屬頁面與演出**，不是 `GachaModes.deluxe`「第六種一般演出：裝幀典藏」的改名。第六種一般演出的編目、冊頁、壓印流程與既有五種模式均不在本案改動範圍；未來接線須以獨立入口／演出策略隔離，不能全域覆寫共用 reveal 特效。

所有精裝卡仍用同一版型：階級寶石、文字框、名字、稀有度缺一不可。一般卡面不升級；`characterId` 與 `cardId + edition` 的分工不改。common／rare／epic 白色粗體；legendary 實心亮金 `#fff45c` 加自體光暈；mythic 用與框同步的 conic 彩虹及 `--phase`，字形黑邊用 `drop-shadow`。靜止時相位固定，不自行循環閃爍。

場景保持既定 `depth`／`flat` 處理與共同裁切；宇宙冒險羊為神話、天外膠膠為傳說、玥面探索者及居家珍獸為史詩。卡背延續六之三的圖形與燙金環；不在旋轉卡背的 pseudo-element 引入 CSS mask。原型目前引用 `cardback/deluxe-back.webp`，不把它與 HANDOFF 的純 CSS 作法誤認為完全相同的實作。

## 3. 整頁版面與可讀尺寸

「整頁」指切換遊戲內容頁，沿用宿主座標，不呼叫瀏覽器 Fullscreen API，不保留後方戰鬥畫面、可拖標題列或視窗外圍陰影。從既有抽卡入口選「精裝」進來；返回還原來源頁。一般／精裝切換是頁面導覽，不把這兩個池混成同一抽獎。

以下 px 均先指設計座標；橫式 960×640，直式 560×900。實際 CSS 像素另設下限，不能把 560 座標縮至 360 後仍宣稱字級足夠。

### 3.3 實際視口與進退場

- 舞台幾何可等比映射；導覽、費用、標籤、操作鍵採 CSS 尺寸下限重新排版。所有可點目標至少 44×44 CSS px。360px 寬時保留 16px 左右實際邊距，三個抽卡鍵等分剩餘寬度、各自顯示兩行文字，不能沿用縮成 28px 的設計高度。
- 扣除 safe-area 與固定操作列後再計算主卡可用高；主卡保持 5:7，放不下時縮卡並保留外置可讀名稱，結果頁改捲動。不要整個 560×900 一次縮到所有字都太小。
- 機率一覽切到同頁資訊面，保留返回與當前池；只呈現已定資料，未設定時寫「尚未公布」，不得展示原型假數字。費用取正式經濟層；未配置的抽數顯示未開放，不杜撰費用。多精裝池頁籤只在確有多池時出現。
- 按抽卡後立即鎖定購買；資料成功固定才讓池頁籤、費用與抽卡鍵在 180ms 退場。演出時保留返回、靜音、跳過及進度，避免在高速演出間誤按再次購買。
- 全部揭曉後切結果，底部只放「收下全部」與檢視／分頁。收下成功後才回到抽卡入口，恢復券數與購買鍵；不設會隱含再次扣款的同位置「再抽」。

## 4. 名字不撞框、人物真置中

### 4.1 文字框的共同安全區

沿用文字框左右各距卡邊 5%、底距 4%、高 16% 的基準。三種卡型的文字容器必須引用**同一個文字安全矩形**，與 `.face-plate` 是否包含文字無關。

以卡寬 W 計：寶石邊長仍是 `22W/290`；文字框內左右各保留 `0.13W` 的對稱區，左側容納寶石，右側保留同量空白，使名字仍在卡中心線。可用文字寬為 `0.64W`。W=300 時，框寬 270、左右保留各 39、名字可用 192px。寶石含旋轉後外框不得越入文字安全區，框描線至字形可見邊緣至少 `0.025W`。

名字預設 `24W/290`，依實際字體量測全名（含字距），超出才減少字距、再縮至 `20W/290`；仍放不下就兩行且保留稀有度一行。兩行姓名與稀有度容不下原高時，該卡文字框向上增加至最多 22% 卡高，主體安全區同步縮小，不能讓字溢出。此為長名例外提案，不改短名字級比例。瀏覽卡外置標籤與單張檢視都顯示全名，不以省略號作唯一內容。

字形安全區按實際排版驗，不只量 DOM 盒子；傳說光暈、神話黑邊不能被裁掉，也不能將光暈當作放寬撞框的理由。不重新加入 `vw` 字級、不把名字改寫成縮寫。名稱資料沿用 catalog。

### 4.2 透明角色圖：建置時計算 alpha bbox

推薦建置時計算、執行時只讀小型資料，不在每張 reveal 即時掃 Canvas 像素。保留原 PNG，不裁掉或重存來源檔。本輪只描述此步驟，沒有執行建置。

每檔記錄來源寬高 `Iw, Ih` 與非透明外框 `[x0,y0,x1,y1)`；預設 alpha ≥ 8/255 為有效像素，避開極淡壓縮殘邊，外框四邊再加 2 來源 px 並截在原圖內。門檻是可校正的美術參數，實作時抽查毛邊是否被排除，不用 RGB 黑白推斷透明度。保留分離配件，不直接只取最大連通區。

令 `bw=x1-x0`、`bh=y1-y0`、主體中心 `cx=(x0+x1)/2`、`cy=(y0+y1)/2`。卡片人物安全區預設 x=11%W 至 89%W、y=8%H 至 78%H，即最大主體寬 78%W、高 70%H；中心在卡上方美術區，並非整卡幾何中心。長名框加高時，安全區底端改為文字框頂緣減 2%H。

```text
s  = min(安全區寬 / bw, 安全區高 / bh)
tx = 安全區中心X - s * cx
ty = 安全區中心Y - s * cy

原圖顯示尺寸 = (s * Iw, s * Ih)
原圖左上位置 = (tx, ty)
```

不要再把未裁原圖塞進 `max-width:78%` 才位移，否則透明留白仍會影響縮放。主體圖與 subject foil mask 必須放在同一個來源座標 wrapper、共享 s／tx／ty；卡框、寶石、文字不跟著移動。傾斜視差是此基礎定位之外的動作，回正時回到同一 bbox 中心。

資料以裸檔名對應現有 mask key，另記來源內容雜湊便於失效重算。40 張 PNG 加 3 張玩具的數值資料是數 KB 級，精確大小以未來產出為準；代價是建置多一次逐像素掃描與人工例外檢視，不增加每次抽卡計算量。空 alpha、資料過期或缺資料時不得除以零：暫用原圖 contain 並列入美術待驗清單，不當作已完成主體置中。

### 4.3 alpha bbox 的適用邊界

- 主體含小配件時，bbox 中心不一定等於臉的中心。已看過 `card-foxfriend.png` 的左側分離圖案；預設一起保留。只有美術確認配件不應決定視覺中心時，才在 metadata 加具名的主體範圍或微量 opticalOffset；不自行把配件刪掉。驗收同時顯示 bbox 中線與卡片安全區中線。
- 完全不透明或有完整背景的 PNG，alpha bbox 只會得到整圖；例如看起來像棋盤格的內容可能就是畫的一部分。不能把灰白棋盤或白底自動去掉。完整圖保留 `flat` 構圖，必要時由美術提供 subject bounds。
- `depth` 場景的背景、主體使用同一個構圖裁切與位移；禁止只把主體 bbox 硬置中，導致前後層錯位。天外膠膠的貓與行星同為主體；場景原本已有構圖決策，本案不重新裁切它。
- 12 隻動態組裝角色沒有 PNG：建議後續用現有零件組裝器，在固定中性姿勢、固定比例、透明背景離線產生一次卡面快照，再走相同 bbox 流程。快照涵蓋所有可見配件，不包含 UI／地板陰影；以角色外觀版本作快取鍵。這是新增卡面來源步驟，並非本輪已完成，也不擅自把缺圖角色加入正式卡池。
- 其餘 2 個 emoji 與這 12 隻分開處理。跨平台 emoji 外觀不固定，精裝素材未補齊前不把系統 emoji 當正式卡圖；需要專案自製圖或明確的素材決策。資料不足時保留缺圖狀態，不假裝已有完整精裝美術。

## 5. 一次抽卡的節拍與操作

假設單抽／五連／十連均由正式設定決定是否可用；演出讀已固定的 draw，不生成結果。所有時間為提案值，正常動態；玩家閱讀停留與資料等待不計入動畫時長。

### 5.1 共用開場

| 時間 | 畫面 | 玩家可做什麼 | 這一拍存在的原因 |
|---|---|---|---|
| 按下起 0–80ms | 按鍵壓下 2px，立即顯示處理中，鎖定重複購買 | 靜音；返回保留既有交易狀態 | 先確認輸入，不拿演出掩飾是否扣款 |
| 等待資料，無固定上限 | 停留入口處理中；不先演假結果 | 返回；不可再次購買 | 成功取得且保存 pending 後才演。失敗顯示實際錯誤並恢復適當狀態 |
| T=0–180ms | 購買與池切換退場，襯紙鋪滿 | 返回、跳過、靜音 | 把注意力從操作面移到舞台；T 起點是 draw 已固定且主卡素材可用 |
| T=180–420ms | 封套移至中央，熱狗獎章扣住封口 | 同上 | 讓下一拍撕裂有可辨識的物件 |
| T=420–700ms | 斜向撕開封條，紙屑沿切口飛出 | 同上 | 給抽卡一個不可逆的視覺動作，結果本身早已固定 |
| T=700–880ms | 第一張大卡背落定；序號列依序出現 | 同上 | 卡背與進度建立空間關係，不塞十張小卡 |
| T=880ms 起 | 待揭，預設逐張；顯示「點卡揭曉」「自動揭曉」 | 選任一未揭序號、點卡、自動、跳過 | 把揭曉時機交給玩家；沒有倒數、呼吸光或強迫長按 |

素材尚未就緒時，T 不啟動，顯示靜態準備狀態；已取得的 draw 不重抽。素材無法載入則仍可跳到有名字及稀有度的結果頁收下，不能把卡面載入當作發獎條件。

### 5.2 每張揭曉，以 R=玩家揭卡或自動隊列開始

| 相對時間 | 畫面 | 可操作行為 | 理由 |
|---|---|---|---|
| R=0–100ms | 大卡背向下壓 3px，接收揭卡動作 | 返回／跳過／靜音；同張揭卡只受理一次 | 即時回應，避免連點觸發兩段演出 |
| R=100–220ms | 停住卡背；若為本包指定高潮卡，封口浮現無色的第二層切邊 | 同上 | 預告「這次動作不同」，不以顏色宣布精確階級 |
| R=220–400ms | 普通路徑翻面；稀有路徑見下表延長 | 同上 | 卡背換成真正卡面，不靠白閃遮切換 |
| V=正面可讀點 | 顯示真正名字、稀有度、edition；角色正面回正 | 下一張／自動暫停可用；返回／跳過一直可用 | 揭曉與可讀是同一個明確事件，不等特效散完才知道抽到什麼 |
| V 至該張 slot 結束 | 依稀有度完成後景動作並留靜止閱讀時間 | 逐張停留不限時；下一張可提前結束餘韻 | 把欣賞時間留給玩家；自動才使用固定停留 |
| 下一張切換 160ms | 前卡縮到已揭序號，下一張卡背就位 | 暫停自動／返回／跳過 | 清出上一張輪廓，避免兩張大卡互相蓋住 |

「下一張」表示選下一張未揭卡並開始揭曉；已揭序號可在逐張待機時重看大卡，不重播稀有高潮。自動模式按暫停後完成當前卡至 V 即停，取消已排但未播放的下一張音效。快速連點最多保留一個下一張意圖，不累積十次。

### 5.3 稀有度與一包的輕重分配

| 路徑 | V 相對 R | 自動 slot 總長（不含切張160ms） | 讀卡前後的差異 |
|---|---:|---|
| common | 400ms | 900ms | 乾脆翻面，500ms 靜讀，無白閃、無碎光 |
| rare | 400ms | 1000ms | 右下扣合墨痕 120ms，餘下靜讀 |
| epic | 460ms | 1200ms | 單筆色塊 220ms，至少 520ms 清楚靜讀 |
| legendary 完整高潮 | 680ms | 1900ms | 先停 120ms，落印重擊、金刷320ms，再靜讀900ms |
| mythic 完整高潮 | 860ms | 2400ms | 先停180ms，整張襯紙裂開／彩紙邊展開540ms，再靜讀1000ms |
| 其餘 legendary／mythic 短版 | 460／520ms | 1300／1450ms | 保留階級專屬落印／紙裂輪廓，局部220／300ms；不再推開整個背景 |

本包最高階級中、原抽取順序第一張 legendary 或 mythic 是唯一完整高潮卡；沒有這兩階就沒有額外製造高潮。其他高階卡用短版，但卡尺寸、真實階級及靜讀權利完全相同。無論玩家先選哪張，指定高潮卡不換，避免操作順序改變演出暗示。這是展示分配，沒有改抽率、保底或結果順序。

不做整包最高稀有度充能色，也不替每張未揭卡塗階級色。只在選中的高潮卡 R=100–220ms 提示「第二層封紙」，最多透露這張有特別演出、不區分傳說與神話；直到 V 才顯示精確階級。聲音同樣不得在開場先奏最高階旋律。若 draw 已存在 veil，前段遵從 veil 的可見資料，V 才切真值，不自行製造「普通變神話」假轉彩。

自動五連全普通：880＋5×900＋4×160＋結果轉場240＝6260ms。十連全普通為11560ms；九普通加一完整神話為13060ms。極端十神話則約18010ms；不是十次2400ms高潮。這些是動畫總時長，未含素材等待、玩家停留與收下；玩家隨時可跳過。單抽完整神話自動路徑約3520ms進結果。

### 5.4 結果、跳過、收下與中斷

| 時間／觸發 | 畫面與操作 | 原因及資料語意 |
|---|---|---|
| 全揭後 0–240ms | 大卡縮入結果頁的對應位置；其餘卡淡入；分頁可用 | 切成整理狀態，不重新播稀有度特效 |
| 結果待機不限時 | 翻頁、點卡大圖、收下全部、返回保留結果 | 閱讀不與特效計時競賽 |
| 跳過後 0–150ms | 結束畫面與音效隊列，直接顯示全部真實結果 | 不依序呼叫十次有音效的 reveal，不自動收下 |
| 點收下 0ms | 鎖定按鈕，走既有 collect 一次性入袋 | 動畫不是發獎機制，draw.id 必須防重入 |
| 收下成功後 0–320ms | 全批縮成一疊滑入封套，收口一次；回入口 | 收下成功才播成功聲；失敗留結果可重試，不消失 |
| 返回／關頁／失焦 | 停止 scope 和時間軸；保留未收 pending | 重進有 pending 直接回真實結果頁，不重扣、重抽或強迫重看 |

返回的短標籤可為「返回」，其可存取名稱與提示為「返回，結果保留」。不插入新的確認視窗。切換尺寸只重排當前狀態，不從 T=0 重播。模式自己的視覺取消、共用 reveal 的資料完成與 collect 分開；實作前需確認 runtime 支援靜默揭曉／自訂呈現，若沒有就加局部介面，不能同時跑舊白閃與本案紙張演出。

## 6. WebAudio 音效設計

全部聲音由振盪器及現場生成的噪音 buffer 合成；不用音效檔、取樣包、外部音源或外部 impulse response。以下只是設計參數，沒有聲稱已試聽。紙聲可用噪音包絡做出材質輪廓，不追求用合成器冒充寫實錄音。

### 6.1 現有能力與使用方式

`GachaAudio` 已有 `ensure()`、`tone()`／`noiseHit()`／`bell()` 的 scoped 入口，以及 pick、drop、lock、tear、burst、deal、hover、flip、reveal、charge、collect、dust、tick、ui。沿用 AudioContext 懶建立、現場噪音、排程與 `createScope().stop()` 的清理結構。

不直接把既有 `reveal(rarity)` 全部疊上本案：它的史詩已有琶音、失諧鋸齒墊底，神話分支還會接著執行傳說的大鐘尾段；傳說鐘聲衰減長至3.2秒，不適合本案的連抽密度。`charge()` 的心跳與高頻上掃也偏魔法蓄能。新精裝專屬配方使用 scoped primitives 組合，既有模式保留原聲。

現有全域 master 固定 0.7；scope 的 dry／verb 可以接管本次輸出，scope 內173／251ms延遲是短回聲，不等同全域交叉回授＋低通的 verb。本案 UI 音量、ducking 與短包絡需在精裝自己的輸出層處理，不把目前程式描述成已提供完整音量設定。

### 6.4 同步、音量、連抽與減少動態

- 用同一時間軸排聲與畫面：AudioContext時間對應視覺單調時鐘。先確認圖可解碼、context已resume，再安排最近一張，避免長串setTimeout漂移。聲音早40–60ms的是撕紙張力與高階引音；撞擊聲仍在V。這是排程目標，裝置輸出延遲需要未來實聽校準，不能承諾所有手機實際差值相同。
- 每包一個scope，每張子scope；同時最多當張主音與前張淡出尾聲。切張前將前張尾聲於60ms內降到零，高潮前停止其他聲。不要十個`reveal()`並行；噪音脈衝也只預排當張，暫停及跳過可取消。
- 精裝bus預設增益.6，再經既有master .7；UI滑桿0–100%映射此bus乘數，0與靜音等效，記住選擇。靜音在30ms內收乾dry及wet，不只是阻止新音；解除靜音只播放之後事件，不追補。
- 因子scope各自連到master，不能假設調父scope.dry就能控制所有子scope；實作時須讓各子scope受同一精裝音量控制或明確共同接到精裝bus。音量功能不可只對一條乾聲有效。
- 合成混音目標峰值不超過−3dBFS，實作時用實際輸出量測調整配方總增益；不可把上表單音g當作已保證不削波。若遊戲本來有背景聲，演出期間降約6dB，收束後180ms恢復；沒有背景聲就不新增循環配樂。
- `prefers-reduced-motion`同時由CSS與runtime處理：開場縮為180ms淡入卡背；每張150ms淡入正面，無旋轉、位移、震動、紙屑或箔面循環。common／rare／epic仍留500ms閱讀，高階留900ms；逐張仍不限時，跳過仍可用。神話保留靜態三層紙邊與大卡，辨識不靠移動。
- 減少動態不自動靜音；採相同階級的短版聲、取消蓄力與提前引音，揭曉聲與150ms可讀點同步，最高尾音450ms。另由靜音／音量控制聲音；不把「不想看晃動」誤解為「不想聽」。
- 首次手勢啟用`ensure()`；不支援或resume失敗仍正常揭曉及收下。鍵盤Enter／Space與點擊等價，序號和頁碼有可讀標籤，結果到達才報讀一次張數，不隨每個碎紙節點朗讀。

## 7. 我反對或修正的方向

1. **同意去掉反覆白閃，但不把「沒有AI味」等同全面禁用漸層。** 卡框箔面、神話彩虹字是已定案的卡片材質，保留；拒絕的是整個背景拿紫藍漸層加白光當全部內容。
2. **同意主體置中，但反對所有圖片只套alpha bbox就宣稱完成。** 非透明背景、分離道具與景深層需要不同處理。預設bbox解決留白偏移，美術例外保持可見、可追溯；不以自動演算法破壞原構圖。
3. **同意整頁，但反對十張都同屏才能叫十連結果。** 960×640下十張5:7卡加文字、間距與操作列必然犧牲尺寸；直式更明顯。本案選大卡逐張＋分頁結果，代價是多一次翻頁，換取真的能讀的姓名與卡圖。
4. **不採用假的「預期落空再翻轉」。** 卡背假装低階再固定升成高階容易讓人誤解規則；本案用物理動作的停住與紙裂形成轉折。既有veil若有真實展示語意就尊重，不另造假稀有度。
5. **不為效能先砍神話規模。** 先做全舞台紙裂、完整卡面材質及同步音形。未來若量測有瓶頸，優先固定紙紋、回收看不見的頁面與停止待機動畫；不能以少一層圖形為由把高潮時長、主卡尺寸和構圖變化一起削掉。
