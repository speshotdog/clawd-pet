## 一、「挑選獨立技能」要顯示卡片，而且要能拖曳設定

### 現況

`map20.html` 的 `openPicker('skill', slot)` 彈窗（`#picker-title` 設成「挑選獨立技能」，
`map20.html:538` 附近）目前每一格顯示的是**去背的角色圖 + 名字**，
不是卡片。畫面下緣寫著「來源尚未定案 · 此處僅配置技能格」，
底部一顆「確認加入」。

### 使用者要的

> 「我希望之後 這個頁面是直接顯示卡片，
>  和他們在主頁面 能直接從 卡面拉下去獨立技能 用拖移的方式更改。」

兩件事：

1. **彈窗裡改成直接顯示卡片**——就是編隊收藏／卡冊在用的那張完整卡面
   （含卡框、稀有度銘牌、階級墨色），不是去背角色圖。
2. **主頁面（編隊收藏）要支援拖曳**——從上方的卡片網格，
   直接把卡面拖到下方的「獨立技能 1～4」格位來設定，取代現在「點格子 → 開彈窗 → 挑 → 確認加入」。
   彈窗應該變成備援路徑，不是唯一路徑。

### 動工前要注意的

- **卡面元件已經統一了**，直接用 `card_face.js` 建的那套，不要另外刻一份縮圖，
  否則會打破這輪剛做好的「全線共用同一份編碼」（見 `DECISION-2026-09-12-lossless.md`）。
- 彈窗一次要放 20+ 張完整卡面，**要先量效能**再決定要不要限制同時 paint 的張數。
  待機 fps 現在是 60，不要做到掉下來。
- 拖曳互動有已知坑：`user-select` 沒關的話拖曳選區會把 `<img>` 塗成藍色。
  驗收要驗像素，不能只驗 CSS 變數。
- 編隊的選取放大用的是 CSS `scale` 屬性不是 `transform`（`team20.css:142`），
  拖曳時要一起處理 `rotate`／`translate` 同一組。

## 二、卡片四角的 L 型黑邊，在這些畫面還有

### 現況

使用者在試玩時截到卡片四角仍有 **L 形純黑硬邊角**。

**修正方法早就找到了**，機制寫在 `METHOD-card-face.md` 第三節：

> 卡面底下鋪了一塊 `background:#000` 的底板（理由是「screen 混合下黑色是中性的」）。
> 那塊底板是**方角**（容器的 `clip-path` 是方形多邊形，沒有圓角），
> 而容器有 `transform:translateZ(...)` 是**獨立的 3D 合成層**——
> `mix-blend-mode:screen` 在圓角外沒有背景可混，就吐出純黑（lum 0）。
> screen 對黑色中性的前提是「有東西可以混」，獨立合成層的空白處不成立。

判準工具也已經有了：`_art/holo-test/check_card_corners.py`
（四角都要驗，背景參考值要取**在地**的——頁面背景是放射漸層，
拿單一背景亮度去套四個角會製造假紅燈）。

### 所以要做的是「把已知的修法補到還沒套到的地方」

⚠ **這不是重新研究，是覆蓋率問題。** 已知沒掃過的狀態：

- **揭卡演出途中**（`HANDOFF-2026-09-11.md` 第六節、`HANDOFF-2026-09-10-night.md` 第 4 節
  都記著「黑角在抽卡演出途中沒掃過」）。禮物卡那次的黑角就是**特定 FX 狀態才出現的**，
  靜態掃描掃不到。
- 使用者這次截到的是編隊／技能挑選相關畫面，**也要納入掃描範圍**。

### 動工步驟

1. 先用 `check_card_corners.py` 把**目前所有畫面與狀態**掃一遍，
   列出哪些地方還有黑角（含揭卡演出的各個時點、hover、選取、拖曳中）。
2. 對每個中標的地方確認是不是同一個成因（方角底板 + 獨立合成層 + screen）。
3. 套已知修法，然後**逐個角驗證**，不要只驗左上角。
4. ⚠ 驗證腳本報「全部都壞」時先懷疑判準——黑角第一版報 28/32 全壞，
   是判準寫錯（見 `HANDOFF-2026-09-10-night.md` 第 141 行）。
