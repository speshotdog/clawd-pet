## A. 稀有度那行也要有顏色（使用者指定）

**使用者原話**：「我想要階級的字體也會有顏色」。

現況：`.r-special .face-rarity` 是單色 `#ffd0e6` ＋ 一道 `text-shadow`。
卡名是粉→藍漸層、角度吃 `--phase`（傾斜時跟著轉）。要讓稀有度那行也有顏色，
**與卡名同一個色系與同一套做法**，但它只有 17.69px，比卡名小一半，所以：

1. 用 `background-clip:text` ＋ 透明填色 ＋ 漸層，**角度同樣吃 `--phase`**，兩行一起轉。
2. ⚠ 一旦用了 `background-clip:text`，**描邊只能用 `drop-shadow`，不能用 `text-shadow`**
   ——`text-shadow` 會畫在漸層外面把字糊掉，上一版的卡名就是這樣糊成黑塊的
   （HANDOFF 六之二）。現有的 `text-shadow` 要關掉。
3. **小字比大字更容易糊**。硬門檻：稀有度那行的 WCAG 亮度對比 **≥ 4.5:1**，
   量法沿用 `check_gift_card.py` 既有的 `text_contrast()`（字身取最亮 25%、底取最暗 35%）。
   達不到就把漸層整條往亮處移（卡名那條就是這樣從 12 救到 6.44:1 的），
   **不准改字級、不准放寬門檻**。
4. 「特殊 / SPECIAL」中英混排，中文與英文的筆畫粗細差很多——兩段都要量，取低的那個當結果。

驗收：`.face-rarity` 的 computed `-webkit-text-fill-color` 必須是 `rgba(0, 0, 0, 0)`、
`background-image` 必須以 `linear-gradient` 開頭、`text-shadow` 必須是 `none`，
對比 ≥4.5:1，置中偏差仍 <2px。**這四條都要寫成斷言。**

## B. 卡框更亮，但不要太亮（使用者指定）

**使用者原話**：「卡片的外框 希望可以更亮一點 提升整體華麗感 但不要太亮」。

現況：`.r-special .frame-material` 是 `opacity: calc(var(--foil) * .92)` 的粉紅 conic 漸層；
`.face-frame` 有五道 inset 描邊（`#ffc2dd` / `#3a1c2b` / `#ffa8d2` / `#2b1420` / `#ffc2dd66`）。

「更亮」與「不要太亮」都要變成數字。**先定義卡框環**：卡片矩形往內縮到
`.face-plate` 的外緣為止、且不含圖窗中央——實作上取「卡片外緣往內 3.5% 的環狀帶」，
把這個遮罩存進證據 JSON，改前改後用同一個遮罩量。

| 條件 | 門檻 |
|---|---|
| 卡框環的平均亮度增幅 | **+12% ～ +30%**（低於 12 沒感覺，高於 30 就是太亮） |
| 卡框環的亮度標準差（層次感）| **不得低於改前的 95%**（不能糊成一片亮） |
| 整張卡的平均亮度增幅 | **≤ 5%** |
| 圖窗中央（角色區）平均亮度增幅 | **≤ 2%**（框變亮不該影響畫） |
| 卡名對比 | **≥ 6.44:1**（不得低於改前） |
| 寶石對比 | **≥ 145**（不得低於改前） |

做法自己決定（提亮 conic 的色階、加一道更亮的內描邊、調 `frame-material` 的 opacity 都可以），
但**不准把 `--foil-gain`／`--grain-gain`／`--subject-gain` 拿來當提亮手段**——那三個是箔面材質的
參數，動了會連帶改變角色與背景，屬於 B 題的範圍外。

## C. 懸浮粒子（使用者要求「幫我思考可不可以」——答案是可以，規格如下）

**目的**：提升質感，不是加特效。粒子應該像空氣裡的細塵／花粉在飄，看第二眼才注意到。

### 硬性限制（違反任何一條就算沒做到）

1. **不准新增常駐 `requestAnimationFrame`。** 純 CSS `@keyframes`，只動 `transform` 與 `opacity`
   （這兩個才走合成執行緒）。不准動 `top`／`left`／`width`／`filter` 之類會觸發 layout／paint 的屬性。
2. **不准蓋到文字。** 粒子層的 `z-index` 必須低於 `.face-plate`（20），
   驗收要用 `elementFromPoint` 取卡名與稀有度的中心，回傳的元素必須仍是 `.face-name`／`.face-rarity`。
3. **`translateZ` ≤ 42px**（HANDOFF 六之四）。粒子放在圖窗裡、角色與卡框之間即可。
4. **不准溢出卡片**：粒子必須被卡片的圓角裁掉，投影不得超出卡緣 1.5px（沿用既有斷言）。
5. **`prefers-reduced-motion: reduce` 時粒子必須靜止**（可以留著不動，但不准有動畫）。
6. 粒子是 CSS 畫的（`radial-gradient` 之類），**不准引入圖片素材或第三方庫**。

### 建議規格（可以否決，但要附量測理由）

- 數量 **12～20 顆**，直徑約卡寬的 0.6%～1.6%（380px 卡上約 2.3～6px），大小不一。
- 顏色走「特殊」的粉藍：粉 `#ffd4ec`、藍 `#cfeeff`、白 `#ffffff` 三種混用，`mix-blend-mode: screen`。
  ⚠ 這張卡的背景是**亮粉紅**，`screen` 在亮底上幾乎不動作（跟 `overlay` 同一個坑，
  上一輪已經踩過並記在 `build_gift_card.py` 的註解裡）。所以粒子要**自己夠亮＋帶柔邊光暈**
  才看得見，或改用 `normal` 混合、靠 alpha 疊。**先量再選，報告寫出你試了哪些、量到什麼。**
- 飄動：由下往上、帶輕微左右擺，單顆週期 **8～18 秒**、各自不同的 `animation-delay`（負值錯開，
  頁面一開就是散開的狀態，不要全部從同一點出發），透明度在頭尾淡入淡出。
- 傾斜時可以吃 `--rx`／`--ry` 做一點視差，但**不是必要**；做的話位移量要小。

### 驗收

| 條件 | 門檻 |
|---|---|
| 粒子真的在動 | 同一入口間隔 2 秒兩張截圖，**圖窗區域**的差異像素（灰階差 >6）占比 ≥ 0.15% |
| 動的只有粒子 | 文字框區域（`.face-plate` rect）的差異像素占比 ≤ 0.02% |
| 沒有常駐 rAF | 頁面靜置 3 秒，`requestAnimationFrame` 的呼叫次數為 **0**（用覆寫 `window.requestAnimationFrame` 計數，或既有 `state().rafs` 那套做法） |
| 不影響可讀性 | 卡名對比 ≥6.44:1、寶石對比 ≥145、稀有度 ≥4.5:1 |
| 不變亮 | 整張卡平均亮度增幅 ≤ 2% |
| reduced-motion | `animation-play-state` 或 `animation` 為 none，兩張間隔截圖差異像素占比 ≤ 0.02% |
| 不蓋文字 | `elementFromPoint` 取卡名／稀有度中心仍是該元素 |

**反向斷言**：粒子必須真的看得見。除了「有差異」之外，還要量**單張截圖**裡粒子區域與周圍的
亮度差——找出粒子的位置（用停用粒子層的對照圖相減），要求粒子峰值比鄰近背景亮 **≥ 8 灰階**。
只有「有在動但看不見」不算過。

## D. 順手修一條假紅（我在驗收時抓到的）

`check_gift_card.py` 的 `assert_crossfade()` 用 **60ms 的 `setInterval` 取樣**去判斷
「中間值至少 3 筆」。320ms 的過渡只會拿到約 5 筆，頁面又有 9.7 MB，瀏覽器排程一漏就變成 2 筆。
**我獨立重跑三次，掛了一次**（`('crossfade intermediate samples', 'alt', 0, 2)`）；
你自己的退出碼表裡也有一行 `Later fixed check, native rendering stall | 1`，是同一件事。

同一個函式**已經另外記了每一格 rAF 的曲線**（`frames`，約 16ms 一筆）。把「≥3 筆中間值」
改成對 `frames` 判斷即可：樣本從約 5 筆變成約 19 筆，**這是更嚴不是放寬**。
`frames` 上原有的三條（不得有空白格、不得雙層同時滿、互補和 ±0.025）維持不動。

驗收：連續跑 **5 次** `check_gift_card.py`，5 次都要 exit 0，把五次的退出碼列進報告。
