## 一、使用者實玩回饋（第一項，必修）

> 「**只有精良的顯示 反射的光澤比較生硬（筆直的 有割裂感）。比照其他的做就好。**」

使用者附了截圖：藍色那張（**精良 / rare**）的卡面上有一道**筆直的垂直亮帶**，
帶子邊緣是硬的，看起來像整張卡被切成兩半，不像光在箔面上流動。

- 只有 **rare 這一階**有這個問題，其他四階（common／epic／legendary／mythic）沒有。
- 修法就是**比照其他階**：其他階的光譜是多柱、有角度、邊緣有過渡；
  rare 顯然是單一條、接近 90°、邊界沒有羽化。
- 去看 `demo.html` 裡 rare 的箔面定義，跟其他四階並排比對，把它改成同一種材質行為
  （角度不要正垂直、加多柱與細掃描紋、邊界過渡拉開、亮度靠角度調節）。
- **不要順手把其他四階也改掉**——使用者只嫌 rare。
- 改完在展示頁的五階並排區，用同一個角度截圖，確認 rare 不再有割裂感、
  而且仍然跟其他階看得出稀有度差別。

## 二、把現有的圖拼接上去（第二項）

> 「**幫我試著把現有的圖拼接上去 我看效果。**」

背景：使用者已定案「滿版場景卡」，而且「**舊卡也要一起升級**」。
現有 40 張 `src/card-*.png` 是**單一角色去背 PNG，沒有背景**，
所以要看得到效果，就得**替它們合成背景**，變成滿版景深卡。

**素材就在專案裡，不要生新圖**：`src/clicker-scene<N>-{sky,far,mid,ground}.png`
（N = 1..7，七個場景各有天空／遠景／中景／地面四層，美術風格跟角色本來就一致）。
另外還有 `prop`／`cloud`／`grass`／`flower` 等點綴層可用。

要做的事：

1. 寫一支產製腳本（放 `_art/holo-test/`，例如 `compose_legacy.py`），
   把「角色去背 PNG ＋ 某個場景的背景層」合成成 600×840 的滿版卡，輸出成分層檔
   （至少 `subject`／`background` 兩層，跟上一輪 `layer-*-{subject,background}.png` 同一套命名與格式，
   讓展示頁的景深程式直接吃）。
   - **這批不需要 GrabCut**：角色 PNG 本來就有乾淨 alpha，直接當 subject 層。
     背景層是場景圖疊起來壓平，不需要補底——這正是它比 GrabCut 那條路乾淨的地方。
   - 角色要**擺在合理的位置與大小**（站在地面線上、不要浮空、不要被裁到頭）。
     不同卡的角色 PNG 尺寸不一（見 `asset-manifest` 或自己量），要按各自比例放。
2. **場景配對**：哪隻角色配哪個場景，用一個可讀的對照表寫在腳本裡（人看得懂、之後好改）。
   你可以照角色的色調挑，也可以照 `gacha-pool.js` 的稀有度分配。**這是初版，配錯不要緊，
   使用者要看的是效果**，但表要明確列出來讓他能指名重配。
3. **不用做完 40 張**。挑 **8～12 張**有代表性的（涵蓋五個稀有度、涵蓋 SVG 角色與 PNG 角色、
   涵蓋兩張 `bleed` 的），做出來讓使用者看效果。做太多會浪費時間在還沒定案的配對上。
4. 展示頁的「D. 舊卡升級」區改成放這批合成卡，**跟原本的去背卡框版並排**，
   讓使用者直接比較「現在的樣子 vs 滿版景深版」。

## 三、限制（沿用前兩輪）

- 展示頁維持**單一檔案、`file://` 直接開得起來**，不可用 `fetch`／XHR／ES module import。
  新增的分層圖照舊用相對路徑 `<img>` 或內嵌 data URL。
  ⚠ 檔案已經 510KB，這輪會再變大——如果超過大約 25MB 會很難開，
  優先用相對路徑引用外部 PNG，只有 CSS mask 非內嵌不可的才轉 data URL。

- 素材程式生成、固定 seed、不用生成式 AI、不搬第三方貼圖。
