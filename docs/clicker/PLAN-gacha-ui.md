## 一、GPT-6 對題目本身的修正（我認為要採納）

它認為「像不像真正手遊」這個問法會把結果導向更多光效、假頁籤和沒有資料支撐的保底提示，建議改問：

> **玩家能否一眼辨識現在的狀態與下一步？從按抽卡到收下，是否始終相信眼前是同一包卡、同一次操作？**

它的核心判斷：**最值得補的是「操作有回應、狀態看得懂、同一個物件連續存在」，其次才是首次進場動畫。**

## 二、建議清單（依投報率排序）

### 第一梯：成本小、直接補操作閉環

| # | 做什麼 | 現在的問題 | 可驗收的條件 |
|---|---|---|---|
| 1 | **狀態語言** | 券不足與演出進行中長得太像，玩家要猜該等、該點還是沒券 | 每個狀態**恰好 1 個**主要提示；不足時顯示「差 N 券」，N 正確率 100%；提示字級 14–16px、對比 4.5:1–12:1 |
| 2 | **結果的結語** | 只有「收下」，缺少「這一抽完成了」 | 補一行「本次獲得 N 張」，N 與結果一致率 100%；進場 160–220ms、位移 6–10px；**覆蓋卡面面積 0px²** |
| 3 | **收下→回場** | 收下後入口直接恢復 | 收下維持 220ms，其後入口短版回場 140–180ms、位移 4–8px；整段 360–400ms；**不得延後可操作時點** |
| 4 | **按鈕層級** | 三顆現在被 CSS 覆寫成一樣的黑底，主要操作沒有突出 | 十連改實底、其餘維持深底；實底主要按鈕**恰好 1 顆**；高度 56–64px、名稱 16–18px、費用 12–14px；主要文字對比 7:1–15:1 |
| 5 | **hover／按下／不足／進行中要長得不一樣** | 目前回饋不足以區分 | hover 變化 120–180ms、按鈕內可見變化面積 25%–75%；按下位移 1–2px／60–100ms；焦點邊 2–3px、對比 3:1–7:1；連點造成的重複抽取 **0 次** |

### 第二梯：中等成本

| # | 做什麼 | 現在的問題 | 可驗收的條件 |
|---|---|---|---|
| 6 | **等待→拆封的物件連續性**（GPT-6 認為玩家最容易注意到的接點）| `prelude()` 把互動卡包隱藏、另建一個純貼圖的拆封卡包，材質與拖轉姿態會斷 | 交接時卡包中心偏差 0–2px、寬度比 0.99–1.01、角度差 0–1°、同區域平均亮度差 0%–5%；在既有 240ms entry 拍內完成，**不新增一拍** |
| 7 | **手機結果左右切換** | `browse()` 直接 `relayout()`，像在切圖片 | 只在 results 狀態加 160–220ms 方向過渡，位移為卡寬 8%–12%；抽取身份與順序改變 **0 次** |
| 8 | **首次入場**（GPT-6 排最後，理由是翻卡已有完整節奏）| 進場幾乎靜態 | 背景 0ms → 卡池名 0–40ms（160–220ms／上移 6–10px）→ 卡包 40–80ms（280–360ms／上移 12–20px／0.96→1.00）→ 按鈕組 140–200ms（180–240ms／上移 8–12px）；整段 320–440ms；按鈕可點區可見比例 100% |

### 明確建議不要做

- **保底提示、NEW／重複轉換標記**：沒有對應真實資料就是誤導。無資料依據的標記 **0 個**。
- **卡池切換頁籤／商店／紀錄**：單一卡池不需要裝出多入口。無對應功能的可點控件 **0 個**。
- **再加一顆十連跳過**：已有「跳過演出」、空白跳過、Esc。應改善可發現性，不要再加一套語意。
- **常駐「十連推薦」閃爍**：新增這類循環 **0 個**。

## 四、兩個實作邊界（GPT-6 特別點名，我認為要寫進未來每一份簡報）

1. `updateFinish()` 把動畫、timer、rAF、音效都納入可收下條件。
   **新增結果 UI 動畫不能反過來把「收下」藏回去**——動畫期間收下控件可見且可操作比例 100%，重複收取 0 次。
2. `focus-held` 同時控制背景暫停與部分元素顯示，**不能只加一句 opacity transition 就假定全部平滑**。

## 五、驗收紀律（沿用這條線的既有規矩）

- 每個數值**同時給下限與上限**；只寫上限＝做出看不見的東西。
- 固定進度的成對截圖 ＋ 正常速度播放，兩種都要。
- 取樣用決定性時點（Web Animations API 暫停＋設 `currentTime`）＋雙重 rAF 重繪屏障。
- **fps、幀時間、冷載入、手機可讀性、玩家注意順序一律實機量**；
  禮物卡那條線的 21fps 與舊 SwiftShader 數據**不能移植**到這個入口。
