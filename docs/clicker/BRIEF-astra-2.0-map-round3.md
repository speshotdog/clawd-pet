## 二、我複驗抓到的三件事

### 修一（最重要）：路線在地景上看不見，而門檻卻全綠

`acceptance.json` 裡：

```
route.walked_alpha    0.72  範圍 0.65–0.80  PASS
route.unwalked_alpha  0.28  範圍 0.22–0.34  PASS
```

**但在 1440×900 的成品上，節點之間的連線幾乎看不到。**

原因：**這兩條門檻在第一輪是有效的，加了地景之後就變成無效門檻。**
第一輪的底是近黑純色，alpha 幾乎等於對比；現在底是一張插畫，
**alpha 量的是 CSS 屬性值，不是玩家看不看得見。**

改法：

- **路線的門檻改成量對比，不再量 alpha。**
  量「路線像素」與「它正下方地景像素」的亮度對比（沿線取樣，不是取整張圖平均）：
  - **已走路線 ≥ 3.0:1**（上限 6.0:1，太高會變成刺眼的白線壓在畫上）
  - **未走路線 1.6～2.4:1**（要看得見，但要比已走弱）
- **量法要沿線走**：每隔 8～16px 取一個樣點，取樣點的**中位數**要落在區間內，
  而且**最差的 10% 樣點也不得低於下限的 80%**（防止只有幾段亮、其他段消失在深色樹叢裡）。
- 為了在各種地景上都成立，路線可以加**描邊或投影**（例如深色細描邊 ＋ 亮色主線）。
  ⚠ 描邊不可以粗到讓路線看起來像管子：路線總寬（含描邊）**≤ 5px**。
- `route.walked_alpha` / `route.unwalked_alpha` 兩條**從腳本裡拿掉**，
  換成上面的對比項。在回報裡寫明「這兩條被撤換的理由」。

### 修二：地景放太大，一段只看得到一小塊

現況第一段的地景被放大到只看得到樹的一部分，樹幹比節點還粗好幾倍。
玩家會覺得那是一張大插畫，不是一段要走過去的路。
手機識別物只有 8.761% 也是同一個原因。

門檻（新增）：

- **走完一段（4 個節點）的整個捲動行程中，該段地景累計被看過的高度 ≥ 70%**（上限 100%）
- 桌面 1440×900 靜態一屏：**地景可見面積 60～75%**（維持）、
  **已標定識別物可見 15～25%**（維持）
- **手機 390×844：識別物可見 12～25%**（我把下限從 15% 放寬到 12%，
  因為手機還要放下方面板；但 8.761% 太低）
- 縮放之後**中央 30% 帶仍要維持乾淨**（地景那張圖本來就是這樣畫的，不要縮到破壞它）
